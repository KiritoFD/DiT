# Built with Qwen：跨字合成条件评测

2026-10-23，使用已校验的Qwen-Image-2.1-Turbo、原有48环境，官方8步、BF16、1024方图。
参考为三位书家的训练真迹，每位6个不同字符；目标GT只参与评分，不进入prompt或图片条件。

## 固定流程

- 独立validation：每书家2字，共6对。4种条件生成24张：原6图长prompt；6图紧凑铺满prompt；
  同6字拼成一张2×3样本板+紧凑prompt；6图紧凑prompt+明确书家名。
- 仅按验证集原画幅Alex LPIPS均值选方案，Ink-IoU破同分；不按test调prompt。
- test：每书家10个不同字符，30对GT，每对2个seed，共60张。排除之前6张试验的目标组合、
  参考字及validation字符。总计84张。所有组都不输入STD。
- 同一GT对照：历史Top20 114M@30k EMA的逐图结果；Qwen两seed，历史模型一seed，
  不声称同噪声或与当前最佳架构比较。

这是输入/提示策略筛选，不是所有因素逐一独立消融：紧凑prompt同时改了措辞和占幅要求；
书家名组还可能调用预训练的名字先验。成功也不能直接证明全部风格来自参考图。

## 评测与审计

复用`tools/synthetic32/paired.py`和仓库SSIM、Alex LPIPS、墨迹指标。
原始输出1024→256 LANCZOS，GT原生256，无粗细处理，作为主结果。
附加双方各自threshold=.5墨迹bbox、等比例最长边铺满256的诊断SSIM/LPIPS，
保留原始图，不把此后处理数字当作主评测；裁框不会修复字符错误或错误书风。

`study.py prepare`在数据机器构造固定`study.json`、GT及参考图SHA、CSV SHA、对照表副本。
`study.py run`串行执行四组验证、自动记录`selection.json`，随后执行60张test，
写`comparison.json`和`status.json`。失败即停止，输出目录不得复用。

## 为什么通用模型可能明显落后

这是待检验解释，不是已证实根因：专用模型在真实书法域训练，条件ID直接对应目标分布；
通用编辑模型的多图条件不保证学到跨字符的历史书家笔法，可能更偏向标准字体与图像复制。
白底占幅不一致会拖低配对指标，但此前读图也暴露了风格趋同，不能只归因于评测尺度。
此外，单张GT只是同书家该字的一种写法，配对指标并不等于纯风格判断；
本轮会同时检查原图，不能仅靠提示词或分数证明历史书风忠实度。
