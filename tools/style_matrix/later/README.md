# 48/64h隔离升级

本目录只在后续边界启用，不覆盖当前活动源码。

- `plan.py`：给S10、S0/S4、S11生成50k→60k→75k的匹配LR分段，保留当前S9-FM/Pair的24h轨迹。
- `runner.py`：只接续后续阶段，沿用原64h墙钟、实验身份、数据与已有结果。
- `handoff.py`：标准库后台观察器；4090等待S9Pair@60k机制评测完成，48等待当前S11@50k完成。
- `checks.py`：CPU检查源spec未被修改、LR逐点匹配及checkpoint身份链。

交接前必须取得全局GPU锁且GPU无训练所有者，再停止旧控制器。当前GPU任务持锁时持续等待；若旧成熟任务已经开始则保留原任务并登记deferred。代码包SHA校验通过后只解包本目录，随后重新封存源码及未来spec。

升级不修改24h样本、步数、Loss或checkpoint；不重置时钟。新匹配成熟对照使用同样的50k/60k重启点、200步warmup、相同峰值比例与余弦区间，避免把LR轨迹差异归因为架构收益。
