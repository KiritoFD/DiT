### ★ 一个有价值的设计差别：`q="x"` 是唯一能在 CFG 下存活的变体

## 【★★★ 主判据之一：t=0.1 换书家速度场差 —— 结构性地卡在 0.02】

用户指定判据是「断笔比 + **t=0.1 的换书家速度场差**」。用
`tools/signal_tracing.py --probe-t 0.1,0.3,0.5,0.7,0.9 --n-groups 12 --device cpu`
（probe 模式只做前向、不采样，**CPU 就能跑，不占 GPU**，每次约 2–4 分钟）扫了 5 个 ckpt：

| t | E0@60k | E0@80k | **E0@100k** | inj3@25k(旧数据) | inj3-fixed@40k |
|---|---|---|---|---|---|
| **0.10** | 0.0264 | 0.0246 | **0.0223** | 0.0208 | 0.0227 |
| 0.30 | 0.0286 | 0.0320 | 0.0326 | 0.0182 | 0.0221 |
| 0.50 | 0.0638 | 0.1056 | **0.1826** | 0.0278 | 0.0364 |
| 0.70 | 0.1285 | 0.1960 | 0.2614 | 0.0543 | 0.0702 |
| 0.90 | 0.1992 | 0.2676 | **0.3266** | 0.1020 | 0.1226 |

### 结论 1（★ 最重要）：t=0.1 **不随训练增长，也不被任何机制拉动**
E0 自己从 60k → 100k，t=0.1 从 0.0264 **略降到** 0.0223（其余 t 都在涨）。
inj3@25k / inj3-fixed@40k 也是 0.021 / 0.023。
→ **t=0.1 的换书家速度场差在 ~0.02 处结构性饱和**，与步数、与已试过的机制都无关。
用户的目标「把 t=0.1 拉上去」，**到目前没有任何一条路做到，连 baseline 自己都不涨**。
→ 这个判据在 t=0.1 上**分辨力为零**，用它判定机制有效/无效会得到假阴性。

### 结论 2（方法论陷阱）：t≥0.5 **强依赖步数**，跨 step 比是错的
E0 的 t=0.5：60k=0.064 → 80k=0.106 → 100k=0.183（**近 3 倍**）。
所以「E0@100k 0.183 vs inj3-fixed@40k 0.036」这种比较**毫无意义**。
**任何 t≥0.5 的结论必须同 step 比。**（E0 的 25k/40k ckpt 已被 `ckpt_keep=8` 轮转删除，
现存 60k–100k，所以 inj3 那侧的同 step 对照只能等它跑到 60k+。）

### 结论 3（物理含义）：书家条件主要在**高 t**（去噪早期）起作用
t=0.9 时换书家能改变速度场 33%，t=0.1 时只改变 2%。
→ 风格是**早期注入**的，不是收尾时加的。
这解释了为什么所有"出口侧/后程"的风格注入改动（gate / lowrank / E1 的 style_gain）都没效果 ——
**改的不是风格真正起作用的地方**。

## 【★ 风格监督 / 对比学习设计】文档 `docs/922/94_style_supervision.md`

**核心设计原则（唯一关键判断）：内容匹配的对比**
- 朴素"拉近同书家、推远异书家"**会失败**：模型可借**内容**作弊（同书家共享字表分布）
- 正确：**正样本 = 同书家·不同字**（共享只有笔法，内容被打散）
  **负样本 = 同字·异书家**（内容相同，唯一差异是风格）
- → **poster 上那两行不只是给人看的，它们就是正负样本的定义**

**需要的东西**：在 VAE latent 上训一个小的**书家分类器** `f`（50,786 条 / 45 类，现成标签，~10 分钟），
训练时**冻结**。⚠ **第 0 步必须先验证 `f`**（留出集按**字**划分，准确率 ≥~40%），
否则整个 loss 是噪声 —— 不达标就停。

**两种监督项**：
(a) `L_style_cls = CE(f(x0_pred), y_callig)`，w=0.05 —— 最简，先做
(b) content-matched InfoNCE，`z = f_embed(x0_pred)`，w=0.02 —— 真正对症
共同细节：**必须按 t 加权**（x0_pred 在 t 大时是垃圾，建议 `1[t<0.5]`）；`f` 冻结；
复用已存在的 `return_pred_xstart=True` 链路。

**实验顺序**：0) 训并验证 `f` → 1) 加 CE 从现有 ckpt resume 20k → 2) 加 NCE → 3) 有效再从头 100k。
**判据必须同时含 frag**（条件增强可能就是拿风格保真度换来的，防按下葫芦浮起瓢）。

**备选（优先级低）**：把"同字最近邻 SSIM"或 latent 余弦直接当 loss —— 缺点是要 decode / 会推着模型"抄"某一张。

-> **更差**。主要杀手是 **latent 输入加噪**：它正好抹掉携带风格的细微笔触纹理。
   ⚠ 教训：latent 加噪 ≠ 骨架条件增强 —— 前者直接破坏被监督的那个量。
-> train 100%/留出 24% 是**良性过拟合**，缩模型只会欠拟合。**别再调编码器了。**

⚠ 操作失误：第二版把 `assets/style_enc_latent.pt` **覆盖了**更好的大模型权重。
   以后对比实验必须 `--out` 分开存。

### ★ 最终路线：放弃编码器，走 **L_retrieve（无编码器）**
```
Query   : x0_pred_i（只在 t<0.5）
正样本   : z_i（自己的 GT latent）
负样本   : z_j，同字·异书家（内容匹配，无法靠内容作弊）
L_ret = −log exp(−d(x0_pred,z_i)/τ) / [exp(−d(x0_pred,z_i)/τ) + Σ_j exp(−d(x0_pred,z_j)/τ)]
```
优点：无可训参数 → 无过拟合；天然内容匹配；**直接优化 cal_enrich 本身**；
成本 = 每步 K+1 次 latent gather（≈0）；不需要 decode。
负样本必须**按索引查表**取（batch 内配对会因 5750 字/batch 512 而恒空 → no-op，已踩过）。
实现要点：预建 `char -> [latent 行]`；`d` 用平方 L2；τ=0.1；t 加权；权重 0.02；
判据同时盯 frag + tgt_spec + cal_enrich。
