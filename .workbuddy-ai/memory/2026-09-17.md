**⚠ 概念澄清（用户指出）**：`intra`=**输出多样性**（同条件换种子，"同一个字写两遍像不像"）；
`inter_*`=**条件可控性**（换条件，"条件作用多大"）。**两者是独立维度，不可混谈**。
多样性判定**必须有参照系** = 真迹的自然差异。

**真迹参照值（(书家,字,书体) 三元组，加书体约束）**：
| | med | mean | p10 | p90 |
|---|---|---|---|---|
| 老数据 | 0.3946 | **0.3903** | 0.2421 | 0.5264 |
| HCSU | 0.1285 | 0.1729 | 0.0423 | 0.3645 |
- ⚠ 踩坑：只按 (书家,字) 分组会把**跨书体**混进来（老数据 41% / HCSU 23% 的多图组合跨书体）
  → 测的是"楷 vs 行"不是"写两遍"。**必须加书体约束**
- 两数据集"自然差异"差很远：老数据来自不同作品/扫描；HCSU 多图组合很多是**同页近重复**

**⚠⚠ 但"真迹差异"与"换种子差异"本质上不可比（用户指出，正确）→ 上面的判定作废**
- 真迹差异含**四类**成分：①书写状态 ②工具材料 ③**采集变化** ④作品语境
- 模型换种子**只含**"后验方差"
- **关键在 ③**：采集变化模型**不该也不能复现** → **真迹差异是「上界」不是「目标值」**
- 佐证：老数据 0.3903 vs HCSU 0.1729 **差 2.3 倍** → 这个数主要反映**采集条件**，不是风格
- **→ `intra` 绝对值没有合格线，只能做相对比较**。"48% → 不合格"**撤回**

**有效判据组合**：
| 判据 | 门槛 | 为什么 |
|---|---|---|
| intra > 0 且不太小 | 噪声必须被使用 | **intra≈0 = 采样塌缩**，扩散退化成确定性映射 |
| ratio_style/char ≫ 1 | 条件必须主导噪声 | 否则"风格控制"是假的 |
| ssim_to_gt/LPIPS 好 | 输出得像真迹 | 任务本身 |
- 且：对"给定 书家+字+骨架"任务，**低方差+高精度对生成工具反而是好事**，
  除非目标是"建模风格分布"。**判据取决于任务定位，需先明确**

### 【文献标准】多样性该怎么判（查文献结论）
1. **标准框架是"一对"**：Fidelity(Precision) / Diversity(Recall)。
   Improved Precision/Recall、Density/Coverage 等六对。**FID/IS 单一标量已被认为不够**
2. **★ 关键 norm：没有模型能达到真实数据的多样性**（Vendi Score 论文实测：
   Stacked MNIST 原始集 VS 943.7 / PresGAN 866.6 / Self-cond GAN 746.7，
   三者 NoM 都是 1000）→ **"低于真迹"是常态，不是失败**
3. **失败模式是 mode collapse**，用 **Vendi Score** 检测：
   `VS=exp(−Σλlogλ)`，λ 是 `K/n` 的特征值；**范围 [1,n]**；
   **VS=1 完全坍塌**；可解释为"**有效不同元素数**"；**不需要参考数据集**
   （正好绕开"真迹不可比"）→ 代价：reference-free 意味噪声也能得高分，**必须配质量指标**
4. ⚠ **对条件生成，VS 不该接近 n** —— 4 个样本本就该像（同字同风格），
   **VS 显著低于 n 是正常且期望的**。该看 VS 明显 >1（没坍塌）
5. **无黄金指标**：ICML2025 position (arXiv 2505.22450) 检验 6 对共 12 个指标，
   没有一个通过全部 sanity check → 只能**相对比较 + 坍塌检测**

### 【实测】Vendi Score → **我们的模型没有坍塌，多样性健康**
| | VS(有效变体数) | 上界 | 归一化 | **坍塌条件** |
|---|---|---|---|---|
| v12 cfg=0.7 | **2.233** | 4 | 0.558 | **0/30** |
| v12 cfg=1.0 | 2.210 | 4 | 0.552 | **0/30** |
| v12_d8 (K=3) | 2.084 | 3 | 0.695 | 0/4 |
- **0/30 坍塌** → 采样确实用到了噪声，**不是查表**
- 有效变体 2.23/4，对条件生成是**健康的**（有真实变化又保持同字同风格）
- **→ "多样性不合格"彻底撤回。结论：多样性健康，无坍塌**

### ★ CFG 文献明确"用多样性换保真度"→ 反向确认我们 CFG 失效
- CFG 原论文(Ho&Salimans 2022): "increasing guidance strength has the expected effect of
  **decreasing sample variety and increasing individual sample fidelity**"
- 实测(ImageNet64, p_uncond=0.1): w=0→4 时 FID 1.80→26.2（**涨 14.6 倍**），IS 53.7→260
- **→ 正常工作的 CFG，cfg 提高应明显降多样性**
- **我们实测 cfg 0.7→1.0：VS 2.233→2.210（不变）** → **从行为侧独立确认 CFG 失效**
  （与代码侧分析互相印证）

**★ 意外发现：多样性与精度是权衡的**
- v12: intra 0.1878 低 + ssim_to_gt 0.6757 高
- d8 : intra 0.2519 高 + ssim_to_gt 0.6487 低
→ **"容量小就更塌缩"是错的**：小模型是**更飘**（约束不住），不是更塌缩。
  与它 ratio 更低（1.42 vs 1.83）一致

**四条结论**：
1. **条件确实起作用，但信噪比只有 ~1.8** —— 条件驱动的差异只有噪声驱动的 1.8 倍
   （理想应 5~10×）→ **输出方差里"随机噪声"占比偏高**
2. ⚠ **inter_callig ≈ inter_char（0.3447 vs 0.3258）** —— 换书家和换字造成的差异**几乎一样大**。
   理想是内容 ≫ 风格（字要认得出来）→ **风格被过度表达 / 内容约束偏弱**。
   **两个模型都这样 → 共性问题，不是容量问题**
3. **XS/2 的 intra 高 34%（0.2519 vs 0.1878），inter 却差不多** → ratio 1.83→1.42
   → **小模型输出更"飘"、条件控制更弱**。这给 d8 strict 更差提供了机制解释
4. 两模型 inter_char 都没比 inter_callig 高多少 → 内容条件偏弱是共性

### 【已修】std 骨架尺度归一化
**问题**：std 明显比 GT 小 —— 实测 std 长边 med **172** vs GT 长边 med **224~230**，
**只有 72% 大**。→ std token 与 GT token 的空间覆盖不一致，模型要额外学尺度映射。

**方案对比**：
| 方案 | 评价 |
|---|---|
| A旧: std bbox **拉伸**到 256 | ✗ **压坏长宽比**（我第一版的 bug，用户指出） |
| A': 保比例长边→256 | ✗ 过头 14%（GT 只填充 0.875） |
| **C: 保比例长边→230（采用）** | ✓ 可复现 + 尺度匹配 |
| B: 逐样本对齐 GT bbox | 最优但**推理时没 GT，不可复现** |

**目标 230 的依据**：`GT 长边 228.5 / std 长边 172 = 1.33` → `172×1.33 = 229`
≈ **90%×256 = 230** —— 用户"用 90%"的直觉与统计吻合

**⚠⚠ 指标踩坑：落墨率与 Chamfer 都有"越小分越高"的偏**
- 骨架落墨率：std 越小 → 全落在 GT 粗笔画里 → 分越高
  实测 原样 0.414 / A' 0.325 → **假象："不改反而更好"**
- Chamfer(std→GT) 同样有偏
- **正确判据是"尺度匹配"**：归一化后 std 长边 229.0 vs GT 230.5 → 比值 **0.993**

**实施**：裁 bbox → 保比例长边缩到 230 (NEAREST) → 居中 →
**重新 skeletonize + 3x3 膨胀**（缩放会改线宽，必须重建 3px）

**结果**（51,036 个 std）：std 长边 229.0 / GT 230.5 = **0.993**；线宽 **3.49** ✓
目检 8 张：6 张完美匹配，2 张 GT 长边 248/250 的略小（固定目标的固有限制）

### 【分析】eval 与 epoch 对齐带来的优化机会 (doc70 §7, commit e029fc9)
**实测现状（从 12ch 日志挖的）**
- **1 张 4090 单卡（world_size=1）**
- **eval 每 5000 步 = `epoch_steps` → 正好一个 epoch 一次**；ckpt 每 2500 步（eval 的 2 倍）
- eval **39~49s/次**，跑满 100k = 40 次 = **28 分钟 GPU 被采样占满、训练停摆**
- eval **只在 rank 0** 跑（单卡时即唯一 GPU）
- eval 失败被 `try/except Exception: logger.warning` **吞掉**
- eval PNG **0 张**（已关）；ckpt **592 MB/个** → 23 GB/100k

**对齐带来的四个便利**
1. eval 可退化成 **epoch 钩子** → 实现简化 + **失败处理集中**
2. ★ **train-only 模式是「等价」的**，因为 **eval 点 ⊂ ckpt 点**

### 【性能】新一轮 infra 排查 + 4 项落地 (doc70 §8)
**先确认有余量**：12ch 实测 263ms/步，naive `2NT×3`=20.2 TFLOPs → 47% 峰值
（matmul-only 口径 ~28%）→ **不是纯 compute-bound**

**★★ 最大一项：H2D 拷贝没用 `non_blocking`**
`DataLoader(pin_memory=True)` 一直开着，但每步 `.to(device)` **全都没传
`non_blocking=True`** —— PyTorch 语义下**即使源在 pinned 内存里，不传就是同步拷贝**，
主机线程被阻塞。**pin_memory 完全白开。**
- 每步传输量：**图像 283 MB**（float32）+ latent/skel/aux 各 17.7 MB ≈ **340 MB/步**
- 修法：9 处 per-step `.to(device)` 全加 `non_blocking=True`（源非 pinned 会自动退回同步，**无副作用**）

**★ 每步 7 次 GPU 同步（全在 `backward()` 之前）**
5× `.item()` + `isfinite` 的 bool 判断 + `float(_cm.mean())`
→ 打断 CPU run-ahead → 流水线气泡。
修法：只留 NaN guard 必需的 `isfinite`；其余改 **GPU 张量累加**，日志步再取标量。
累加器用 **float64**（原语义就是 Python float；实测 float32 累加 50 项差 1.34e-06）

**循环不变量外提**
- aux 权重解析 + 3 处校验 + `_ch_w` 的 GPU 分配/切片赋值 → 循环外
- `dit.py` 的 `_inj = {blk:k for ...}` → `__init__` 预计算 `_inj_map`

**已排除**：DataLoader IPC（走共享内存传句柄）/ ckpt 写盘(已异步) / eval(已 deferred) /
grad clip(0.3ms) / EMA(已间隔+decay^N) / 启动 preload 27s(占 0.09%) / REPA fp32 升精度(0.05ms)

**待定**：
- 图像改 uint8 传输（283→71 MB，省 ~10ms/步 ≈4%）—— 需改 REPA 的 `x_0` 约定（跨模块）
- `compile_mode: default` → `max-autotune` A/B（本仓库 vae_fast.py 自己就用 max-autotune）

### 【已验证】4ch → 12ch 通道扩展是**逐位无损**的 (commit d9abc3a)
工具：**`tools/expand_4ch_to_12ch.py`**

只涉及 **3 个张量**形状变化：
```
① x_embedder.proj.weight      (384,4,2,2) -> (384,12,2,2)   拷前 4 个输入通道
② final_layer.linear.weight   (16,384)    -> (48,384)       按 patch 交错拷贝
③ final_layer.linear.bias     (16,)       -> (48,)          按 patch 交错拷贝
```
（`x_embedder.proj.bias` 形状 `[h]` 不变）

**⚠ 最易写错**：final_layer 输出布局是 `reshape(N,h,w,p,p,C)` —— **通道在最内层**。
通道**不是"前 4 行"**，而是每个 patch 位置内连续的 4 个。
必须 `view(HWpp, C, ...)` 再拷；直接拷前 16 行会**错位**。

**验证**：4ch 输出 vs 12ch 输出前 4 通道 **max|diff| = 0.000e+00**；新通道输出恰好 0。
→ 第 0 步的 12ch 模型**完全等价**于 4ch。

**判断**：
- **解决**：成本结构（预训练走 4ch 更便宜 + 收敛更好），且是**更干净的实验**（4ch ckpt 固定，只加 aux）
- **不解决**：aux 与 img **争 final_layer 梯度**。算 12ch 配置：img 4×1.0=4.0，
  aux 4×0.3+4×0.8=4.4 → **aux 占 52%**（配置注释说"等权 67% 有害"，
  0.3/0.8 只降到 52%，**没真正解决**）。评测只看 img 通道 → aux 占的容量是"浪费"
- **建议**：aux 权重先调小（如 0.1,0.2 → 占 23%）、后训练短 schedule + 低 LR，
  **同时盯 img 通道 loss 是否上升**（上升=aux 在抢容量）
- **更根本**：先想清 aux 通道的假设。若目的是"结构监督"，**REPA 已在做且不占输出通道、
  不改推理成本** —— 12ch 的负结果也支持这条路线
