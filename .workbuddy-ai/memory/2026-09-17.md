**⚠ 概念澄清（用户指出）**：`intra`=**输出多样性**（同条件换种子，"同一个字写两遍像不像"）；
`inter_*`=**条件可控性**（换条件，"条件作用多大"）。**两者是独立维度，不可混谈**。
多样性判定**必须有参照系** = 真迹的自然差异。

**真迹参照值（(书家,字,书体) 三元组，加书体约束）**：
| | med | mean | p10 | p90 |
|---|---|---|---|---|
| 老数据 | 0.3946 | **0.3903** | 0.2421 | 0.5264 |
| HCSU | 0.1285 | 0.1729 | 0.0423 | 0.3645 |
- ⚠ 踩坑：只按 (书家,字) 分组会把**跨书体**混进来（老数据 41% / HCSU 23% 的多图组合跨书体）
  → 测的是"楷 vs 行"不是"写两遍"。**必须加书体约束**
- 两数据集"自然差异"差很远：老数据来自不同作品/扫描；HCSU 多图组合很多是**同页近重复**

**⚠⚠ 但"真迹差异"与"换种子差异"本质上不可比（用户指出，正确）→ 上面的判定作废**
- 真迹差异含**四类**成分：①书写状态 ②工具材料 ③**采集变化** ④作品语境
- 模型换种子**只含**"后验方差"
- **关键在 ③**：采集变化模型**不该也不能复现** → **真迹差异是「上界」不是「目标值」**
- 佐证：老数据 0.3903 vs HCSU 0.1729 **差 2.3 倍** → 这个数主要反映**采集条件**，不是风格
- **→ `intra` 绝对值没有合格线，只能做相对比较**。"48% → 不合格"**撤回**

**有效判据组合**：
| 判据 | 门槛 | 为什么 |
|---|---|---|
| intra > 0 且不太小 | 噪声必须被使用 | **intra≈0 = 采样塌缩**，扩散退化成确定性映射 |
| ratio_style/char ≫ 1 | 条件必须主导噪声 | 否则"风格控制"是假的 |
| ssim_to_gt/LPIPS 好 | 输出得像真迹 | 任务本身 |
- 且：对"给定 书家+字+骨架"任务，**低方差+高精度对生成工具反而是好事**，
  除非目标是"建模风格分布"。**判据取决于任务定位，需先明确**

### 【文献标准】多样性该怎么判（查文献结论）
1. **标准框架是"一对"**：Fidelity(Precision) / Diversity(Recall)。
   Improved Precision/Recall、Density/Coverage 等六对。**FID/IS 单一标量已被认为不够**
2. **★ 关键 norm：没有模型能达到真实数据的多样性**（Vendi Score 论文实测：
   Stacked MNIST 原始集 VS 943.7 / PresGAN 866.6 / Self-cond GAN 746.7，
   三者 NoM 都是 1000）→ **"低于真迹"是常态，不是失败**
3. **失败模式是 mode collapse**，用 **Vendi Score** 检测：
   `VS=exp(−Σλlogλ)`，λ 是 `K/n` 的特征值；**范围 [1,n]**；
   **VS=1 完全坍塌**；可解释为"**有效不同元素数**"；**不需要参考数据集**
   （正好绕开"真迹不可比"）→ 代价：reference-free 意味噪声也能得高分，**必须配质量指标**
4. ⚠ **对条件生成，VS 不该接近 n** —— 4 个样本本就该像（同字同风格），
   **VS 显著低于 n 是正常且期望的**。该看 VS 明显 >1（没坍塌）
5. **无黄金指标**：ICML2025 position (arXiv 2505.22450) 检验 6 对共 12 个指标，
   没有一个通过全部 sanity check → 只能**相对比较 + 坍塌检测**

### 【实测】Vendi Score → **我们的模型没有坍塌，多样性健康**
| | VS(有效变体数) | 上界 | 归一化 | **坍塌条件** |
|---|---|---|---|---|
| v12 cfg=0.7 | **2.233** | 4 | 0.558 | **0/30** |
| v12 cfg=1.0 | 2.210 | 4 | 0.552 | **0/30** |
| v12_d8 (K=3) | 2.084 | 3 | 0.695 | 0/4 |
- **0/30 坍塌** → 采样确实用到了噪声，**不是查表**
- 有效变体 2.23/4，对条件生成是**健康的**（有真实变化又保持同字同风格）
- **→ "多样性不合格"彻底撤回。结论：多样性健康，无坍塌**

### ★ CFG 文献明确"用多样性换保真度"→ 反向确认我们 CFG 失效
- CFG 原论文(Ho&Salimans 2022): "increasing guidance strength has the expected effect of
  **decreasing sample variety and increasing individual sample fidelity**"
- 实测(ImageNet64, p_uncond=0.1): w=0→4 时 FID 1.80→26.2（**涨 14.6 倍**），IS 53.7→260
- **→ 正常工作的 CFG，cfg 提高应明显降多样性**
- **我们实测 cfg 0.7→1.0：VS 2.233→2.210（不变）** → **从行为侧独立确认 CFG 失效**
  （与代码侧分析互相印证）

**★ 意外发现：多样性与精度是权衡的**
- v12: intra 0.1878 低 + ssim_to_gt 0.6757 高
- d8 : intra 0.2519 高 + ssim_to_gt 0.6487 低
→ **"容量小就更塌缩"是错的**：小模型是**更飘**（约束不住），不是更塌缩。
  与它 ratio 更低（1.42 vs 1.83）一致

**四条结论**：
1. **条件确实起作用，但信噪比只有 ~1.8** —— 条件驱动的差异只有噪声驱动的 1.8 倍
   （理想应 5~10×）→ **输出方差里"随机噪声"占比偏高**
2. ⚠ **inter_callig ≈ inter_char（0.3447 vs 0.3258）** —— 换书家和换字造成的差异**几乎一样大**。
   理想是内容 ≫ 风格（字要认得出来）→ **风格被过度表达 / 内容约束偏弱**。
   **两个模型都这样 → 共性问题，不是容量问题**
3. **XS/2 的 intra 高 34%（0.2519 vs 0.1878），inter 却差不多** → ratio 1.83→1.42
   → **小模型输出更"飘"、条件控制更弱**。这给 d8 strict 更差提供了机制解释
4. 两模型 inter_char 都没比 inter_callig 高多少 → 内容条件偏弱是共性

### 【筛查】GT 噪点图 —— 我第一版判据大面积误判，修正后结论
**⚠ 教训：判据必须先目检验证**
- 第一版用「最大连通块占墨比 lcf < 0.30」判坏 → **大面积误判**
  （钟繇「侯」lcf=0.19、王羲之「乎」lcf=0.06 都是**干净图**）
- **书法字（尤其楷/瘦金）笔画本来就不连通，lcf 5~30% 完全正常**
- 误判结果：报"全量坏 7.6%"、宋高宗 41.6% —— **都是假的**

**修正后（只按开运算保留率 keep 分档）：**
| 档 | keep | 全量 | 占比 |
|---|---|---|---|
| clean | ≥0.60 | 52,739 | **98.72%** |
| light_speckle | 0.30~0.60 | 374 | 0.70% |
| heavy_speckle | 0.05~0.30 | 207 | 0.39% |
| **pure_noise** | <0.05 | **56** | **0.10%** |
| empty | 墨<10px | 48 | 0.09% |

**宋高宗 500 张真实分布**（目检确认）：
clean 282(56.4%) / light 170(34.0%) / heavy 27(5.4%) / **pure 21(4.2%)**
→ **不是整批坏**，只有 4.2% 是纯噪点。之前"41.6%"是误判

**纯噪点最多的书家**：宋高宗 15、王献之 8、钟繇 8、虞世南 7、黄庭坚 6、蔡襄 4、米芾 3、王羲之 3（合计 56）

**★ 修法测试结论：修复不可靠，建议只丢不修**
| 档 | 3×3 中值保留 | 3×3 开运算保留 |
|---|---|---|
| clean | 1.007 | 0.893 |
| light | 0.980 | 0.435 |
| heavy | **0.630** | 0.188 |
| pure | 0.195 | 0.008 |
- **中值滤波反而更糟**：纹理是细密点阵，中值把周围点当"多数"→ **连成块**
  （「憺」直接糊成一团黑）
- **开运算**对部分图有效（「予」很干净），但**细笔画图会被削碎**（「抴」「憺」）
- 干净图两者都基本无害（0.998 / 0.990）
- **→ 两类错误都可能，修复不划算**

**⚠ 另一个坑**：我渲染海报时把极性写反了（ink→白），看着像反色。
真实 GT 是**白底黑字**；"全黑"其实是"没有墨"。

**⚠ 极性检测的两个失败判据（务必记住）**：

**★ 「描满」修复 —— 用户指出旧方案方向错了**
- 旧: 3×3 **开运算** → 把笔画**削碎** ✗

- **✗ 不做 `binary_fill_holes`**

**⚠⚠ 两个坑**：
1. **`fill_holes` 会把闭运算连成的"网格"逐格填满** → 墨量爆炸
   （实测 **17.86× / 6.49× / 5.66×**，渲染出来整张全黑）
2. **顺序错也会爆**：先闭运算（散点连成网格）再填孔 → 同样爆炸 → **必须先去散点**

**修复效果**（keep<0.90 的 1,723 张）：
