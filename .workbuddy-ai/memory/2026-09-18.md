## 08:00-08:20：按用户要求停训练 -> 改 strict 250 -> 纯评测 155k ckpt

### 【已做】给 train.py 加了 `--eval-only`
加载 ckpt -> 跑一次 in-mem eval -> 退出，**不进训练循环**，不污染 step 计数 /
LR 调度 / optimizer / EMA。
不加这个开关时想评某个 ckpt 只能 `--resume-full` 再跑几千步等 epoch 落点 ——
**那会真的训练若干步，不是"评这个 ckpt"**（用户直接指出）。
用法：`--config <cfg> --resume-full <ckpt> --eval-only`

**踩的两个坑**：
- 函数内 `import` 会把名字变成**局部变量** -> `--resume-full` 分支引用到未绑定的
  `materialize_lazy_params` -> UnboundLocalError。改成**模块级导入**。
- `run_in_mem_eval` 的 `logger` 形参要的是**可调用对象**（默认 print），
  传 Logger 实例会 `TypeError: 'Logger' object is not callable` -> 传 `logger.info`。

### 回答"能不能解决"
**差距 0.188 本身不是 bug** —— `seen` 是 20 张**训练集内的图**（记忆指标），
`strict` 是未见「字×书家」组合（泛化指标）。**直接比是苹果比橘子。**

**真正的问题**：strict 的**绝对值**好不好？**没有参照**。

**缺的决定性实验**：需要一个 **val 集**（留出图 + 三元组**已见**），把差距拆开：
- 若 val ≈ seen  → 瓶颈是**内容泛化**（画不出新字）
- 若 val ≈ strict → 瓶颈是**图像记忆**（换个图就不行）
**只有这个拆解能告诉我们该拉哪根杠杆。**

**候选杠杆**：
1. `g`（标准字形）条件的强度 —— 未见字全靠它（glyph_scale_init=0.6,
   glyph_inject_layers=4, glyph_vec_cond）

3. 训更长（strict 仍在微升）
4. 更多"每书家字符数"（更多数据）
