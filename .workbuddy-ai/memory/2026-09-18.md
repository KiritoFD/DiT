### 【已修】评测保存标准字图时的 OOM（commit 2cd2d11）
**现象**：`input-g save failed: OutOfMemoryError('Tried to allocate 7.81 GiB...')`
**根因**：`save_input_g` 把 strict 的 **250 张一次性丢给 `vae.decode`**：
```python

```
而训练常驻 20.25 GiB → OOM。
**主路径（预测图 decode）一直是按 `vae_batch` 分批的，这个辅助函数漏了。**

**修法**：
1. `save_input_g` 加 `batch` 参数，按 `vae_batch`（默认 16）分批 decode + 每批清缓存
2. 异常处理补 traceback —— 原来只打一行 repr，OOM 被吞掉后只看到
   `input-g save failed`，**不知道 poster 会少一整行图**

⚠ **本修复在下次训练重启后生效**（模块已加载，热改无效）。当前运行的 poster
第 1 行仍缺失，但**指标不受影响**。

**教训：凡是"一次性处理整个集合"的辅助函数，都要检查是不是该分批 ——
主路径分批了不代表辅助路径也分批了。**

### 【★ 关键文献】Gu et al. 《On Memorization in Diffusion Models》arXiv 2310.02664
用 EMM 指标（记忆率）**实测**了数据/模型/训练三大类因素：

| 因素 | 对记忆的影响 | 实测数据 |
|---|---|---|
| 训练集规模 | ⬆️ 最关键 | CIFAR-10 **50k 时记忆率 0%**；1k 时 >90% |
| 模型宽度 | ⬆️ 提升记忆**最有效** | channel 128→320，EMM 1k→5k（**4 倍**）|
| 模型深度 | ⚠️ **非单调**，先升后降 | 12 块时 EMM 仅 1k-2k，继续加深**训练失败** |
| 训练步数 | ⬆️ 持续上升 | 1k 数据 40k epochs → >90% |
| Batch size | ⬆️ 越大越强 | 128→896：89.5%→92.8% |
| **weight decay** | **大值显著抑制** | **1e-2: 35.9%；5e-2: 13.8%；1e-1: 1.3%** |
| **EMA** | **几乎无影响** | 0.0→0.99929 记忆率不变 |
| **★★ 条件唯一性** | **触发记忆最强开关** | 无条件 0% → **唯一标签 >65%** |

**★ 最强的一条直接解释我们的现象**：
```
75% 的 (书家,字) 对只有 1 张样本
-> 条件 (y_callig, g) 与目标图近乎一一对应
-> 等价于论文里的"唯一标签"状态
```
**这解释了为什么缩模型没用**：问题不在参数量，在**条件的信息量**。
