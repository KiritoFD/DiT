## concat 应该在哪里（用户追问，已实现）
ref 是 `cat([callig,font,char]) -> Linear(3h->h)` = **特征维拼接多个向量因子**。
我们只有 callig 一个向量因子，直接照搬退化成单层 Linear（实测 cat==add 参数量
完全相同 36.4571M）。

**答案: 在条件向量 c 上 concat，操作数 = {e_callig, f(g)}**
```
c = t_emb + Linear( concat([ e_callig(128) , e_glyph_vec(128) ]) )   # 256 -> h
```
f(g) = 把 g_tok 的 256 token mean-pool 后投影成 128 维。
理由: (a) 唯一既非退化又对应 ref 形式的位置；(b) 补洞 —— 原先 `c = t_emb +
callig_proj`，**adaLN 调制分支从来看不到内容**，每个 block 的全局 scale/shift/gate
都不知道在写哪个字。

备选(未采用): g 的 256 token 拼进**序列**（xattn 加强版）—— doc54 实测 xattn
strict ≈0 / 成本 +33%，期望值低。

  - 无 g 时走零向量但**仍过 proj** → DDP 参数参与前向

## 参数量预算推演 → docs/system/62_param_budget_derivation.md
**实测规模表**（非估算）:
XS/2 d8 h384 **26.62M** FLOPs 0.527× / S/2 d12 h384 **37.25M** 0.790× /
M/2 d12 h432 **47.05M** 1.0× / Sp/2 66.70M 1.405× / B/2 147.63M 3.160×
**FLOPs 比可直接预测步速比 —— 已验证**: S/M FLOPs 0.790 → 预期 1.266×，
实测 5.28/4.15 = 1.272× ✓。以后墙钟推算直接用 FLOPs 比例。

**误差分解**: L(N) = L_floor + A·N^(−α) + B·(N/D)^β，N* ∝ D^(β/(α+β))。
实测 α ≈ 0（strict 在 30M–67M 上不随容量变）→ 公式退化，
问题变成"**求下界 floor 在哪**"。

**⚠ 关键歧义**: "strict 对容量不敏感"可能是 (a) 数据受限，也可能是
(b) ssim 饱和。doc59 已证 ssim 会撒谎；本轮 v12@15k 再次复现

## MFU 复核（我上一轮报错了峰值）
我用的 82.6 TFLOPs 是 4090 的 **FP32 shader** 峰值，不是 bf16 **张量核**峰值。
