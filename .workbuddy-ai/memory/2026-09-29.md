### 2.2 🔴 主要障碍：历史 ControlNet 框架**装不下当前 top10 backbone**
`src/model/legacy/controlnet.py::load_main_model()` 构模时**只传**：
`num_calligraphers / num_characters / condition_fusion / callig_embed_dim / char_embed_dim /
char_proj_mode / freeze_char_table / ids+dino / cond_drop_* / norm_type / mlp_type / qk_norm / rope / attn_impl`。

**缺 3 个 v25 必需的字段**：
| 字段 | v25 的值 | load_main_model | 后果 |
|---|---|---|---|
| `use_glyph_cond` | **True**（skel_as_glyph_cond=true） | 未传（默认 False） | glyph_embedder / 4 个逐层注入器**不构建** → v25 这些权重变 unexpected 被丢；且 **g 完全不喂**（v25 训练时 glyph_drop_prob=0，从未见过 g=0）→ 冻结 backbone 行为**分布外退化** |

| `cond_fusion_norm` | **split** | 未传（默认 **joint**） | **融合层架构不同** → cond_ln/cond_fusion 权重形状不符，静默丢失（仓库开头已警告过此类事故） |

→ 直接拿 `train_controlnet.py --config` 跑 v25 会**静默得到一个残缺 backbone**，指标不可信。

### 3.2 结论：**架构上不用改代码，但 id 值域必须处理**
- **不用改代码的部分**：from-scratch 分支自己 `DiT_2Cond_models[args.model](...)` 建模型，
  **没有 ckpt 要对齐** → 架构自洽，不存在 warm-start 那种静默残缺问题。✅ 用户判断正确。
- **但必须处理**（harness 的两处能力缺失）：
  1. `MCCDLatentDataset` **支持** `callig_id_map` / `callig_script_map`，但
     `train_controlnet.py` **不传**（第 ~270 行）→ `_map_callig(raw, None)` 退回原始 id；
  2. 该 harness **没有 `--no-char-cond`**，`DiT_2Cond` 的 `use_char_cond` 默认 **True**。
  而 top10 的 csv 用的是**原始 id**：
  | 字段 | 唯一值数 | 值域 |
  |---|---|---|
  | `calligrapher_id` | 10 | **53..9001** |
  | `glyph_id` | 9012 | **0..56830** |
  | `character_id` | 6845 | 0..56461 |
  → 若照 v25 那样设 `num_calligraphers=23`，会**索引越界**。
  → 解决（**零代码改动**）：把表大小设成覆盖原始值域 ——
  **`num_calligraphers=9002`, `num_characters=56831`**（历史 `ctrl_skel_top30` 就是这么做的：
  1011 / 35130）。代价是表稀疏浪费（callig 9002×128 + char 56831×256 ≈ 15.7M 参数）。
  → 备选（数据侧）：生成重映射 csv（`calligrapher_id`→pair_id 0..22，`glyph_id`→0..9011），
    表就能用 23 / 9012，更贴近 v25 语义。`assets/callig_script_id_map_top10.json` 的
    `pair_map` 有 23 条、值域 0..22，可直接用。

### 3.3 口径差异（对比 v25 时必须说明）
- harness **无 `--callig-emb-pretrained`** → 书家表**从零学**（v25 用了预训练 top10 表）；

### 6.1 ⚠️ 我自己诊断脚本的真 bug（重要教训）
```python
with np.load(f) as z:
    for j,i in enumerate(z['img_ids']):
        m[int(i)] = z['latents'][j]     # ← 每次循环都重新解压整个数组!
```
`z['latents']` 写在循环里 → 每个文件重新解压 **5120 次**（≈51GB）→ 卡死十几分钟。
**这就是我此前多次「shard 加载卡住」的真凶**（`diag_stdskel_consistency2.py` 卡 17min 同因）。
修法：`L=z['latents']; I=z['img_ids']` 先取一次。修好后同样加载 **4.6 秒**完成。
（`diag_stdskel_glyph2.py` 的懒加载版没踩这个坑，所以它 37 秒跑完。）

- 换 style 向量（预训练表 vs ckpt 训练表 vs 全零）输出都**一样糊**（ink 均 0.0055）
  → **不是 style 喂错**。

### 6.4 根因：`deform_skel` 的**双线性 warp** 把稀疏骨架 latent 抹平了（SkelNet 固有特性）
`g2 = F.grid_sample(g, grid, mode='bilinear')`，而 `off` 上限 `max_off=6.0`，
`grid = base_grid + off/(grid/2)` → off=6 相当于 **6 个 latent 像素**的位移。
对 32×32 上 ~1px 宽的骨架线做 6px 双线性重采样 → **必然糊**。
证据：把 `stroke_mod=0` 后 min 从 -1.99 变 -1.51（std 是 -2.17）→ **即使关掉 stroke_mod 也仍是软的**，
说明糊来自 warp 本身，不是 stroke_mod。
（v24 日志里 `off` 位移 1.40→2.37，量级确实很大。）

### 6.5 对实验设计的含义（需要用户定夺）
- v24_frozenskel 的 `g` **本来就是 `deform_skel(std)` = 这个 predskel** → 所以
  **v24 才是「predskel 口径」的正式实现**；v26 + pred 输入 是「拿 GT 训的模型喂 pred」的
  **训练/推理不匹配**，指标偏低（0.657 vs GT 0.754）有相当一部分来自这个不匹配 + 输入变软。
- 三条可选下一步：
  1. **接受现状**：把 `strict_pred` 当作"GT→pred 的敏感性下界"，主结论仍用 v24(真 pred) vs v26(GT)。
  2. **锐化 predskel**：decode→二值化→重编码，得到"硬"的 pred 骨架再喂（能回答"若骨架够锐，pred 能到多少"）。
  3. **换/重训 SkelNet**：当前 `deform_skel_top10_v1.pt` 闭合率仅 49%，本身就是短板。

DeformSkel 有 7 条路径，**我们关掉了最关键的两条**：
| # | 路径 | 作用 | 原配置 |
|---|---|---|---|
| 1 | FiLM 逐层调制 | 风格进 UNet | ✅ |
| 2 | 风格专属全分辨率偏移底图 (`style_off`) | 每书家"习惯间架" | ✅ |
| 3 | 内容自适应残差偏移 (`out`) | 内容驱动偏移 | ✅ |

### 13.2 SkelNet-V3 设计（提案）
```
输入: g_std (B,4,32,32) + style (B,128)
 ├─ PatchEmbed(4→D, p=2) → (B,256,D) 16×16 tokens, + 2D RoPE
 ├─ 风格 token: MLP(128 → K×D) → (B,K,D)
 ├─ depth × DiTBlock(adaln 风格调制)
 │     每层插 CalligStyleCrossAttn: Q=骨架token+2Dpos, K/V=风格token
 ├─ FinalLayer → 3 个头: offset(2ch) / residual(4ch) / topo(2ch)
 └─ g' = grid_sample(g_std, base_grid + off/16) + tanh(res/cap)*cap + topo项
```
- **规模**: D=384, depth=8, heads=6 → **≈18M**（现 4.1M）
- **仍是 deform**: 拓扑由 warp 保证，不会凭空生成笔画（满足用户"不要完全生成模型"）
- **当作映射/生成任务**: 用 transformer 直接做 (g_std,style)→形变场 的映射，不再是"小 U-Net 回归偏移"
- **cross-attn 的价值**: 让**每个骨架位置**在 K 个风格 token 间内容寻址 —— 比单个 FiLM 向量的
  表达力强得多，这是"书家间架习惯"能被表达的关键
- **训练路径**: 先用 standalone 直接监督（batch 4096，几分钟出"改善%"）验证，再考虑接冻结主干微调

## 十四、🔴 重大更正：predskel shards 曾被污染（我的 bug），已修

用户要求「简单版：先把书家表用 cross-attn 注入；FiLM 改 adaLN；不做 standalone 训练」。
实现过程中做验证时，**发现我之前生成的 predskel shards 是坏的**。

### 14.1 根因：`gen_predskel.py` 的懒加载器缓存 bug
```python
class Lazy:
    def get(self, iid):
        f, j = self.idx[iid]
        if self.cur != f:
            with np.load(f) as z: self.arr = z["latents"][j]   # ← 已按 j 索引成单张
            self.cur = f
        return self.arr                                        # ← 同一分片内所有 id 都返回它!
```
**同一 shard 文件内的所有 id 拿到同一个 latent。**
实测污染程度：
| shards | 条数 | 唯一 latent | 结论 |
|---|---|---|---|
| `predskel_eval_seen20` | 20 | 18 | ❌ |
| `predskel_eval_strict84` | 84 | **21** | ❌ 75% 重复 |
修法：缓存**整个 latents 数组**，再按 j 取。修后复核 **20/20、84/84 全唯一** ✅

### 14.2 ⚠️ 这推翻了我之前的一个结论
**v26 的 pred 轨（`strict_pred` 0.6558 / `seen_pred` 0.6601）是无效的** ——
模型被喂了几乎相同的骨架，当然出不来正确的字。
→ **"pred 轨躺平是因为 SkelNet 输出软"这个归因是不完整的**：主因是**输入被污染**。
（v27 不受影响：它已去掉 `_pred` 轨，SkelNet 在模型内部。）

### 14.3 「糊」的结论仍然成立（且比之前更严重）
用**修正后**的 shards 重测墨迹率：
| 骨架 | ink mean | median | min | max |
|---|---|---|---|---|
| GT | 0.0523 | 0.0515 | 0.0257 | 0.0690 |
| std | 0.0471 | 0.0489 | 0.0217 | 0.0659 |
| **pred** | **0.0017** | 0.0005 | 0.0000 | 0.0150 |
→ **pred 比 GT 稀 30 倍**。所以 SkelNet 偏软是**真实的、独立的问题**（warp 双线性抹平 +
残差路径被关），与 14.1 的 bug 是两回事。

### 14.4 本轮实现：SkelNet 的书家表 cross-attn + adaLN
1. **`_FiLM` 支持 `mode="adaln"`**（`LN(x)·(1+γ)+β`）
   - ⚠ 坑：conv 特征是 `(B,C,H,W)`，末维是 W 不是 C → `nn.LayerNorm(C)` 会报
     `expected input with shape [*, C]`。必须 permute 成 `(B,H,W,C)` 再 LN。
   - **adaLN 会破坏 step0 恒等**（`g=1,b=0` 时输出是 `LN(x)` 而非 `x`）：
     实测 `vs film max|Δ| = 2.295` → warm-start 语义被扰动（但 `to_gb` 形状不变，权重可载入）
2. **瓶颈处插 `CalligStyleCrossAttn`**（复用 `dit.py` 的实现）：风格向量 → `MLP(128→K×D)` →
   K 个 token；Q=瓶颈 token(+2D pos)，K/V=风格 token。
   - **step0 恒等已验证**：`film+K16` vs `film` 的 `max|Δ| = 0.000000` ✅（out_proj zero-init）
   - K=16 时新增参数 0.55M
3. 参数打通：`cli.py` 注册 `--deform-film-mode / --deform-style-tokens / --deform-attn-heads`；
   `dit.py` 加形参并透传；`train.py` / `model_io.py` 透传。

### 14.5 待办
- 需要**重新跑 v26 的 pred 轨**（或用修正后的 shards 补评）才能得到有效的 pred 口径数字。
- v27 仍在跑；其 eval 只用 seen/strict（std 骨架），不受 14.1 影响。

### 18.3 ★ VAE-free 的图像域监督（回答用户"loss 能不挂 VAE 吗"）
`DeformSkel` 里 `z_bg`(白背景 latent) / `delta_ink`(墨迹-背景差分) 两个 buffer 是**无条件注册**的
→ 墨迹图可以**解析地**算出来，零开销：
```
inkmap = ((g - z_bg) · delta_ink) / |delta_ink|²      # (B,1,32,32)
```
新增 `--w-mass`：对 pred/GT 的 inkmap 做 **L1 + 边缘梯度差**（= `img_loss` 的 VAE-free 版）。
`--w-img 0 --diag-decode 1` 时**完全不加载 VAE 到训练路径**（diag 只把 VAE 放 CPU 做诊断）。

### 18.4 ★★★ 关键发现：latent MSE 有**退化吸引子**
探针（width128/batch2048/expandable_segments）：
```
step0   MSE=0.68840  闭合 -41.5%   墨量 0.0677 / 目标 0.0536 (比 1.26)
final   MSE=0.29715  闭合  38.9%   墨量 0.0001 / 目标 0.0536 (比 0.00)  ← 塌到空白!

**"输出空白/背景"的 MSE(0.297) 竟然低于"输出 g_std"(0.487)** —— 因为稀疏 latent 的 MSE 被

→ 这解释了为什么历史上所有 standalone SkelNet 都不行；也解释了为什么 `img_loss` 必须带

### 18.6 用户问：「L2 换 L1 有效吗？或加超强墨量惩罚？」
我的判断（待实测验证）：
- **L1 未必有用**：逐像素 L1 的最优解是**中位数**，稀疏 latent 里某像素 95% 是背景 → 中位数仍是
  背景 → 照样塌；且 MSE 是二次的，对笔画像素（大误差）权重**更高**，换 L1 反而降低笔画相对权重。

  必须配**边缘梯度项**。

原始空间:   meanY=0.265  <  g_std=0.487  <  zbg=0.518                     ✗ 平均骨架胜出
```
**MSE vs L1（probe 空间里 MSE 反而更好，和原始空间相反）**：
```
                 α=0      α=0.3    α=1.0   全塌陷动态范围   工作区间[0,0.3]
probeL2        0.04405   0.07725  0.45355     10.3x          1.75x
probeL1        0.11094   0.17504  0.44799      4.0x          1.58x
```
两个 probe（MSE 训的 / L1 训的）结论一致。
**机理**：probe 输出已"去背景化"，能量集中在结构上，MSE 的二次加权（偏向大误差=笔画像素）
从劣势变优势；原始空间背景占绝对主导，MSE 梯度被淹没，所以那里 L1 才赢。
**梯度正交性**：cos(∇probeL2, ∇rawL2) 仅 0.06~0.37 → probe 提供的是**正交的新信号**，
不是 raw MSE 的重新缩放。cos(∇probeL2, ∇probeL1) ≈ 0.72~0.97（方向基本一致，只是尺度差）。
cos(-∇probeL2, 指向真值) 仅 0.06~0.25 —— 低是正常的（probe 只管骨架，不管墨色），不用慌。

**两个前提（不满足就会失效）**：
1. **probe 输入必须是图像 latent**。DiT 主训练喂 `pred_xstart`（图像 latent）→ in-distribution ✓。
   **SkelNet standalone 的输出是骨架 latent，直接喂 probe 是 OOD** → 那条路要么单独训
   「骨架 latent→骨架 latent」的 probe，要么直接用 VAE 解码算像素 loss（往返 IoU 0.956 无损）。
2. **权重要够**。probeLoss 基线 0.044 / 塌陷 0.45，主 loss 量级 0.3~0.5 →
   w=0.05 只贡献 ~0.002（0.5%），等于没挂。**建议 w=0.3~1.0**，且**别超 1.0**
   （probe 只有 225k 参数，权重过大会过拟合 probe）。

**结论**：`LatentSkelStructureLoss` 保持 `F.mse_loss`（实测优于 L1），把 `--w-latent-skel` 设 0.3~1.0。

### 18.26 ★★★ 结论与下一步（用户判断成立）
1. **latent MSE 是错的信号** —— 它把"输出空白"评为历史最优(MSE 0.2479)。铁证：v1。
2. **"不挂 VAE 的替代品"（probe 空间 / w-mass / 解析 delta_ink）也都不对**：
   它们都不直接约束"**g' 本身是一个骨架**"。
   - probe 空间损失：`MSE(probe(g'), g_gt)` 允许 g' 是糊的, 只要 probe(g') 对。
     **损失与消费者不一致** —— DiT 直接吃 g', 不吃 probe(g')。
   - w-mass：解析投影只约束"墨量总量 + 边缘能量", 不管拓扑。
3. **监督必须与最终消费者一致 = 直接约束 g' 本身是骨架**：
   - VAE 解码 g' -> 像素骨架 -> `_balanced_bce_dice`(BCE+pos_weight+Dice, 已有实现)
     + 连通分量/骨架 IoU。VAE 往返无损(IoU 0.956)。
   - VAE 显存问题用 **sub-batch 16~32 解码** + expandable_segments 解决（不是不挂 VAE 的理由）。
4. **评测判据要换**：`evaluate()` 现在以 MSE 为主判据，会把"输出空白"评为收敛良好。
   必须改成 **输出墨量比 + 骨架 IoU + 连通分量**。

### 18.29 ★★★ 总 batch 64 + 解码 chunk 的显存（用户目标配置）
`tools/bench_vae_cfg.py`（不开 expandable_segments）。
**★ 关键纠正：不能用 `retain_graph` 分块。** 先前"整批前向一次、再分块 backward(retain_graph=True)"
会让**解码器激活不被释放** → 分块等于白分，B=32/64 全 OOM。
**正确写法 = 每个 chunk 独立前向 + 立即 backward（不 retain）** = 梯度累加。
```
写法A(纯累加)  deformCk bf16   B   CH   peak alloc   resv    sec
               1      False   64   16     --         OOM
               1      False   64    8    12.57G     15.46G  2.34
               1      True    64   16    20.12G     21.26G  1.73   (fp32 直接 OOM)
               1      True    64    8    10.33G     10.92G  1.60   ★ 又快又省
               1      True   128   16    20.12G     21.20G  3.11
写法B(两遍)    1      True    64   16    20.12G     21.24G  1.61
```
→ 用户要的「总 batch 64 / 解码 16 / 不开解码器梯度检查点」**fp32 放不下，bf16 21.26G 勉强**。
   **chunk=8 严格优于 chunk=16**（10.92G vs 21.26G，且 1.60s vs 1.73s）。建议用 8。
   写法的另一形式(保留全批对比损失) = 两遍: pass1 全批 latent+contr backward; pass2 分块像素
   backward。峰值 = max(deform(B), deform(CH)+decoder(CH))，实测与纯累加一致。
   另: `chunk+ckpt`（解码器梯度检查点）能把 B 推到 512(13.95G)/1024(21.71G)，但用户不要。
