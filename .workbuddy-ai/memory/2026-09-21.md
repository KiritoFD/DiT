## 【★ 重大发现】v15 的多风格表是坏的 —— 不是容量问题，是表没区分度

### 现象链
1. v15a @150k strict 0.5699 ≈ v13 base @155k 0.5703 → **多风格零增益**
2. v16 few-shot diff 卡在 0.345 降不下去，grad-norm 只有 0.008
3. 我昨晚的 v15_fs 4 书家全部"纹丝不动"（0.1847→0.1848）

### 根因（两层）
**第一层（我的 bug，已修）**：`--train-only-new-callig` 的 mask 写死 `[_n_old, _n_all-1)`，
但 MultiStyleEmbedder 的表**不含 null 行** → v15 上算成 `[87:88)` 应为 `[87:87)` = 空
→ **0 个参数可训**，训练完全空转。
（LabelEmbedder(v13) 表 (N+1,D) 末行是 null → 减 1 对；MultiStyleEmbedder(v15) 表 (N,K*D)
无 null 行 → 不减 1。现在按类型分支处理。）

**第二层（真正的根因）**：**DINO CLS 特征几乎不区分书家**
```
样本间余弦(随机4000):        mean = 0.741
pair 质心间余弦(77 个 pair):  mean = 0.956  max = 0.998  min = 0.838
```
→ v15 的表（tools/build_multistyle_k4.py, DINO + K-Means）行间余弦 **0.860**
→ 87 个 pair 的向量**几乎共线**，模型根本分不出书家
→ 进一步拆：同一 pair 内 4 个子风格间余弦 **0.884**（"多风格"也是假的），
   子风格 k 跨 87 pair 余弦 0.85~0.87

### 对照
| 表 | 行间余弦 | 来源 |
|---|---|---|
| v13 单向量表 (45,128) | **0.020** | SupCon |
| v15 多风格表 (87,1536) | **0.860** ✗ | DINO + K-Means |
| **新 SupCon 表 (87,1536)** | **0.0019** ✓ | SupCon（本文档产出）|

## 【已做】用 SupCon 重训 v15 大表 —— 成功

## 【★★ 重大发现】简繁错配 —— csv 的 character 与 GT 实际字形不符

### 现象
用户发现"有些字明显是繁体，但标准骨架是简体"。

### 实测（肉眼 + OCR 双重确认）
- **csv 标注**：并 乱 来 国 学 后 书 东 乐 风 门 鸟（简体）
- **GT 实际**：并 乱 **來 國 學 後 書 東 樂 風 門 鳥**（繁体）
- **12 个里 10 个错配**（但那批是特意挑的简体字 → 有选择偏差）

### 统计
- 训练集里**繁体字占 20.3%**（10,296/50,786）
- 繁体字 1391 个 / 简体字 1056 个 / 简繁同形 3377 个
- 每个字有独立 gid（std_path 无共用）
- **std 字形本身是对的**（繁体字符→繁体字形，已肉眼验证）✓
- **真正的问题：csv 的 `character` 字段标的是简体，而 GT 写的是繁体** ✗

### 危害（用户洞察）
模型被迫"听简体 g 去写繁体 GT" → 听从 g 则 MSE 爆炸 →
**模型学会忽略 g，靠死记硬背** → 解释了几何控制失效 + SSIM 上不去 ✓

- **我们已经是 flow matching + logit_normal + heun(2阶)** → 比 DDPM 新一代 ✓

### REPA 的真相
