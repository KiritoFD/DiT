### ★ 修了 3 个保护机制漏洞（关键教训）
`_sync_work/cleanup_ckpts.sh` 原本的保护逻辑**静默失效**，差点删掉正在训练的 run：

1. **路径前缀不匹配**：保护文件内容形如 `assets/results/xxx/.../checkpoints`，而脚本已 `cd assets/results`，CPDIR 是相对路径 `xxx/...` → 前缀永不命中。**修法**：剥掉 `assets/results/` 前缀再入保护集。
2. **陈旧保护条目污染**：全库 69 个 `_active_ckpt_dir.txt` 中 68 个是几周前训完的历史 run，导致大批旧 ckpt 逃过清理。**修法**：加 24h 活跃度过滤（该目录 24h 内有新 `.pt` 写入才算活跃），陈旧条目降级为普通目录（仍按规则保留，不会裸删）。
3. **新 run 首个 ckpt 未落盘时无保护**：`v17_s2_s2z_baseline` 刚起（<5k 步）时目录内 0 个 pt，活跃度检测抓不到。**修法**：从 `pgrep -af 'src\.train\.train'` 的命令行解析 `--config` 取 run 名，硬保护并豁免活跃度过滤。

**通用教训**：「保护机制」一定要验证**实际生效**（`保护跳过: N 个` 从 0 变成 3 才是对的），否则保护只是心理安慰。前缀匹配类逻辑尤其容易静默失效。

## 中程结构 loss：PNG 路线已废弃 ★ 改回「训练前 encode 存 shards」

### 结论（用户裁定，重要教训）
用户原话：**「到时候训练之前，就 encode 好了啊」** / **「别动GPU，之前都encode过的，最多两个小时」**
/ **「给你那个png路线删除干净」**

我曾花大量精力做「纯 CPU 预建载体 PNG + 训练时 8x 下采样」路线，**这是错的**：
- 它是在**回避** VAE encode 成本，而不是解决它。把 encode 成本换成了一套
  pixel→latent 的手工近似，还引入 3 个静默失效风险。
- **正确做法就是最直接的**：GPU 空闲时**离线 encode 一次**存成 latent shards，
  训练时 mmap 直读 —— 正是 `tools/cpu_encode_50k.py` / `encode_csv` 既有的模式。
- 量级实测：CPU 单张 829 ms；用户说 GPU encode「最多两个小时」。
  **两小时的一次性成本，不值得用一套近似 + 3 个静默 bug 去绕。**

**通用教训**：遇到"encode 太重"的问题，先问「是不是一次性成本 + 能不能离线做」，
而不是立刻去设计在线近似。后者复杂度高得多且容易静默失效。

### 中程 loss 的正确实现路径（下次照这个做）
1. **离线 encode 载体**（GPU 空闲时）：
   - 多宽度骨架：先 `skeletonize` 到 1px 再 `binary_dilation[(w-1)//2]`，
     w=3/5/7/9/11 → `encode_csv` 存 `data/50k/shards_std_w{3,5,7,9,11}`
     - ★ 必须先 skeletonize：std 骨架 PNG 本身已有 ~3.5px 笔宽
       （实测 ink 4210 / skel 1193），直接膨胀会等效偏大 ~2.5px。
       skeletonize 后实测等效笔宽精准命中 3.04/5.05/7.04/9.03/11.01 px
   - 高斯模糊 GT：σ=0.5..4 → 存 `data/50k/shards_blur_s{...}`
2. **训练时** mmap 直读这些 latent shards，按 σ(t)/k(t) 选档（最近档）。
3. σ/k 调度用 `calibrate_mid_structure.py` 校准出的 json。

### 踩过的坑（若将来再做"从 pixel 造 latent"类近似，这些会复现）
1. **σ/k 与预建档位单位不匹配** → 选择器瞬间饱和在最大档，前几档**永不可达**。
   `k(t)` 是 latent px 而预建 w 是 pixel px；直接除 8 后 w∈[0.125,0.625] 对上
   k(t)∈[0,2] → t=0.35 就冲顶。
2. **载体用 min-pool 丢粗细** → 2px 与 10px 竖线 8x 下采样后是同一批格子。
   必须用 **area mean**（灰度 ∝ 墨占比 ∝ 局部线宽）。
3. **测试判据本身会误报** → 用"覆盖格数(<0.5)"判档位变化；avg-pool 保粗细时
   该值本就不随线宽变。应改用**墨量**(1-灰度)。
4. **`img_id` 是 int 而 PNG 是 6 位补零命名** → `f"{img_id}.png"` → `"0.png"`
   查不到 → 被当缺失填零，**不报错、loss 照常下降但从未生效**。
5. **`default_collate` 会转置 `list[str]`** → 按元素而非按样本分组。
