### ★ 显存实测（纠正此前"4096 是上限"的错判）
无梯度检查点、独立进程测峰值（4090 24G）：
- 4096×96 OOM 22.8G / 4096×64 OOM 22.2G / 4096×48 OK 18.6G
- 3072×96 OOM 22.5G / **2048×96 OK 18.2G**
- 前向 `no_grad` @4096×96 单独就 **12.3G**

**根因**：`d1` 在 32×32 全分辨率 ×96ch 下，单个激活张量 = batch×96×1024×4B；
batch 4096 → **1.61GB/张**，反向要存 6–8 张 → 单 d1 ~10GB。
**显存几乎只随 batch 线性，对 width 很不敏感**（96→48 只省 ~5G）。

**已实测无效的省显存手段**：`GELU(inplace=True)`（峰值一模一样，因为 GELU 反向可用输出）、
`bf16 autocast`（GroupNorm/cat 仍 fp32）。

**结论**：width 96 + batch 4096 单次前向在 24G 上放不下。三条出路：降 width（丢 v5 U-Net 暖启动）/
梯度累积 2×2048（**数学等价**，模型只用 GroupNorm 逐样本归一）/ 梯度检查点（用户明确禁止）。
**用户拍板：单次 2048 / width 96。**

### 顺带修掉的两个真 bug（`tools/train_deform_standalone.py`）
1. **`img_loss()` 从未被调用** —— 训练循环里只有一行孤儿注释，`--w-img` 是静默空操作。
2. **`_to_gray` 被 `@torch.no_grad()` 包住** —— 图像 loss 的梯度根本回传不到模型。
   拆成 `_decode_gray(lat, grad=False)`；训练路 `grad=True`；`--w-img>0` 时 VAE 常驻 GPU。

## ★★ 训练速度排查：0.496 → 0.358 s/step（1.39×）

用户质疑："30M 的主网络还 4 steps/s，你 infra 写的什么东西"。查下去确实是真问题。

### 定位（先测不猜）
- **吞吐对 batch 完全线性**（256→2048 都是 ~4100-4600 samples/s）→ 排除 launch 开销 / 分配器压力。
- **算子级 profiler**：`upsample_bilinear2d` 占 **30.2%**（40 次调用、平均 37.3 ms/次）。
- **根因**：torch 2.5 的 **NCHW `upsample_bilinear2d` CUDA 核病态慢**。
  batch 2048：C=192 8×8→16×16 **97.0 ms**；C=96 16×16→32×32 **49.6 ms**。
  两次加起来 147 ms/step，和 profiler 的 149 ms/step 完全对上（≈2 G 元素/s，带宽的 2%）。

### 修复（`src/model/deform_skel.py` 新增 `_up()`）
转 `channels_last` 再插值再转回 → 走另一条向量化核，**42× / 10× 更快**，
数值一致到 2.4e-07（纯 float32 舍入，逐形状验证）。**语义完全不变。**
结果：494 → **353.5 ms/step**，`forward(no_grad)` 255 → 114.9 ms，upsample 从 profile 消失。
真实运行 `step 500`：**248 s → 179 s**，功耗 **272 W → 400 W**（GPU 终于被真正驱动）。

### 已实测无效 / 更差（别再走一遍）
- **固定核 `conv_transpose2d` 替双线性**：快 78× 但**数值不等价** —— `align_corners=False` 的
  双线性权重是**位置相关**的（偶位 0.75/0.25、奇位 0.25/0.75）+ 边界 clamp，均匀 stride-2 核复现不了。
- **整模型 channels_last**：**420 ms，慢 0.84×**。风格是 `style_proj(st).expand(...)` 的跨步视图，
  `cat` 后退回 NCHW → 白付转换。**只有 `_up` 这种局部转换划算。**
- **`cudnn.allow_tf32=False`**：353.5 → 354.0 ms，**无变化**（用户要求关，已关，但要如实说它是 neutral）。
- `GELU(inplace=True)`、`bf16 autocast`：均无变化。

### 剩余瓶颈（下一步线索）
conv bwd 48.6% / conv fwd 16.3% / **nchwToNhwc 13.1%** / groupnorm 12%。
★ **结构性浪费**：`coarse=8` 让 `off_u` 在 32×32 算完立刻降到 8×8 再升回，
U-Net 在 32×32 的计算**信息上被丢掉**；32×32 那几个卷积占 **54% FLOPs**。
把 U-Net 直接做在低分辨率理论上能再快 ~2×，但要改架构。

待观察：step2000 评估的**墨量比**与**闭合率**（判 v9 是否修好了破碎）。

## ★★ v9 首次评估（step2000）—— 结论：远未可用

| 指标 | 无用 | 可用门槛 | v5 | **v9@2000** |
|---|---|---|---|---|
| style-follow | 50%=随机 | ≥75% | 99.8%* | **51.7%** ❌ |
| 闭合率 | 0% | ≥60% | 66.9% | **34.4%** ❌ |
| 墨量比 | <0.5/>2 | 0.85–1.15 | 0.40 | **0.04** ❌ |

step0→step2000：闭合 32.3%→34.4%（慢），**style-follow 51.4%→51.7%（完全没动）**；
`off` 0.42→1.72、风格底图 0.17→0.78、输出变化 0.015→0.157（在动，但方向不对）。

### ★ 关键发现：v5 的 99.8% 是残差在"作弊"
v9 **step0** 刚载入 v5 的 61/66 个键（含 `style_off`/FiLM/`style_proj`），
style-follow 只有 **51.4%** → **v5 的几何形变路径本身不带风格判别力**。
v5 的 99.8% 主要来自 `style_res`（每书家一张 4×32×32 **加性墨迹图**，
不移动笔画、只按书家补墨）→ 指标爆表但几何没动。
这正好印证"加性残差凭空产生虚假线条、破坏拓扑"。

### ★ 为什么 style-follow 卡在 50% 不动（真正病根）
目标 `MSE(g', g_gt)` **被"该字的平均形变"主导**，风格特异部分只是总方差一小块
→ 模型走捷径学到"字→平均形变"就降掉大部分 loss，风格梯度太弱 → 躺平。
**不是加步数能解决的。** 修的方向：目标函数显式奖励风格判别 ——
按**字内中心化**（减去该字跨书家均值）后算 MSE，或加对比/排序项
（`g'(c,k)` 应比 `g'(c,k')` 更接近 `g_gt(c,k)`）。

### 另外
去掉残差后只剩纯几何 `grid_sample`（只移像素、**改不了粗细/墨色**），
墨量比 0.04 是"没墨"不是"碎" —— 这是几何形变的能力上限，不是训练问题。

结论已写进 `docs/922/96_skelnet.md` 第 13 节。

## ★★ 实现监督对比学习（治 style-follow 卡 50%）

### 形式
`tools/train_deform_standalone.py::contrastive_loss(gp, gt, gid, sid, tau)`
InfoNCE / 监督对比：同字 c 内 `anchor=g'(c,k)`、`positive=g_gt(c,k)`、
`negatives={g_gt(c,k'): 同字不同书家}`。

### 三个关键设计决定
1. **相似度用余弦不用负 MSE**：余弦 O(1) 好调；负 MSE 当 logits 时 d≈0.33 会让 logits
   整体偏到 −33、正负样本只差 ~0.002 → softmax 极平、梯度极弱。
2. **负样本只取"同字且不同书家"**（`same_char & diff_style`）：同 (字,书家) 的组内重复
   样本不能当负样本。
3. **无负样本的行整行屏蔽并跳过**（用 −1e4 而非 −inf），避免 NaN。

### 单元测试（AST 抽真实函数体跑，非重写）
完美=0.0000 / 全错书家=14.2755 / 随机=2.0534(≈log7=1.946) / B=1 与无负样本=0.0000 不 NaN /
梯度可回传 ✓

### 接口与实验
`--w-contr 0.1 --contr-tau 0.07`（0=关）。
`_sync_work/run_v9c.sh` = **v9 的单变量 A/B**（配置逐项相同，只多对比项），
`--eval-every` 从 2000 收到 1000 以便尽快看到 ① 动不动。
`--out assets/deform_skel_v9c.pt`，日志 `logs/deform_v9c.log`。

**v9 已停**（style-follow 51.4%→51.7% 完全没动，继续跑没意义；mid-run 无 ckpt 落盘，
但 baseline 数字已在日志里）。v9c 已起，402 W / 100% util。
判读：**只看 style-follow 是否显著离开 50%**。

文档见 `docs/922/96_skelnet.md` 第 14 节。

### ★ 预先备好多种实现（用户要求"提前做出来几种"）
`--contr-mode {cos,mse,margin}` × `--contr-hard N`，都在
`tools/train_deform_standalone.py::contrastive_loss` + `_pair_mse` + `_hard_neg`。

| mode | 形式 | 与评估口径 | 超参 |
|---|---|---|---|
| `cos` | InfoNCE 余弦/tau | **不一致** | tau=0.07 |
| `mse` | InfoNCE **−(d−d_self)**/tau | 一致 | tau≈0.005 |
| `margin` | 排序 `relu(margin+d_self−d_neg)` | **完全一致** | margin≈0.005 |

`mse` 先减 `d_self` 的理由：softmax 平移不变，所以 d≈0.33 导致的 −33 绝对值**无害**；
真问题是正负只差 ~0.002，按绝对尺度猜温度会全平或全尖。减 d_self 后对角线恒为 0。

**单元测试**（AST 抽真实函数体，负样本 7 个 log(7)=1.946）：
cos 0/14.28/2.05；mse 0/399.9/11.75；margin 0/0.302/0.027；hard=3 分别 1.53/10.63/0.041。
边界(B=1/无负样本)=0 不 NaN；梯度有限；非法 mode 抛 ValueError。

**配套工具**（`_sync_work/`，已同步到远端根目录）：
- `run_contr.sh <mode> <w> [hard] [tag] [tau]` —— 一键起变体（单变量，只改 --contr-*）
- `contr_status.sh` —— 横向汇总，输出 `gap = shuffled − correct`（正=好）。
  **gap 比二值 style-follow 敏感得多**（n≈1600 时二值 1σ≈1.25pp），两个都要看。

**注意符号**：`correct - shuffled` 是负的才是好（correct 的 MSE 更低）。
我第一次把 gap 定义反了，已改成 `shuffled - correct`（正=好）。

## ★ v9c (cos, w=0.1) 最终判定：**负结果**

| 步 | style-follow | gap | 闭合率 | contr | off |
|---|---|---|---|---|---|
| 0 | 51.5% | +0.00047 | 32.3% | — | 0.42 |
| 1000 | 52.7% | +0.00239 | 33.8% | 2.032 | 1.70 |
| 2000 | **49.6%** | **+0.00033** | 35.2% | **2.226** | 3.48 |

step1000 的 +1.2pp 是**噪声**（1σ≈1.25pp），step2000 掉回 49.6%、gap 塌回 0.00033，
而 `contr` 反而从 2.03 涨到 2.23（对比目标本身在变差）。
**闭合率却一路稳升**（32.3→33.8→35.2）—— 典型的"平均形变学得更准、完全不理会风格"。
→ 余弦对比在 w=0.1 下不起作用。

## ★ 两个必须记住的坑

**① 各 mode 的 loss 量级差几个数量级，`--w-contr` 跨 mode 不可比**
- `cos`: loss ~2.0 → w=0.1 贡献 ~0.2（占 MSE 60%，有实际作用）
- `margin`: loss ~0.003 → w=0.1 贡献 ~0.0003（**可忽略**）
所以 margin 必须给大 w。**但 margin 的梯度量级与 MSE 同数量级**（都是 2(g2−gt)/D），
**判读要看 gap 不看 loss 值**。且 `margin` 给 gap 设了上限：gap≥margin 后梯度归零。

**② 进程会静默退出（未查明）**
v9c 在 step2000 eval 后无声消失：无 traceback、无 OOM-killer、RAM 充裕(251G 用 7G)、GPU 干净；
`dmesg` 被权限挡住拿不到证据。v9 同配置跑到 step2600 都没事 → **非确定性**。
怀疑 `expandable_segments` 或 eval 里反复搬 VAE。应对：
- 启动器**摘掉 expandable_segments**（唯一非标准设置，先排除变量）
- 训练器新增 **`--save-every N`**（之前只最后存一次 → 静默退出时**整轮白跑**）
