# 哪些变量改变了什么：证据等级与实施诊断

证据等级只表示当前项目的可归因程度，不是论文显著性等级：

- **A：较可靠对照**——同模型/同集合的配对干预，或主要配置接近的对照；仍注明单seed与实现边界。
- **B：组合改动的方向证据**——质量变化真实，但不独立归因到某一个模块。
- **C：探索/未完成**——样本少、阶段未跑完、没有独立验收；不作为部署替换依据。
- **无效：实现/协议错误**——不能用其数值解释模型机制。

## 2. 怎样从指标判断模型实际改变了什么

**结构、笔宽与书风应分开。** 同一张图的增粗可同时提高 Ink-IoU、降低 Frag、提高某些Writer分类分数；这不证明笔画组织更正确。反过来，细笔和飞白也会使阈值连通块变多，不能单凭Frag惩罚真实GT的细碎结构。

本轮读图最典型的反例：正确映射A/C的“西”仍缺结构、部分“而”更残缺，同时Frag比BASE更低。Deep85比Deep50的均值更好，但个别“西”变差。Qwen某些字覆盖变完整，同时“荷”等笔势更规则，离该GT并不更近；第三行“屍”还缺少内部结构，不能只当风格差异。

推荐固定报告四类观察：

1. 内容：错部件、缺笔、错误粘连、严重杂线；可靠OCR与人工确认。
2. 几何：Ink-IoU、bbox比例/重心、笔宽分布；这些都不是纯笔法指标。
3. 感知：LPIPS、实际笔锋/边缘/飞白图像；单个GT只是条件分布的一种实现，不要求逐像素相同。
4. 风格：同字同书体的GT相对方向、多字独立检索、盲评；既检查粗细也检查去掉粗细后的局部/结体差异。

SSIM/LPIPS只能说明与该参考真迹的相似性。FM训练目标是条件分布，不存在“这张随机生成必须与单张GT完全同形”的数学保证。可是严重错字与缺笔仍是应当修复的内容错误，不能用多模态为其开脱。

## 3. 训练预算与因果比较

名义曝光 `E = steps × actual_batch`；按分组/配对采样后，各样本出现次数通常并不均匀。

| 对比 | 曝光 | 为什么不能只看steps |
|---|---|---|
| V68 200k B288 | 57.60M | 和现代B512的同200k差很大 |
| Deep114 85k B512 | 43.52M | 计划60M未完成，不是从头跑满117.2k |
| 清洗组30k B512 | 15.36M | Top2/5/10/20每图重复次数差异很大 |
| Top2 10k B512 /6226 | 平均约822次 | Top20同10k约169次；“专门训练更快”部分是更多重复 |
| 直接FT50k B256 | 12.80M | 更新次数更多但总曝光少于P1/P2 |
| P1 10k +P2 20k B512 | 15.36M | 还改变LR/混合/dropout；不能说同预算胜过50k |
| Qwen20k B12 | .24M | 预训练底座、可训练参数、像素分辨率与U-Net不同；不能按step比较样本效率 |

早停点、最好checkpoint、最后checkpoint应分别标注。按验证指标选点后再在同一个集合宣称显著改善，存在选择偏差。正式模型选择应在固定验证协议完成，测试集合不再调参。

## 4. “分离”到底有没有用

需要区分四种完全不同的事情：训练时独立学表并冻结；Writer-only归一化支路；把输出写成base+residual；从不同字参考提取连续条件。它们不能合称一个已成功/失败的“解耦”。

现有证据最支持：**显式Writer条件有用；硬性规定它只能走一小段独立通路，没有展示稳定优势。** 共享U-Net更强可能来自允许Writer参与更广泛的内容依赖变换，也可能是预算、数据与优化差异；没有单变量对照前两者都只是解释候选。

主干与head的交换满足：

`v_BB − v_AA = (v_BA − v_AA) + (v_AB − v_AA) + (v_BB − v_BA − v_AB + v_AA)`。

最后的交互项不可省略。负余弦不是Writer总效应归零。正确的直接验收是同一GT/noise/t下 `L_AB−L_AA`、`L_BA−L_AA` 是否为正，并看样本不确定性。

CalliFlow `v=b+d_w` 时，真实Writer CFG是：

`v_cfg = b + s·d_w + (1−s)·d_null`。

只算 `b+s·d_w` 仅在 `d_null=0` 时等价。单pass residual gain应单独命名，不能沿用严格CFG的解释。

### 根因与影响

CSV行号只在特定数据契约内有意义，不能跨checkpoint视作全局身份。张量shape完全合法，所以不会抛错，却会生成别的书家条件。这里十行全不相同。

旧BASE85错误评测约 `.5812/.3590/.2455`；原生历史约 `.6129/.3209/.3378`。新旧STD张量SHA256同为 `d0b751829462df92d58a0789d030e6f0dc78064264ae04d6ed5d71fbd3a8fd3b`，因此不能把差距归因于STD bbox。影响当前已确认覆盖旧Deep的Qwen A/C及其BASE对照；**没有证据据此宣布所有现代P2评测都错了**。

### 本轮验证

48空闲卡上，用原始raw ID CSV、checkpoint对应映射、原生U-Net严格加载EMA，完成BASE85/A90/C90三组187张评估，固定seed0、Heun50、CFG1、STD sigma .65；日志 `REVIEW_EVAL_COMPLETE`。没有更新模型、重训或修改源实现。

BASE恢复 `.612881/.321187/.337529`，历史基线得到复核；A/C综合都没有优于起点，C也没有胜过A。此复现是必要的纠错诊断，不是为了穷举checkpoint或过度测试。

本地[配对结果](visuals/paired_C_minus_A.json)来自5,000次图像配对bootstrap；CSV已四舍五入，均值与原浮点汇总有微小差异。不是字符/来源分组或多训练seed的置信区间，不能按样本独立性过度解读。

### 建议的最小源码修复（尚未执行）

1. 评测以checkpoint的语义ID→embedding行映射为唯一来源；CSV使用raw ID，或显式附带其映射身份。
2. 只有CSV映射哈希与checkpoint相等才允许identity，不能根据“都是0..9”自动接受。
3. 模型加载时校验Writer、Script、VAE、STD契约；产生manifest而非静默重编号。
4. 修复后只需一个旧映射checkpoint回归与一个现代checkpoint对照，确认身份正确，不需要跑一套庞大测试矩阵。

本报告完成诊断与正确评估；旧入口风险仍在。历史错误分数应保留审计痕迹并标为无效，不应覆盖掉来源记录。

## 7. 当前最有价值的下一次对照

在继续训练前，先把 U100Base55k、Deep114成熟点、P2/Astrong 拉到同一清洗集合、STD和采样条件做候选验收。保留每张原图、固定失败集和正常集，不依赖海报挑选好看的字。

若要拆训练变量，从同一个P0开始，以相同总曝光、相同LR/EMA/dropout对比直接FT与分阶段混合/配对；先只改变采样。只有确认收益后，再单独改条件学习率或Writer支路。当前不缺新的复杂模块，缺的是能独立解释现有小幅收益的对照。
