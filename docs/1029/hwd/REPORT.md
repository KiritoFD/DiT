# HWD：30个面板已完成，中文书家身份校准不足

使用官方FontSquare VGG16-10400权重，严格加载完整checkpoint。官方HWD机制：RGB、补白、nearest缩至高32、[0,1]张量，不做ImageNet归一化或特征L2归一化；每位书家特征均值的欧氏距离，再按书家宏平均。当前256²单字缩至32²后，VGG最终只有一个空间token。

实现参照官方`aimagelab/HWD`的`HWDScore`非stream公式，版本`eabb5b5ede5899ac7f8b716429cbd1a1c97c7485`。官方stream路径混合作者计数存在疑点，本实现不使用该路径。完成两机9+21=30个协议面板，包含24个模型端点；没有重新生成图片、传输模型或改动训练。两机各自下载权重，CPU两线程、低优先级执行。

最小等价核验：从上游源码直接载入VGG16Backbone和AdjustDims，用相同官方权重和同一32²样本，与本实现比较512维特征，max_abs=0、逐位一致。它验证该方图前向路径，不声称所有数据协议与上游论文一致。

HWD的S5−S0为−0.05223，约降低6.14%，但S3更低、S4几乎不变。它与E-G身份排序不同，不能据此宣布S3或S5具有最真实书风。HWD没有单独检验目标书家身份；池化均值还可能掩盖差异。

额外身份核验沿用同书体、排除同字符、每候选书家K64。仅该核验将HWD特征单位归一化计算余弦；原始非方参考图先补为正方形。它是额外适配诊断，不是官方HWD分数。GT仅53.64%，说明当前特征/预处理域下缺少足够辨识能力；不能将它作为可靠中文Writer网络，更不能把生成AUC接近随机归咎于生成模型。

## 对下一步的影响

保留S0/S4/S5到85k的匹配续训，不改网络、不加入新Loss。S5的E-G优势有探索性配对区间支持，但独立HWD没有提供有效的书家身份验证。当前状态仍是“内容基线S0、局部融合对照S4、风格候选S5”，不是确认冠军。

HWD仅保留为辅助分布诊断，不升为审美或主要风格指标。完整数值及GT基准见本目录压缩JSON；原始逐query核验、输入身份和512维特征留在两端`assets/eval_hwd_20261029/<machine>/`。源代码见`tools/eval_unpaired/hwd/`。
