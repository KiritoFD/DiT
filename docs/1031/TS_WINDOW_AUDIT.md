# 时间步审计：结构损失在哪个 t 有效（以及为什么不能照搬 t≤0.3）

**日期：** 2026-11-02  
**脚本：** `tools/d_20261101/ts_window_audit.py`  
**数据：** `assets/d_20261101/ts_audit/ts_audit.json`  
**回答的问题：** 未来 STRUCT arm 的结构损失，应在哪个时间窗施加？

## 结论

**信号随 t 单调增强，小 t 几乎没有区分力。**

`margin` = 把同一个 latent 的笔画「打碎」后，结构损失上升多少。
margin>0 表示该项**能分辨「连通的墨」与「同样墨量的碎墨」**，因此能提供修复梯度。

| t | margin（err=0，理想估计）| margin（err=0.30，真实误差）|
|---|---|---|
| 0.05 | +0.0000 | +0.0001 |
| 0.10 | +0.0000 | +0.0005 |
| 0.20 | +0.0000 | +0.0012 |
| **0.30** | +0.0000 | **+0.0024** |
| 0.40 | +0.0000 | +0.0034 |
| 0.50 | +0.0000 | +0.0046 |
| 0.60 | −0.0000 | +0.0056 |
| 0.70 | −0.0000 | +0.0067 |
| 0.85 | −0.0000 | +0.0081 |
| 1.00 | −0.0000 | **+0.0089** |

## 三个要点

1. **理想估计（err=0）下 margin 恒为 0。** 这是**结构性**的，不是 bug：
   单步欧拉 `z_hat = z_t − t·v` 在精确 v 下**恰好还原 z_gt**，
   此时「干净渲染」与「打碎渲染」的差别只来自我人为覆盖的那 1/4 列，
   而该覆盖在 latent 空间被解码器平滑掉了大部分。
   → **「结构损失在哪个 t 有效」不是理想估计的性质，只在真实误差下才有定义。**

2. **真实误差下 margin 随 t 单调增大**（+0.0001 → +0.0089，约 **90×**）。
   原因合理：t 越大，z_hat 离 z_gt 越远、笔画越细碎，结构项越有东西可纠。
   → **旧代码的 `latent_struct_max_t=0.3` 恰好落在信号最弱的区间**
   （margin 仅 +0.0024，为 t=1.0 的 27%）。
   若照搬这个门，**P1 的结构损失会用最弱的信号去训练**。

3. **但 margin 的绝对量级很小**（最高 +0.0089，而结构损失本身 O(0.5)）。
   这意味着结构项在**损失数值上**几乎被重建项淹没。
   → 若采用，需要**较大的权重**，且应监控它的**梯度贡献**而不只是损失值。

## 对 P1 时间窗的建议

- **不要照搬 `t≤0.3`。** 若要用，至少覆盖到 **t ∈ [0.3, 1.0]**，
  并按 margin 曲线对权重做归一（大 t 给较小权重，避免主导）。
- **先验证梯度而非损失。** 真正的门是「结构项的梯度对 latent 的影响方向是否指向更连通」，
  不是损失下降多少。本审计只测了后者。
- **与 P0.5 的结论联合看：** P0.5 显示在 inversion 设定下拓扑项**没有可测的额外收益**；
  本审计显示它的信号在训练设定下也**偏弱**。两者合起来说明
  **「加一个 clDice 项就能修断笔」目前缺乏证据支持**。

## ⚠️ 本审计的设计边界（重要）

1. **误差模型是简化的。** 我用 `v_pred = v_true + ef·N(0,1)` 模拟模型误差，
   真实 U-Net 的误差**不是**各向同性高斯（它有结构、有偏置）。
   因此 margin 的**绝对值不可当真**，只有**随 t 的趋势**有意义。
2. **扰动是人工的**（按列覆盖 latent）。它确实制造了破碎
   （连通块 4→9、2→8、1→7，见 `check_shred_perturb.py`），
   但**不是** K 真实的破碎模式。margin 衡量的是「对这类人工破碎的敏感性」。
3. **n=16 字。** margin 数值小且未报方差，**不足以支撑精确的门限选择**，
   只够说明「小 t 信号弱于大 t」这个方向。

## 本轮修掉的一个真实 bug

三个版本的审计脚本都栽在**墨迹极性**上：墨是暗的，
`pw` 必须是 `sigmoid(+k(0.5 − mean))`。写成 `sigmoid(−k·mean)` 会让
墨迹概率**整体反相**，参考掩码 `pw>0.5` 变成空集，margin 恒为 0。
前两版报告的「margin 全 0」是**这个 bug 的症状**，不是实验结论。

同一 bug 也出现在 `p05_invert.py`，并**伪造了 P0.5 的核心结论**
（见 [P05_TOPOLOGY_LOSS.md](P05_TOPOLOGY_LOSS.md) 的自我更正）。

**防御措施：** 凡把图像转成墨概率，先断言参考掩码非空
（本脚本已加 `if ref.sum() == 0: continue`）。
