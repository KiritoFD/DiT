# SSIM × LPIPS 全代际散点（2026-11-01）

## 口径

- **同 GT 配对**：每个面板的 `g{i}.png` 对 `gt{i}.png`，187 行，不做重采样（面板本身已是 256×256）。
- **SSIM**：11×11 高斯窗（σ=1.5）、C1=0.01²、C2=0.03²，通道先取均值后计算 —— 标准 skimage 公式。
- **LPIPS**：AlexNet 主干、v0.1 权重、`spatial=off`，输入归一到 [-1,1]。
- **身份**：仅纳入 `historical_panels.json` 中 `exact order` 核验通过的 187 字面板。
- **y 轴已反转**：LPIPS 是距离，越小越好；反转后「右上 = 双优」。

> 数值全部**重新计算**，不是从旧报告抄的：这些历史目录里只存了 PNG，没有任何 metrics json。

## 三条结论

1. **v80 是双指标最优**：@190k SSIM 0.6192 / LPIPS 0.3805，两项都排第一。
   这与它在 E-G×OCR 图上的表现（86.7 / 73.8）一致 —— v80 是唯一在三张图里都靠前的模型族。
2. **SSIM 与 LPIPS 高度一致**（43 点近似单调）：说明在这批数据上两者测的是同一件事「像素级接近 GT」。
   这与 E-G/OCR 的双轴分离形成对比 —— 后两者测的是不同维度，这两个是同一维度。
3. **训练步数存在明显台阶**：scan 系列 20k→200k，SSIM 0.5374→0.6187（+8.1pp），
   LPIPS 0.4967→0.3812。但 v88 在 50k 只有 0.5509，远低于同期的 v80 —— 架构差异大于步数差异。

## 重要说明：不能与旧报告直接比

旧文档记录的 v68 SSIM 0.6120、MoYi 4ch 0.6085 等是**各模型的原始自评**（可能用了不同评测集、不同预处理）。
本表是**统一重算**：同一协议、同一 GT、同一实现。所以本表数值与旧报告不可混用。

## MoYi 的恢复尝试（2026-11-01 晚）

用户要求尝试用 GT 哈希反推标签。结果：

| 方法 | 结果 |

| 灰度数组哈希 | 0/187 |
| 反色灰度哈希 | 0/187 |
| 8 级量化近似哈希 | 0/187 |

检索池：`eval200_fixed`(187) + `eval200`(187) + `eval200_combo_unseen`(112)
+ 主索引 `train.csv`(9000 可读) + `train_top10_candidate`(8282) + `train_top10_noaug`(9000)
= **26,768 张图**，全部未命中。**结论：MoYi 的 GT 不在本地任何图库中，非压缩噪声所致。**

### 但 OCR 侧可以救：直接读 GT 图上的字

MoYi 的 GT 是正常渲染（白底黑字、墨占比 7–15%），可直接用项目 OCR 解码：

- 解码 187 张 → **184 个不同字**，平均置信度 0.613
- 与 `eval200_fixed` 规范顺序**位置匹配 137/187**，首个分歧在第 6 位，
  差异是 `復/复`、`咏/瓏` 这类**繁简/异体互读**，不是顺序错乱
- 用解码字作标签，**GT 自评 100.0%（187/187）** → 标签自洽
- **MoYi 12ch 生成图对这套标签 = 48.7%（91/187）**

这个 48.7% 才是 MoYi 12ch 的真实内容指标。此前基于 `eval200_fixed` 推算的 63.37% 是错配协议的产物，**已作废**。

### 为什么 MoYi 只进 SSIM×LPIPS 图、不进 E-G×OCR 图

- **SSIM/LPIPS 不需要标签**：只需生成图对自带 GT，MoYi 自带完整 187 对，**原生合规**，故已放回本图。
- **OCR 需要标签**：已通过 GT 解码重建（48.7%），理论上可入 E-G×OCR 图的内容轴。
- **E-G 需要书家标签**：解码只能得到字，**得不到书家**；26,768 张索引全未命中，书家无法恢复。
  因此 MoYi 在 E-G 轴上仍然没有合法坐标。
