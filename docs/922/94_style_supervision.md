# 922 / 94 — 风格监督：从"同字最近邻"诊断到对比学习的具体实现

> 承接 `93_samechar_nn_diag.md` 的诊断：**认字 +0.036（正常）/ 认目标 +0.012（只有 1/3）/ 认书家富集 1.1–1.9×（弱）**。
> 过去所有改动都在改"骨架条件怎么进网络"，而它本来就正常 —— 瓶颈在风格/实例特异性一侧。
> **而 loss 里没有任何一项约束"像不像这个书家"**：现在只有 velocity MSE + REPA(+可选中程)。
> 本文给出补上这一环的具体方案。

---

## 0. 先明确"风格监督"要监督什么

诊断给出的三个量正好对应三层监督目标：

| 量 | 现状 | 对应要监督的东西 |
|---|---|---|
| `mean_同字 − mean_错字` = +0.036 | ✓ 正常 | **认字**（已有骨架条件在做）|
| `own_gt − nn_mean` = +0.012 | ✗ 弱 | **认目标实例**（该输出更像"这一张"而不是"随便一张同字"）|
| 同书家富集 1.1–1.9× | ✗ 弱 | **认书家**（在控制字内容的前提下，输出应更像目标书家）|

→ 需要新增的 loss 应该**同时压后两项**。

## 1. 核心设计原则：**内容匹配的对比（content-matched contrastive）**

这是整个设计里唯一关键的判断，其余都是工程细节。

朴素做法是"把输出拉近同书家的样本、推远异书家的样本"。**这样会失败**，因为模型可以靠**内容**作弊：
同书家的样本往往共享内容分布（同一个数据集、同样的字表），embedding 只要编码"这个字"
就能区分同/异书家，loss 降下去但风格一点没学到。

**正确做法是把正负样本都按内容配对：**

| 角色 | 取谁 | 为什么 |
|---|---|---|
| **Query** | `f(x0_pred)`，本样本预测的干净 latent | 就是要被监督的对象 |
| **正样本** | **同书家、不同字** 的 GT | 共享的只有"笔法"；内容被显式打散 → 逼 embedding 编码风格 |
| **负样本** | **同字、异书家** 的 GT | 内容完全相同，只有书家不同 → 唯一的差异就是风格 |

这正是 poster 上已有的两行（`训练集·同书家异字` / `同字异书家`）——**那两行不只是给人看的，它们就是对比学习的正负样本定义。**

InfoNCE 形式：

```
L_nce = − log  exp( sim(q, z⁺)/τ ) / [ exp( sim(q, z⁺)/τ ) + Σ_{m} exp( sim(q, z⁻_m)/τ ) ]
```
`sim` 用余弦；`τ` 建议 0.07–0.1；负样本取 8–16 个同字异书家。

## 2. 需要什么：一个**冻结的风格编码器** `f`

对比学习要求 `f` 能把"风格"从图像里读出来。**不能用主干自己的特征**（它没被训练成风格判别器）。

**方案：在 VAE latent 上训一个小的书家分类器**（约 5–10 分钟，CPU/GPU 都行）
- 输入：`data/50k/shards_img` 里的 (4,32,32) latent（50,786 条，45 个书家标签，现成）
- 结构：3–4 层 conv（stride 2）+ 全局池化 → 128 维 embedding → 45 类 Linear
- 损失：CE（书家分类）
- **产物**：`assets/style_clf_50k.pt`，**训练时冻结**

**⚠ 第 0 步必须先验证 `f` 本身**：
- 留出 10% 样本（最好按**字**划分，避免同字泄漏）测分类准确率
- 若准确率 < ~40%，说明这个编码器读不出风格，**整个 loss 都是噪声**，不要往下做
- 顺手看：它的 embedding 上做"同字异书家"的检索命中率——这正是后面 loss 要优化的量

> 这个"先验证编码器"的步骤不能省。本项目已经有太多次"指标/模块建出来了但量的是噪声"。

## 3. 两种监督项（建议先做 (a)，再看要不要 (b)）

### (a) 分类监督（最简，先做这个）
```
L_style_cls = CE( f(x0_pred), y_callig )        # 输出应被判定为"目标书家写的"
```
- 优点：一行代码；`f` 已经会做分类；梯度稳定
- 缺点：只把输出推向该**书家的质心**，不区分"像这一张"还是"像那个书家随便一张"
- 权重起点 **0.05**，观察 `strict ssim` / `frag` / `tgt_spec` 三者

### (b) 对比监督（真正对症的那一项）
用第 1 节的 content-matched InfoNCE，`z = f_embed(x0_pred)` 取分类器的倒数第二层。
- 正样本：该样本的**同书家异字** GT 的 embedding（训练集里现成，可离线建索引）
- 负样本：该样本的**同字异书家** GT 的 embedding（同样现成）
- 权重起点 **0.02–0.05**

### 共同的关键细节
1. **必须按 t 加权**。`x0_pred` 在 t 大时是垃圾，拿它算风格 = 灌噪声。
   建议 `w(t) = 1[t < 0.5]`（或 `(1−t)^2`），并且**只在低 t 施加**。
2. **`f` 必须冻结**，否则它会被一起优化掉（退化成"什么都能匹配"）。
3. **需要 `return_pred_xstart=True`** —— 这条链路已经存在（`w_std_mid` 就在用），直接复用。
4. 预建索引：把 `char → [(id, calligrapher, latent_path)]` 和
   `calligrapher → [(id, char, latent_path)]` 在训练前建好（内存里只存路径/索引，用到再读 shard）。
5. 采样策略：**每个样本每步随机抽 1 个正样本 + K 个负样本**，避免固定配对过拟合。

## 4. 风险与护栏

| 风险 | 护栏 |
|---|---|
| `f` 本身读不出风格 → loss 是噪声 | 第 0 步验证分类准确率与检索命中率，不达标就停 |
| 模型"骗" `f`（对抗方向） | 权重小、`f` 冻结；监控 `tgt_spec`/`enrich` 与 `frag` 是否背离 |
| 风格 loss 压过重建 → 断笔比恶化 | **同时监控 frag**（这是本项目最容易被忽略的指标）|
| 正样本索引引入内容泄漏 | 正样本**强制不同字**；负样本**强制同字**（第 1 节）|
| 长训后期退化（55k 后的碎裂） | 判据区间仍是 55k–100k，别在 40k 下结论 |

## 5. 建议的实验顺序（每步都可独立判定）

| # | 做什么 | 判据 | 成本 |
|---|---|---|---|
| **0** | 训 `f`（latent 上的书家分类器），**留出集验证** | 分类准确率 ≥ ~40%；同字异书家检索命中率明显高于随机 | ~10 分钟 |
| **1** | 加 `L_style_cls`（w=0.05），从 E0 或 gq 的 ckpt **resume** 跑 20k | `tgt_spec` 与 `enrich` 是否上升；`frag`/`ssim` 不掉 | ~1 小时 |
| **2** | 若 (1) 有效，加 `L_nce`（w=0.02） | 同上，看增量 | ~1 小时 |
| **3** | 若有效，从头训 100k（与 gq 同配方 + 风格监督） | **55k–100k 的 frag 与 enrich 同时看** | ~7 小时 |

**为什么从 resume 开始**：能在一小时内知道方向对不对，不用等 7 小时。
**为什么判据必须含 frag**：本项目已经证明 frag 是唯一随训练恶化的指标，
且条件增强是用风格保真度可能换来的——**加风格监督后必须同时盯这两个，防止按下葫芦浮起瓢**。

## 6. 两个不需要学编码器的替代方案（备选，优先级低）

- **(A) 可微的"同字最近邻 SSIM"**：把 poster 那行的量直接当 loss
  `L = −SSIM(decode(x0_pred), GT_nn)`，`GT_nn` = 同字同书家的另一张。
  缺点：要 VAE decode（每步 +成本），且会推着模型"抄"那一张。
- **(B) 只做内容匹配的 latent 一致性**：`L = −cos(x0_pred, latent_nn)`。
  不用 decode，但同样有"抄"的倾向，且 latent 上的余弦是否等价于风格相似性未验证。

→ 两者都不如 (a)+(b)，因为 (a)+(b) 监督的是**风格这个抽象量**，而 (A)/(B) 监督的是**某一张具体图**。
