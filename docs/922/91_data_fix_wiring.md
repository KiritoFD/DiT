## 3. ★ 根因：配置继承链断了

```
9/21 21:29  v15c_fixed.json    ← 接上了修复版（train_50k_v2_fixed + shards_std_fixed + eval_v13_strict_fixed）
9/22 09:36  v15c_gzero.json    ← 也接上了
9/22 23:56  v17_s2_s2z_baseline.json
            _comment: "模板=v13_base_50k.json（逐字段复制，只改本文件列出的字段）"
            ↑ v13_base_50k 早于修复
            → data_csv           = assets/train_50k_v2.csv        （未修）
            → in_mem_eval_sets   = ...eval_v13_strict.csv:250     （未修）
            → skel_latent_shards = data/50k/shards_std            （未修）
→ E0 / E1 / inj3 / gate / lowrank 全部继承未修版
```

全库核查：40 个配置引用 `train_50k_v2.csv`，56 个引用 `shards_std`，
**只有 `v15c_fixed` / `v15c_gzero` 两个引用修复版**。

**通用教训**：修数据的产物必须**同时改掉所有在用配置**；否则一次"从老配置逐字段复制"
就会静默回退。这与本项目已经踩过的「保护机制要验证实际生效」「参数建出来了 ≠ 通路接上了」
是同一类 bug —— **产物存在 ≠ 产物被使用**。

## 4. ★★ 但是：修 eval 标签**救不了** strict

用户怀疑 strict 上不去是标签造成的。数据不支持这个假设：

| 组 | n | ssim | ink_ssim |
|---|---|---|---|
| 标签错的 20 条 | 20 | **0.5579** | 0.3787 |
| 其余 | 229 | 0.5524 | 0.3792 |

**错标样本的全图 ssim 比其余还高**。机理：简繁字对（静/靜、书/書）结构高度相似，
模型按 g 写简体、GT 是繁体，全图 SSIM 仍 ~0.56（白底抬高 + 结构相似）。

单看「升」（E0 baseline，100k 步）：

| step | 它全图 ssim | 排位 | 去掉它后 strict Δ |
|---|---|---|---|
| 40000 | 0.6177 | 188/249 | **−0.0003** |
| 100000 | 0.6046 | 177/249 | **−0.0002** |

它的 `ink_ssim` 0.2668 排 36/249 才暴露真问题 → 正是 9/22「白底抬高 SSIM」那条发现。

**→ 修 eval 标签是口径正确性问题，不是指标问题。对 strict 的影响 ~0.0003。**

## 5. 真正值得动的是训练侧

**为什么值得动**：9/21 的用户洞察 ——
> 「模型被迫听简体 g 去写繁体 GT → 听从 g 则 MSE 爆炸 → **模型学会忽略 g，靠死记硬背**
> → 解释了几何控制失效 + SSIM 上不去」

这**正是 inj3 三件事（丢弃 + 拼接 + 交叉注意力）想解决的"模型不肯用骨架"**。
而且历史效应量排序是 **数据质量 +0.087 / 实例骨架 +0.16 ≫ 注入方式 ≤0.008**
—— 我们已经在**未修数据**上做了 gate / lowrank / E1 / inj3 / midskel 五个机制实验。

**注意代价**：切数据后与 E0 不再单变量可比（E0 是未修数据 + 原架构）。
要干净对照，需要补一个 **E0-fixed**（同样配方、只换数据），才能把"数据效应"和"架构效应"分开。
