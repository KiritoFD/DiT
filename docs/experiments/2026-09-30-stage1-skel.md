# 两阶段：stage1 由标准骨架预测书家骨架（v31 / v32）

日期：2026-10-01
启动：`bash run_v31_v32_two_stage.sh`（tmux 会话 `two_stage`，单脚本串行）

```
stage 1 (v31_stage1_skel): std 骨架 + 风格 --> GT 骨架 latent    ← 替代 SkelNet
stage 2 (v32_stage2_img ): GT 骨架 + 风格 --> 真迹图像           ← v26 续训 + 整块抹白
```

两者都用仓库自己的训练管线 `src/train/train.py`（flow / logit_normal / heun /
EMA / CFG / 条件扰动 / 显存策略全是已验证的那套），只是**去噪对象不同**。

## 2. stage 1 的架构：照搬 v25_stdskel，只换去噪对象

| 项 | 值 |
|---|---|
| model | **DiT-2Cond-S/2**（depth12 / hidden384 / heads6，**36.4M**） |
| 网络输入 | 噪声化的 **GT 骨架** latent（4ch） |
| 条件 | **std 骨架** latent，走 `skel_as_glyph_cond`（**adaln 注入 4 层** + 128d mean 向量） |
| 融合 / 归一 | `factorized_cat` + `cond_fusion_norm=split` |
| 扩散 | flow + `logit_normal` + heun（采样端 50 步） |
| 架构细节 | rms / swiglu / rope(θ=100) / qk_norm / sdpa |
| 优化 | lr 5e-4 / cosine / warmup 2500 / wd 0.02 / ema 0.9999(interval 4) |
| 目标数据 | `data/top10_style23/shards_gtskel_w3` |
| 训练量 | **batch 384 × 80k 步**（≈5.0h）+ 早停 |

**唯一的功能性改动**：`latent_shards_dir` 由 `shards_img` 换成 `shards_gtskel_w3`。

### 为什么目标是 w3（不是 w7）

`shards_gtskel_w3` **就是** `shards_aux_skel3` —— **stage2(v26) 训练时的条件本身**，
所以 stage1 的产物天然落在 stage2 的训练分布里。

之前 w3 输给 w7（下游 0.6274 vs 0.6427）是因为那时用 **9M 小模型**：3px 骨架在 32²
latent 上只占 **0.375 格**，被 patch=2 一平均就没了。S/2 上该劣势应当消失。

## 3. ⚠ 三处更正（前几版都写错，已回滚）

### 3.1 不要用 xattn

`v10b_stdskel_fame3_c41x_cos_e`（MANIFEST 里 std-skel 家族 strict 最高 0.5680）
用的是 `Sp/2 + xattn×12`，我照抄了它。但 `docs/HISTORY_REVIEW_2026-09-22.md`：

```
| xattn 注入 | strict ≈ 0 且成本 +33% ✗✗ |
| 结论 5: xattn strict ≈ 0 且 +33% 成本 |
```

且 xattn 路径历史上从未跑通（`ctx_pos_g` 重复注册 bug）。
→ 改回主线（v19..v29）的 **adaln 注入 4 层**，模型从 Sp/2 降回 **S/2**。
（Sp/2 + xattn12 实测 **75.8M** 参数，明显偏大，就是这个信号；改正后 36.4M。）

### 3.2 12ch concat 输入是负面的

第一版照 `v13_12ch_post` 做成 8ch/12ch（条件拼进输入通道）：

```
| 4ch 预训练 + 后训练扩 12ch（v13_12ch_post） | 本轮新指标确认最优（ink_ssim） |
| 12ch 从头训                                 | strict −0.056 / seen −0.144（全面落后 4ch）✗ |
| 结论 4: 12ch 从头训劣于 4ch                 |
```

12ch 只有"**先训好 4ch 再扩通道微调**"才有用，从头训纯负面。
且我当时拿它和 v13_base_50k 直接比 ssim 也**无效**：两者评测集不同
（strict 250 vs 50），12ch 版还白捡了 20k 步预训练。

### 3.3 STATUS 文档：stage1 不是零贡献

`docs/STATUS_2026-09-30.md` 原记「pred 0.5399 vs std 0.5351 → stage1 只值 +0.005」。
错因：0.5399 来自 `train_joint_g2img.regen_pred_shards` 那条路径（该文档 §3.1 自己
记了它有 4 个 bug，含**极性反转**）。用该文档自己认定为"参照实现"的
`tools/gen_predskel_dit.py` 重跑同一生成器、同一批 84 条 → **0.6427（+0.108）**。
已在文首加了更正块。

## 4. stage 2 的条件增强：加噪 + 逐格丢 + **整块抹白**（新增）

推理时喂给 stage2 的是 **stage1 预测出的骨架**，它的失效模式不是"加点噪"，而是
**整段笔画没画出来 / 一整块糊掉**。v26 原本只有加噪，于是新增：

| 增强 | 参数 | 模拟什么 |
|---|---|---|
| `glyph_noise` | scale 0.3 / prob 0.5 | 条件不精确（v26 已有） |
| `glyph_patch_drop` | 0.05 | 逐格散点（像噪声点） |
| **`glyph_mask_*`** | **prob 0.5 / size 4 格 / jitter 1 / n 3** | **连续一整块变白** = "一段笔画没了" |

`glyph_mask_*` 的实现：随机把 n 个 3~5 格见方的**连续区域**填成纯白背景
（`Z_BG_VEC`，与既有 patch_drop 用同一个背景向量）。
尺度：**1 个 latent 格 = 8px** → 默认 4 格 = **32×32 px**（用户指定）。
代码：`src/train/train.py` 的条件增强段；参数注册在 `src/train/cli.py`。

## 5. batch / 步数（实测，目标显存 ~22G，每阶段约 5h）

| batch | 峰值显存 | 速度 |
|---|---|---|
| 128 | 7.2G | 13.2 steps/s |
| 256 | 13.7G | 6.6 steps/s |
| **384** | **20.1G** | **4.4 steps/s ← 采用** |
| 448 | OOM | — |

- stage1：80k 步 / 4.4 = **5.0h**
- stage2：由 30k 续到 80k = 50k / 4.4 = **3.2h**
- ⚠ 探测 batch 时若关掉 `compile`，显存会明显偏高（eager 保留全部中间量），
  容易得出"batch 320 都 OOM"的错误结论 —— 要按真实配置（`compile=True`）测。

## 6. 踩过的坑

1. **`ckpt_every` 与 `epoch_steps` 必须相等**，否则启动即报错
   （"不再支持取不同值"）。
2. **config 的 `_comment` 不能含真实换行**：JSON 里必须是 `\n` 转义。
   用脚本写 JSON 时尤其注意（我因此两次把配置写坏）。
3. **tmux 内层脚本里不能写 `pkill -f "src.train.train"`** —— 内层脚本的命令行
   本身就含这串字，`pkill` 会把自己杀掉，表现为"会话瞬间消失、GPU 空"。
   pkill 要放在外层。
4. **JSON 重复键后键胜出**：`early_stop` 我加了一次 true，文件模板后面还有一次
   false，结果静默取了 false（早停没生效）。
5. 看结构对不对要**直接看 poster**（`tools/poster_skelnet_now.py`），且必须
   `--cell 256`（原生尺寸）：缩到 150 会**抽样丢掉 1px 笔画**，看起来比实际碎得多。
6. 判据不要用"墨量比"：目标是 w3 骨架时，"完美答案"自己对 1px png 的 mse 反而
   比模型输出还差（0.094 vs 0.052）。
