## Tier 1 — 一次性定论（每个 ~10h，答"到底有没有效"）

### E1. C2OT × 数据增强 2×2（**最优先**）

固定 `S/2 33.9M / 150k / bs384 / 三表+route(2,4,5,6) / Heun-50`，只动两个开关：

| | 无 C2OT | C2OT |
|---|---|---|
| **无增强** | **v66 ✅ 0.5976** | **v67 ⬜ 已就绪** ← 起 |
| **3x 增强** | ⬜ 新建 `v71` | ⬜(今天那格被中止) |

- **跑 v67**（`src/train/configs/v67_tables_condroute2456_c2ot.json`，逐键只差 `use_c2ot/c2ot_mode=slot`）→ **C2OT 净效应 = v67 − v66**。
- **新建 v71** = v66 只把数据换成 aug 78k → **增强净效应 = v71 − v66**。
- 判据：Δ ≥ +0.0030 算有效；±0.0015 内算中性；≤ −0.0030 剔除。

### E2. FLUX 16ch 修复重跑（**唯一可能把上限从 0.650 提到 0.658**）

- **先验排查（必修）**：flux VAE 的 `scaling_factor`/`shift_factor` 是否接对（v63b 惨到 0.478 高度疑似这里错）。写 `tools/verify_flux16_pipeline.py` 自检往返 + 训练目标尺度。
- **然后**：同 `v63b` 配方（S/2 + 三表 + 16ch）重跑 40k，对照 4ch 同频。
- 资产已备：`shards_img_flux16`（38,583）+ `shards_std_flux16` + `flux_vae_diffusers`。
- 判据：修复后 ≥ 同期 4ch（~0.55@20–40k）→ 方向通；仍惨败 → 16ch 端到端证伪。

### E3. 容量阶梯（立 scaling law + 黄金尺寸）

```
固定: 三表 + route(按尺寸缩放) + aug 78k + LN/GELU + lr1.5e-4 cosine + Heun-50
      样本预算固定 = 7.68M (= 20k 步 × bs384)
尺寸: S/2 33.9M · M/2 42.5M · Sp/2 59.1M · B/2 131.2M · L/2 458.6M   (13.5× 跨度)
成本: 串行 ≈12h → 4090+48 并行 ≈ 6h
```
- 产出：第一条 `N_params → SSIM` 曲线；再补一个 2× 预算点即可拟合幂律。
- **黄金尺寸判据 = 每 GPU 小时得分**（要同步记 wall-clock），不是每样本。
