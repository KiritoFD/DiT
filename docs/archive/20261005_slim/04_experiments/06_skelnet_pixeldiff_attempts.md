# 06 — SkelNet 像素域/扩散化重构尝试全记录（2026-09-30）

> **一句话总结**：本日把 SkelNet 从「latent 域 warp」重构为「生成式」，先后试了
> **latent-DiT / bridge 起点 / 幅度校准 / 像素域 U-Net / 像素域 32² DiT** 五条路线。
> **骨架级判据的进展是真实的**（方向对齐 0.49/上限 0.51；像素域 dice 0.10 → 0.17），
> **但下游 ssim 始终没兑现**（0.55 ≈ 直接用标准骨架的 0.535 ~ 0.58），
> 唯一仍居首位的是 **latent-DiT + w7 目标 + bridge 起点（strict 0.6427）**。
> 结论：瓶颈不在「骨架生成」，而在 **① 骨架→latent 的接口保真度；② 风格条件在
> 网络里被稀释（`cond_fusion_norm=joint`）；③ 训练预算（本日全部实验 ≈ 仓库标准的 1/6）。**

---

## 0. 任务与判据

**任务**：给定 `g_std`（标准字骨架）+ 风格（书家×书体 pair_id），预测 `g_pred` ——
"该书家写这个字的骨架"，作为冻结主干（v25/v26 谱系）的 `g` 条件。

**为什么不能只看 clDice**（本日第一课）：

| 判据 | copy 基线（输入=输出） | 理论上限 | 动态范围 |
|---|---|---|---|
| clDice(容差3px) | **0.2666** | ~0.5 | 0.23 —— 判别力被压死 |
| **resAlign** = cos(z−g, x0−g) | **0（照抄的定义）** | **0.5087** | 0.51 —— 实测残差组内余弦 |

`resAlign` 上限 0.5087 = 同一 (书家,字) 多张样本的残差方向一致度（`tools/diag_residual_consistency.py`）。
**clDice 曾把"已学会 97% 方向"的模型判成"连照抄都不如"** —— 这是本日最大的判据教训。

## 2. 逐条尝试与结论

### 2.1 latent-DiT 生成（噪声起步，w3/w7 目标）

- **做法**：`DiT_2Cond`(depth6/hidden256/inject2，adaln) 在 32² VAE latent 上做
  rectified flow；目标 = GT 骨架 latent（`shards_gtskel_w3` / `_w7`）。
- **结果**：`resAlign` 0.4933(w3) / 0.5042(inject6) —— **方向几乎学到上限（97%）**；
  但 `clDice` 0.2428 < copy 0.2666，`ink比` 3.4（过墨）。
- **结论**：**方向对了，"幅度/形态"不对**；clDice 无法表达这一进展（判据问题）。

### 2.2 bridge（以 g 为起点）**带** g 条件 → 代数泄漏 ⚠

- **做法**：`x_t=(1−t)x0+t·g`，速度目标 = `g−x0`（残差），同时把 `g` 作为条件注入。
- **结果**：flow loss 掉到 **0.003**（噪声起步时是 0.21-0.25），但 `resAlign` 一路转负到 **−0.60**，
  采样发散（ink 6.8×）。
- **机理**：`x_t=(1−t)x0+t·g` 且 `g` 已知 → 模型可**代数解出** `x0=(x_t−t·g)/(1−t)`，
  不用学形变就能把 loss 压到 0；只有采样起点 t=1 处该式退化，但那一步学不到东西。
- **修复**：`--bridge-hide-g`（只把 g 当起点，**不喂给网络**）。字身份由输入流承载。

### 2.3 bridge + hide-g = 目前唯一"真的学到形变"的配置 ✓

- **结果**：`resAlign` **0.5067 ≈ 上限 0.5087**；`cosGen 0.870 > cosStd 0.8264`（**唯一打败"照抄"的 arm**）；
  `ink比` 1.44（最接近 1）；下游 **strict 0.6427 / seen 0.6517** —— **本日最佳**。
- **注**：w3 目标（resAlign 0.5067）优于 w7（0.4008）在**骨架级**；
  但 w7 在**下游**略优（0.6427 vs 0.6274）。两者不可混比，判据空间不同。

### 2.4 幅度校准（闭式 β\*）

- **做法**：`β* = argmin‖g+β(z1−g)−x0‖²` 的闭式解，对 128 张留出样本统计。
- **结果**：**β\* = 0.634 ± 0.064（变异系数仅 10%，极其稳定）**；残差幅度比 ‖d_gen‖/‖d_gt‖ = 0.78。
- **效果**：ink 比 1.59→**1.28**，cosGen 峰值 0.8714（+0.045 vs 照抄）；
  **但 clDice 在所有 β 下都低于 copy**（0.209~0.259 vs 0.2666）。
- **结论**：**latent 域"最优幅度" ≠ 像素域"最优结构"**；且 `resAlign` 对 β 不变（方向不变）。

### 2.5 换到像素域：64²「降采样→取 1px 骨架」落盘数据集

- **做法**（用户裁定）：原图/标准字图 → **min-pool 降到 64²** → 落盘 → 在 64² 上 `skeletonize` 取 1px。
  （顺序很重要：不是"256 提骨架再降采样"。）
- **产物**：`tools/build_skel64_dataset.py` → `data/top10_style23/skel64/*.npz`
  （`ids/std_ink/gt_skel/std_skel/img_ink`，**值域 0/255**）。
- **数据质量**：训练 34,749 / 验证 3,834；退化简并（原迹墨比 >0.5 的近黑块）**232 + 35 条已过滤**；
  空骨架 0。`1px@64` 墨比 ≈ **0.055**（稀疏！）。
- **踩坑**：早期版本存 **0/1** 而训练侧按 0/255 读 → **背景被当成墨，数据全废**（日志墨比 0.0002 是唯一线索）。
  现版本已统一 0/255，且训练侧**量纲自适应**。

### 2.6 像素域纯 MSE：loss 好看但结构=噪声 ⚠（本日最重要的诊断）

- 纯 MSE（velocity 目标）下：**train loss 1.21 → 0.14（"解释 88% 方差"），但采样结构等于噪声**
  （`dice64 0.094 ≈ 照抄 0.1098`）。
- **机理**：`x0` 是二值稀疏图（墨 5.5%）→ **94.5% 的背景像素平凡已知**（模型只要预测 `v≈ε−1`
  就能拿走近乎全部 loss）；真正承载结构的 5.5% 墨像素只占 loss 的 ~5%。
- **教训**：**稀疏二值目标上，"loss 收敛"完全不能作为学会结构的证据**。

### 2.7 结构 loss 的**门控方向**（与主干相反）⚠

- **主干配方**（`src/train/v11_struct-loss.json`）：`w_latent_skel/canny` + **`latent_struct_max_t=0.3`**
  （= 只在低噪声步监督，因为其结构 loss 走 probe，高噪声下 probe 不准）。
- **直接照抄会失效**：像素域的 `x0_pred = x_t − t·v`，在 **t 小的时候 `x_t≈x0`，
  即使 v=0（模型什么都不学）也有 Dice≈0.9** → 门控 t≤0.3 = **只留最平凡的一段，等于没监督**
  （实测 `struct` loss 第 1000 步就掉到 0.0086，且与速度目标互相打架）。
- **实测档位表**（v=0 时的 Dice）：

  | t | 0.02 | 0.10 | 0.20 | 0.30 | 0.50 | 0.70 | 0.90 |
  |---|---|---|---|---|---|---|---|
  | v=0 Dice | 0.891 | 0.610 | 0.423 | 0.315 | **0.195** | **0.130** | **0.093** |
  | 正确 v Dice | 0.9989 | 0.9989 | 0.9989 | 0.9989 | 0.9989 | 0.9989 | 0.9989 |

  → **必须门控在 t ≥ 0.4（高噪声段），那里 v=0 的 Dice 只有 0.09~0.20，才有梯度**。

### 2.8 墨像素加权 MSE（`--ink-w 10`）→ 过墨塌陷 ⚠

- **结果**：结构 loss 生效后 recall 从 0.31 跳到 **0.94**，但同时 **ink 比 7.7 → 8.5 倍**，
  precision 掉到 0.23，ssim 曲线"1000 步到顶"。
- **poster 判读**：多出来的墨**不是笔画加粗，是随机乱麻**（77% 的墨是垃圾）
  —— 用户的假设"多墨不一定是坏事"经数据检验为**否**。
- **修复**：**单边墨量约束** `relu(Σp − tol·Σt)`（`tol=1.5`）。
  注意**双边**版（`|Σp−Σt|/Σt`）会把模型逼到"不敢画"（recall 0.94 → 0.30）。

### 2.9 容量（64² U-Net）

- base 32（2.9M）→ base 64 + 16×16 与 8×8 两层自注意力：**视觉质变**
  （散点 → 乱麻 → 能认出的字），prec 0.23 → 0.41，平台从 1000 步推到 2000 步。
- 但骨架级 `dice64` 停在 **0.102 ≈ 照抄 0.1098**，下游 0.5486 ≈ std。**卷不动。**

### 2.10 pixel-32 + 抄 v25/v26 架构（本日骨架级最好）

- **动机**（用户裁定）：U-Net 没有全局注意力，笔画间无法全局协调；且 **VAE 的空间尺度本来就是 32²**
  → 在 32² 上做像素 = "用简单下采样代替 VAE"，token 数 16²=256 **正好是 `DiT-2Cond-S/2` 的设计点**，
  每步比 64² 便宜 4×。且 `1px@32 ≈ 8px@256`，与效果最好的 w7@256 载体同量级。
- **实现**：`tools/train_skelnet_fm_dit.py` —— 模型/条件通路**照抄 v25/v26**
  （`DiT-2Cond-S/2`、`skel_as_glyph_cond` 直通、`glyph_inject_layers=4`、`factorized_cat`）。
- **结果**（1 epoch = 训练集过 3 遍，每 epoch 评测）：

  | epoch | dice64 | prec64 | rec64 | inkRatio |
  |---|---|---|---|---|
  | 1 | 0.1374 | 0.297 | 0.969 | 3.78 |
  | 3 | 0.1600 | 0.468 | 0.664 | 1.24 |
  | **5** | **0.1723** | 0.493 | 0.577 | 1.156 |
  | 9 | 0.1671 | 0.518 | 0.526 | 1.033 |

  **dice64 0.1723（比 64² U-Net 的 0.102 高 70%）、prec 0.30→0.52、墨量收敛到 1.05×** —— 骨架级最好。
- **但下游**：strict **0.5520** / seen 0.5694 —— **仍 ≈ std 基线**。
  → **骨架质量大涨而下游纹丝不动，说明瓶颈已不在生成侧。**

### 2.11 超参/设计对照：**至少三项与 v25/v26 不一致**

| 项 | v25/v26 | 本日实现 | 后果 |
|---|---|---|---|
| **`cond_fusion_norm`** | **`split`** | **默认 `joint`** | 代码注释明示：`\|e_glyph_vec\|=60.9` vs `\|e_callig\|=9.86`（**方差差 38×**），joint 的 LN 分母被骨架信号支配 → **风格振幅被稀释约 1/5**。本任务的全部重点就是风格 |
| `warmup_steps` | 2500 | 200 | 一上来就满 LR |
| `ema_decay`（× interval） | 0.9999 ×4 ≈ 0.9996 | 0.99 | EMA 地平线 100 步 vs 2500 步；抖动大，且**评测会"看起来冻住"** |
| `max_steps`（@bs320） | 60k~150k | 3,060（@bs1024） | **曝光量仅约 1/6** |
| `lr` | 5e-4 | 3e-4 | 接近，非主因 |
| `norm_type/mlp_type/qk_norm/rope` | rms/swiglu/1/1 | 默认值 | **已是同一套**（默认即现代化组件）✓ |

### 2.12 其它实现级陷阱（都已修，记录备查）

1. **g 硬旁路 λ 过大**：`λ=4` 时 `sigmoid'(4)≈0.018` → **有墨处梯度被压死**（eval 完全冻结）。λ=1 才健康。
2. **EMA 地平线过短/过长**都会误判：`0.999`(地平线1000步) 在前几百步"评测冻住"；
   正确做法是让地平线与评测间隔匹配。
3. **`run_skel_calibration.py` 的 pred 目录优先级**：原实现 `ckpt 属性 or CLI` →
   传空 `--alphas` 时 ckpt 里的旧目录**静默覆盖**命令行，导致 β 扫描三个 β 全测了同一批旧 shards
   （数字一模一样）。已改为 **CLI 优先**。
4. **`torch.compile` + 大 batch 会额外吃显存**（inductor workspace）→ 16GB 基础上直接 OOM；
   且必须把 compile 放在 poster/dump 分支**之后**，否则评测路径也走编译图（`load_state_dict` 触发重 trace）。
5. **AMP 是关键**：纯 fp32 实测仅 ~15 TFLOPS（batch768/36M 模型，GPU 100%/395W）；
   加 bf16 autocast 后同 batch 显存减半、可上 1024。
6. **`ssim` 对曝光不敏感**：漂白（灰糊）的生成仍能拿 0.55 —— 判读必须配合 poster 与 `ink_ssim`。
7. **收尾管线的几何量化**：`32² → nearest×8 → 256 → skeletonize → 3px 膨胀`，
   nearest ×8 把 1 px 变成 8×8 方块，**几何量化误差可达 ±4px@256**（GT 骨架只有 3px 宽）。

## 3. 定论

1. **"学不到"是错的 —— 但学到的不是下游要的东西。**
   latent 域方向对齐拿到上限的 97%（resAlign 0.5067/0.5087），像素域 dice 提升 70%，
   这些进展**都是真的**；**但它们都没能转化成下游 ssim**（始终 0.55 ≈ std）。
2. **判据必须"双轨"**：`clDice` 判别力不足会把成功判成失败；`ssim` 对曝光不敏感会把失败判成成功。
   本日的 `resAlign`（latent 方向）+ 像素域 `dice/prec/rec/ink比` 已经比两者都好。
3. **稀疏二值目标的 MSE 是陷阱**：loss 收敛与结构学会**没有关系**；
   必须配结构 loss，且**门控方向与 latent-probe 方案相反**（高 t 监督）。
4. **风格被稀释是本日最可疑的"设计 bug"**：`cond_fusion_norm=joint`（默认）在
   glyph/callig 方差差 38× 时把风格振幅稀释 ~1/5 —— 而我们唯一需要的恰恰是风格。
5. **下游瓶颈已从"生成骨架"转移到"接口"**：
   (a) 骨架几何保真度（收尾管线量化、32² vs 256 的尺度）；
   (b) 条件 latent 的量级/分布保真度（poster 显示"整张发灰"= 幅度特征）；
   (c) 风格条件的有效幅度（`split` vs `joint`）。

## 4. 下一步（按性价比，未执行）

1. **把 `cond_fusion_norm="split"` 传进去重跑**（一行改动，直接针对风格稀释 38× 问题），
   同时把 `warmup=2500`、`ema_decay=0.9999×interval4`、`max_steps` 对齐 v25。
2. **修收尾保真度**：`nearest×8` → **bilinear + 阈值**（亚像素几何）；
   或**跳过 32²**，直接 64²/256 输出再 encode。
3. **量 latent 幅度**：`‖predskel_latent‖` vs `‖GT骨架_latent‖`（`shards_aux_skel3`）的比值 ——
   若显著偏小，则"发灰"就是幅度问题，需要量级校准（与 2.4 的 β\* 同源）。
4. **回归到已被验证的最佳组合**：latent-DiT + **w7 目标** + **bridge+hide-g**（strict 0.6427），
   在其上做增量（例如只改 g 注入层数 / renorm 宽度），而**不是**继续换生成范式。
5. 若要继续像素域：**先把下游 ssim 作为唯一验收标准做小步对照**（每次只动一个变量），
   并用 poster 检查"发灰 / 缺笔画 / 几何偏移"是哪一类。
