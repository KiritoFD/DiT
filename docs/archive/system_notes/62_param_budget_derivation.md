## 1. 框架：误差分解

把测试损失写成三项：

```
L(N) = L_floor  +  A · N^(−α)   +   B · (N / D)^β
        ↑            ↑                  ↑
      不可约     容量项(欠拟合)      估计项(过拟合)
```

- `α`：容量项的衰减指数。**α 越大，加参数越有用**
- `β`：过拟合项的增长指数
- `D`：数据量（28,569）

最优点 `dL/dN = 0` 给出经典的

```
N* ∝ D^( β / (α+β) )
```

**关键洞察**：如果实测发现 `α ≈ 0`（strict 不随容量改善），
那么这个公式退化为"**N 越小越好，直到撞到下界**" —— 问题从"求最优点"
变成"**求下界（floor）在哪**"。

---

## 2. 用我们自己的锚定 α

| 证据 | 结果 |
|---|---|
| v12 (S/2, 36.4M trainable) vs v11 (M/2, 42M trainable)，同 step 逐样本配对 | strict 差异 **不显著**（5k 后全部 \|t\|<2） |
| doc 54：S/2 30M / M/2 49M / Sp/2 59M 三档 | strict 全部落在 **0.51–0.57** |

→ **在 N ∈ [30M, 67M] 上，d(strict)/dN ≈ 0，即 α ≈ 0。**

⚠ 但 doc 54 那张表来自旧配方（我们现在 M/2 实测 seen 0.77，
已超过该表给 Sp/2 的上界 0.67–0.76），**表本身不可直接迁移**；
唯一可用的是"strict 在该区间内对容量不敏感"这一**定性**结论。

---

## 3. ⚠ 必须先破的歧义：α≈0 是真的，还是 ssim 饱和？

"strict 对容量不敏感"有两种截然不同的解释：

| 解释 | 含义 | 对策 |
|---|---|---|
| **(a) 数据受限** | 容量已经够了，瓶颈在数据 | 缩容量，把预算给数据 |
| **(b) 指标饱和** | ssim 看不出容量带来的细节改善 | **缩容量会丢质量，只是指标看不见** |

**证据倾向 (b)**：doc 59 已实测 ssim 会撒谎 ——
"图糊成一团黑，只要白底比例对，ssim 就不会太低"，它掩盖了"字形根本没出来"。
本轮 v12 也复现了：step 15000 时 v11 能看出字形、v12 是墨团，
**而两者 ssim 几乎相同**（0.4796 vs 0.4860）。

**而且我们发现一个现成的漏洞**：
`eval_stdskel_summary.csv` 的表头里有 `lpips_mean` 列，但**所有行都是空的** ——
说明 LPIPS **从来没有被计算过**。而 LPIPS 恰恰是对结构和细节敏感的指标，
正是用来区分 (a) 和 (b) 的工具。

→ **补 LPIPS 是零训练成本的动作，且必须在缩容量之前做。**
否则我们可能在错误的指标上做一个看起来正确的决策。

---

## 4. 过拟合侧给上界

实测（N = 47.05M，M/2）：

- gap(seen − strict)：40k 的 **−0.0126** → 157.5k 的 **+0.2089**
- 47 个相邻点里 42 个单调上升，斜率 **+0.00217/1k（t=+23.0, R²=0.920）**
- **到 157.5k 仍未饱和** → 47M 有大量富余的"记忆容量"

记忆容量大致 ∝ N（参数越多越能记住 36 位书家的风格）。
若目标是把渐近 gap 压到一半（~0.10）：

```
N ≈ 47.05M × 0.5 ≈ 23.5M
```

→ 上界估计 **N ≲ 24M**。

---

## 5. 样本数启发式

窄域从头训练的经验区间：**~100–1,000 params / 训练样本**
（低于 100 通常欠拟合；高于 1,000 通常过拟合明显）。

我们当前的位置：

| variant | params/sample | 判断 |
|---|---|---|
| M/2 | 1,647 | **超出区间上界** |
| S/2 | 1,304 | 仍超出 |
| XS/2 | 932 | 刚好落在上界内 |
| （假想）h=320, d=12 | ~900 | 落在区间内 |
| （假想）15M | 525 | 舒适区 |

→ 与观测到的过拟合**方向一致**：我们现在确实偏高。
落在区间内要求 **N ≤ 28.6M**；舒适区 ~500–800/sample → **14–23M**。

---

## 6. 结构侧：应该先缩深度，而不是宽度

- **渲染任务本质是"浅"的**：局部特征提取 → 少数几轮全局协调 → 局部输出。
  书法渲染不需要像语言模型那样的深链式推理。
- **h=384 对 4 通道 latent 是 96× 扩张**，表征带宽很充裕
  （doc 54 的"骨架→墨映射缺带宽"结论是在 h=384 时代下的，且当时
  同时改了别的东西；我们的 v12 用 h=384 已能出字形）。
- → **深度（12 层）比宽度更可能被过度配置。**

所以探针顺序应是：**先 depth 12 → 8（XS/2），再考虑缩宽度**。

## 8. 推荐的探针阶梯

| 优先级 | 探针 | params | FLOPs vs M/2 | 预期步速 | 50k 步耗时 |
|---|---|---|---|---|---|
| **P0** | **补 LPIPS**（改 eval，零训练） | — | — | — | 0 |
| **P1** | **XS/2**（depth 8, h 384） | 26.62M | **0.527×** | ~7.9 step/s | **~1.8h** |
| P2 | h=320, depth 12 | ~26M | ~0.55× | ~7.5 step/s | ~1.9h |
| P3 | depth 6, h 384 | ~20M | ~0.40× | ~10.4 step/s | ~1.3h |

**为什么先做 P1**：
- XS/2 是 registry 里**现成**的变体（`DiT-2Cond-XS/2`），零代码改动
- 只改深度（12→8），宽度不变 → **干净的单变量**：直接回答"深度是不是过度配置"
- 50k 步 ~1.8h（M/2 需要 3.35h），**一次探针比 M/2 省 1.5 小时**
- 过拟合信号（gap 开始发散）在 v11 上是 ~50–75k 出现，50k 足够看出苗头

**判据**：XS/2 @50k 的 strict 与 S/2 @50k 配对检验是否显著差异。
- 不显著 → 深度确实过度配置，floor 更低，继续往 P2/P3 缩
- 显著下降 → floor 在 depth 8–12 之间，取 depth 10 收尾

---

## 9. 一条纪律

**不要在饱和的指标上做容量决策。**
"strict 对容量不敏感"既可能是"容量够了"，也可能是"指标看不出差别"。
在补上 LPIPS（或人工看图）之前，缩容量的收益无法与"静默丢质量"区分开。
这与 doc 59 的教训同源：**ssim 只能看趋势，不能作为"是否成型"的判据。**
