## 3. CPU eval infra（当前主任务）

**目标**：eval 全部挪到 CPU 并行于训练，在 2.5k 步间隙内出 `eval_auto_ctrl_*.json`
供早停读；同时把 GPU 上的 eval 尖峰（~2G）让给训练。

### 3.1 预算

- 窗口：v9c 2.80 steps/s × 2500 = **14.9 min**
- 协议锁定不可动：clean_v8 eval n=100 双臂（ctrl 带 skel / base 纯 main）、
  Heun 50 步（100 NFE）、CFG 0.7 → ctrl 100 采样 + base 100 采样 + ~200 VAE decode + 指标
- FLOPs 预算：ctrl ≈285 + base ≈145 + decode ≈120 + 指标 ≈10 → **~560 TFLOPs**
- 硬件：2×EPYC 7542（64C/128T，每 socket 8 CCX×4C，AVX2，无 AVX512-BF16/AMX），
  单 socket fp32 峰值 ~2.95 TFLOPS；251G RAM；训练占 GPU + 少量 CPU

### 3.2 已完成

1. `inference.py` CPU 化：autocast/empty_cache 设备无关化（已同步远程）
2. **`src/eval/cpu_sampler.py` 专用采样器**（本地，待同步）：
   fp32 无 autocast / **Heun 逐 stage**（实测比 heun_batch 快 **39%**：0.728 vs 1.195 s/NFE
   —— heun_batch 每步 6B 行只为摊 GPU launch，CPU 纯亏）/ CFG 拼批（forward_with_cfg
   内部 cat 2B 行，GEMM M 大）/ 预分配 / t 网格+shift 逐行复刻 FlowMatching，数学严格等价
3. 16 样本实测（32 线程单 socket，batch16）：ctrl 133.5s + base 52.0s + decode 8.8s
   → **顺序全量 ≈ 22.1 min，超窗口 7 分钟** ✗

### 3.3 瓶颈分析（profile 数据，`tools/diag/profile_cpu2.py`，清场后）

核心异常：**整体只有 0.34 TFLOPS = 单 socket 峰值的 11%**。逐层定位：

| 测量 | 结果 | 结论 |
|---|---|---|
| 纯 GEMM 4096³ | 1.65 TFLOPS（57% 峰值） | BLAS 底子尚可（MKL-on-Zen2 的正常水平） |
| **实模型形状 GEMM (K=384)** | **0.59 TFLOPS**（square 的 36%） | K 小有效，但不是主因 |
| **模型内 GEMM** | **0.056 TFLOPS —— 比同形状独立基准慢 10×** | ← 主因之一，最反常 |
| attention（SDPA flash-CPU） | bmm 406ms + sdpa 135ms ≈ 540ms/forward（24% 时间，~3% FLOPs） | ← 主因之二 |
| elementwise（mul/add/copy/cat/pow/silu） | ≈1280ms ≈ 与 GEMM 相当 | eager 未融合，编译器可消 |

**独立 GEMM 快 10× 的假说**：独立基准反复复用同一输出缓冲（缓存热）；
模型内每次 forward 几十个 ~36MB 大张量分配 → glibc mmap/munmap + 4KB 页错误风暴。
（对照：v9c 训练同 GPU 跑 batch192 毫无压力——问题纯 CPU 侧。）

已写好**未跑**的决定性实验（`tools/diag/profile_cpu3.py`，网络中断打断）：
- T1：`MALLOC_MMAP_THRESHOLD_`/`MALLOC_TRIM_THRESHOLD_` 调高 + 查 THP 状态 → 验证分配 churn
- T2：`attn_impl eager vs sdpa` → 验证 flash-CPU 路径问题
- T3：`mm fresh vs out= 预分配` → 直接量化分配开销占比

### 3.4 候选优化组合（按预期收益）

| # | 方案 | 依据 | 预期 |
|---|---|---|---|
| 1 | 分配路径修复（env 变量或 THP；极端情况下专用前向 + out= 预分配） | T1/T3 待验 | 2-5× |
| 2 | CPU 上 attention 换 eager matmul+softmax（弃 flash-CPU） | T2 待验 | 1.2-1.4× |
| 3 | 双 socket 双进程臂并行（ctrl@socket1 + base@socket0，taskset 绑定） | 臂比 133:52 | wall=1.6× |
| 4 | skel/gt PNG 跨 eval 硬链接缓存（compute_metrics 的 skel_iou 是 pred-vs-GT，不读 skel.png——纯可视化开销） | 省每步 100 decode | ~1 min |
| 5 | torch.compile CPU | 实测 0.97×（污染数据，需干净重测） | 低，可选 |
| 6 | (Plan B) int8 oneDNN | 2-4× 但破坏 GPU 协议可比性 | 不推荐 |

组合 1+2+3+4 预期 22 min → **~6-9 min**，舒适进窗口。
