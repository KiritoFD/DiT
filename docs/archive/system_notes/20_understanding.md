# 20 · 理解与反思：演进过程、当前实现与下一步

> 这篇是我（AI 助手）对整个项目演进过程和当前实现的理解综合。
> 数据事实来自实测（各 daemon log / eval json / 全量扫描），
> 判断来自 6+ 轮去噪看图迭代和 3 次 eval 口径修正。

## 1. 项目的核心矛盾与解法

这个项目本质上在解决一个问题：

> **给定书家和字，生成该书写者风格的书法字。**

条件信息分三层：
```
L1: 书家 ID（风格层——笔法/结构偏好）        → 预训练解决
L2: 字 ID（内容层——写什么字）               → 预训练解决
L3: 实例层（这一次具体怎么写——骨架/笔画布局）→ ControlNet 解决
```

**核心发现：L1+L2 的信息上限是 SSIM≈0.56（同条件真迹互比）。
要突破到 0.72+ 必须注入 L3 实例条件。** 这个结论不是猜测，
而是被四组独立测量验证的（同写本互比 0.563、1-NN 检索 0.583、
模型 seen 0.5475≈上限 96%、ControlNet 0.80 验证 L3 可行）。

## 2. 演进过程中的关键转折点

### 转折 1: pixel → latent（+0.04）
像素空间 DDPM → VAE latent + flow matching。
在统一口径下这是第一个有效提升。

### 转折 2: 结构损失 → ControlNet 注入（方向性转折）
s6 实验证明把结构信息混入扩散损失**有害**（0.731→0.330）。
正确做法：扩散模型只管生成，结构约束全部交给外部注入
（ControlNet / 骨架条件）。这个决策奠定了后续所有架构。

### 转折 3: mid-clean 增广 → 去增广保真实
增广 11.9 万张没跑赢原始数据（0.5222 vs 0.5204 同期）——
增广不增加信息量。mid_common 去掉增广保留真实，
为 v8 清洗版数据铺路。

### 转折 4: v2 架构（RMSNorm + SwiGLU + QK-norm + RoPE）
同口径 +0.013，训练步数减半即超越——**架构是除数据外最大杠杆**。
SwiGLU 参数量等效但激活显存翻倍 → batch 从 240 降到 192。

### 转折 5: 3px → 1px 骨架
1px 保留笔画中心线，信号更精确：同期 SSIM 高 +0.009，
SkelIoU 高 0.011。配合 max_steps 100k，1px 有充足预算收敛。

## 3. 当前实现的真实状态

### 做对了的
- **条件域隔离**：预训练只管 L1+L2，ControlNet 只管 L3——职责清晰
- **数据清洗 v7**：21,022 张图去噪/切条/极性归一，0 错误
- **eval 口径**：严格凸包 + 中位数 + 分书体，彻底消除跨口径不可比
- **injections 存盘修复**：根除 ControlNet 最致命的实现 bug
- **universal daemon**：eval 指标全自动，不再有 daemon 缺失盲区

### 还不够的
- ** fame-ctrl（0.8045）训练数据含 1.7% 污染**：896 张误翻图在
  训练时未被修复——影响小但不为零；v8b 已用净数据
- **1px ctrl 在 50k 时 SSIM 0.7974 仍在涨**：100k 上限可能仍有空间
- **零样本 SSIM 只有 0.52**：骨架跟随正确但风格≠具体 GT 写本
  ——这个任务定义下是正常行为，不是缺陷
- **gradio 前端是只读的**：不能在线调整书家混合/风格插值
- **skel_bank 未同步清洗**：部分条目基于清洗前骨架

## 4. 我对"什么在起作用"的排序

| 杠杆 | ΔSSIM | 成本 |
|---|---|---|
| 数据干净（去反色/噪点/黑条） | 基础前提 | 低 |
| 换用大而真实的数据集（top6→fame） | +0.087 | 中 |
| 架构升级（v2） | +0.013 | 零成本（已做） |
| 1px vs 3px 骨架 | +0.009 | 零成本 |
| DINO 字符嵌入 | +0.02 | 零成本（已做） |
| **实例级条件（骨架/字形）** | **+0.30** | ControlNet 训练 |
| char→骨架小网络（NLP 先验） | 预计 +0.1-0.2（零样本场景） | 待做 |

**结论：数据质量和实例条件是仅有的两个大杠杆。**
模型容量（S→WS→XL）和增广数据已证明不是瓶颈。
