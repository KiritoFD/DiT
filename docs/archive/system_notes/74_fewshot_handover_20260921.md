## 1. 实验目标与判据

**问题**：模型的风格条件够不够"装下"一个全新书家？
- v13 base = 45 书家 × 1 个 128 维**冻结**向量；v15a = 87 个 (书家×书体) pair ×
  **K=4 个子风格 token × 384 维 = 1536 维/行**（DINO K-Means 质心初始化）。
- few-shot 做法：给 v15a@150k 的表**新增 1 行（第 88 行, 1536 维）**，
  **冻结全部主干，只训这一行**，用新书家的 50 张图。
- **判据**：
  1. fewshot eval ssim（n=100 留出集，cfg=0.7）显著高于"不训练"的 baseline；
  2. Diff loss 从 ~1.6 降到明显低于 baseline 水平并**趋平**（v13 版趟平在 1.05，
     全量训练的书家在 0.24–0.31 —— 这是参照系）。
- **结论预设**：v13 (K=10, 128 参数) 已实测**失败**（loss 趟平 1.05、eval ±0.02 噪声）。
  v15 的 1536 维是关键未测项。

## 3. 管线：数据怎么准备、模型怎么训

参考脚本（都在 `_sync_work/`，旧主题已跑通一遍）：
`prepare_fs50.py`（合并/同步 id/出配置）→ `resize_fs_v15.py`（统一 256）→
`prepare_fs_v15.py`（v15 的 88-pair 词表 + 配置）。编码 latent 的命令**没有落盘**，
需要按 §5 Step 4 现写（10 行 torch，模式抄 `_sync_work/_build_clean_latents.py`）。

**标准流程**（每个新书家 `<cal>`，书体 `<sc>`）：
1. 从 `wild_extract/<书家>-<书体>/` 选 **50 张训练 + 100 张评测**，
   **按"字"划分：eval 的字与 train 的字绝不重叠**（否则 eval 是 seen，不是泛化）。
2. 写 `assets/fs50_<cal>_train.csv / _eval.csv`，列格式照抄
   `assets/fs50_沈周_train.csv`：`calligrapher_id=9999`（新书家原始 id）、
   `script_id` 用 50k 里该书体的 id（楷 0 / 行 3 / 隶 4）、
   `std_path` 借用 50k 里**同一个字**的 std 骨架图（`data/50k/std/<6位id>.png`，
   用 character 在 `train_50k_v2.csv` 里反查；同字多张任选其一）。
3. 编码 **img latent** → `data/50k/shards_fs50_<cal>/shard_00000.npz`
   （键：`latents (N,4,32,32) fp16` + `img_ids (N,) 字符串`；VAE 用
   `data/pretrained/sd-vae-ft-ema`，模式抄 `_sync_work/_build_clean_latents.py`）。
4. 编码 **skel latent** → `data/50k/shards_fs50_<cal>_std/`（对每行的 `std_path`
   图做同样的 VAE encode，img_id 用**同一个键**）。
   ⚠ 这一步旧管线**没做**，是 §4-④ 的 bug 来源，必须补。
5. resize 原图到 256 → `data/50k/fs50_imgs_<cal>/`，CSV `image_path` 指向副本
   （`resize_fs_v15.py` 干的事）。
6. 运行 `_sync_work/prepare_fs_v15.py`（改 `CALS` 列表）：生成
   `assets/callig_script_id_map_fs15_<cal>.json`（88-pair 词表，新 pair = 9999:<sid>）
   和 `src/train/configs/v15_fs_<cal>.json`。
7. 训练：
   ```
   tmux new-session -d -s v15fs 'bash _sync_work/launch_fs_v15.sh 2>&1 | tee logs/_v15fsN.log'
   ```
   `launch_fs_v15.sh` 里 `for c in 伊秉绶 沈周 徐渭 宋高宗` 改成新主题列表；
   每个书家先 `--eval-only` 测 baseline，再
   `--resume-full <v15a@150k ckpt> --train-only-new-callig --init-new-callig mean_scaled`。
   v15a ckpt：`assets/results/v15a_multistyle_k4/20260919-223715-*/checkpoints/0150000.pt`。

## 4. 问题清单（5 个；①已修，②③④必须先修再跑，⑤是背景结论）

**① `--train-only-new-callig` 的 mask bug（已修，2026-09-21 00:30 部署）**
`src/train/train.py:793-835`。旧代码写死"表末行 = CFG null 行"→ 可训范围
`[_n_old, _n_all-1)`。v13 的 LabelEmbedder 表确实是 N+1 行含 null；但 v15 的
`MultiStyleEmbedder` 表是 N 行**不含 null**（null_embed 是独立参数）→ v15_fs
新行(=第 87 行)恰好被排除 → **`[87:87) -> 0 参数`，训练完全空转**（首轮 4 书家
150100/150200 的 eval 与 baseline 逐位相同）。已改为按 `isinstance(..., MultiStyleEmbedder)`
分支取 `_n_new_end`，备份在 `src/train/train.py.bak_20260920`。
**验证方法**：起训后日志必须出现 `[87:88) -> 1536 参数`，且 Diff 必须动。

**② LR/warmup/步数**：原配置 `max_steps=150200`（只训 200 步）+ `warmup_steps=3000`
→ LR 永远爬不起来（实际 ≈6.7e-6）。已改 warmup=100。步数给到了 +50k，
但**别信"步数够就行"**——盯 Diff 曲线，不动就调 lr（batch 放大要按线性缩放调 lr）。

**③ g（骨架条件）错位 —— 静默、最危险、必须先修**
`fs50_*_train/eval.csv` 的 `img_id = 0..149`（`prepare_fs50.py: combine()` 重新编号），
而 config 的 `skel_latent_shards_dir = data/50k/shards_std`（52,457 条，键=50k 的 img_id）。
`0..149` **全部命中** shards_std 的前 150 个 50k 图 → 训练和评测用的 g 是
**无关字的骨架**（50k 000000–000149 = 智永/颜真卿等人的字），不报错、指标照出。
修法（二选一，推荐 a）：
- a) 每个 `<cal>` 把 `std_path` 指到的 std 图 encode 成
  `data/50k/shards_fs50_<cal>_std/`（键=img_id 同名），config 的
  `skel_latent_shards_dir` 指过去；
- b) 干脆让 fs 行的 `img_id` 直接**沿用所借 std 图的 50k id**（如 032217），
  则 shards_std 天然对上；但 img latent shard 的键必须用同一套 id
  （且这些 id 与 50k 训练集重叠没关系，目录是独立的）。
⚠ 这也意味着**此前所有 few-shot 数字（baseline 和训练后）都带病**，
只能看相对趋势，绝对值作废。

**④ 数据质量（背景极性）**：见 §2.1。黑底主题**不能直接用**：
模型白底训练，黑底 GT 使 eval ssim 天花板 ≈0.2-0.3、Diff 卡 ~1.37（lr 1e-3/3e-3 都试过）。
要用黑底文件夹（B 组）必须先极性矫正：检测 `ink<128 占比 > 0.5` → 整图反相 →
必要时二值化/去灰边，使灰度统计落到 50k 白底图的域（参考 50k 图：ink≈0.04-0.25，
gray_mean>150，near_white>0）。矫正后**先肉眼看几张**再入库。
⚠ **这条判据本身是错的，见 ⑧′/⑨′**：按"全图 ink 占比"整夹判定会把绢本灰底
（宋高宗·楷：底≈130 但墨占 60%）误判成黑底并整夹反相；实测 150 张里错了 109 张。
必须**逐图**用贴边底色判极性，并且**二值化**才是 50k 的口径。

**⑤ v13 版（K=10）的结论（背景，不需要重跑）**：
正确实现（128 参数可训），Diff 1.33→~1.05 后**趟平 1800 步不动**，
fewshot eval ±0.02 噪声、个别下降（10 张图过拟合）。
→ **冻结主干 + 128 维单向量学不会新书家**。这就是 v15 (1536 维) 的动机。
⚠ **【2026-09-21 白天改口】这条结论目前不被任何干净实验支持**：`v13_fs*.json` /
`v13_fs50*.json` 同样是 `skel_latent_shards_dir=data/50k/shards_std`（中 ③）、
`num_calligraphers=46` vs 预训练表 45 行（中 ③′：resume 时整张已训好的表被形状剔除）、
`w_repa=0.03`（中 ⑥′）、`weight_decay=0.02`（中 ⑤′）。
"趟平 1.05"完全可能是"条件错位 + 表没加载 + WD 缩表"的合力，而不是容量问题。
要下这个结论必须在修好的管线上重跑 v13（`--init-new-callig row_pt` 对 v13 同样可用）。

### ③′–⑨′【2026-09-21 白天追加】同类静默错误，四条

**③′ `--resume-full` 把已训好的风格表整张丢掉（最致命）** —— 表从 87 行扩到 88 行后，
ckpt 的 `(87,1536)` 与模型的 `(88,1536)` 形状不符，被 `drop_shape_mismatched` 当"新模块"
剔除（日志：`1 个键形状不匹配, 已剔除: ['y_callig_embedder.embedding_table.weight']`）。
于是 87 行用的是 `multistyle_k4_pretrained.pt` 里的 **step 0 K-Means 初始质心**，
而主干是 150k 的 —— **150k 的主干读 0 步的表**。
修法：train.py 里对这张表做"前 n 行搬入 + 新增行保留 init"的扩行加载。
验证：日志出现 `[resume-full] 风格表扩行: ckpt (87, 1536) -> 模型 (88, 1536)`。

**⑤′ AdamW 的 weight decay 绕过 grad hook** —— `--train-only-new-callig` 用 hook 把旧行
**梯度**清零，但 AdamW 的解耦 WD 是 `p -= lr·wd·p`，不走梯度 → 87 行已训好的表被逐步缩小
（lr 3e-3 / wd 0.1 → 每步 ×0.9997，2000 步只剩 0.55）。表现就是"越训越差"。
修法：few-shot 下 train.py 强制 `weight_decay=0`（带 warning）。

**⑥′ REPA 的 DINO 缓存同样按 img_id 查表** —— `repa_cache_dir=data/dino_cache/50k_v1`
(n=51036) 与 0..149 撞号 → 新书家的图拿到的是**别的图**的 teacher 特征。
few-shot 里 REPA 只是 w=0.03 的辅助项，直接 `w_repa=0` 最干净。

**⑦′ 号段隔离 + 内容自校验（防 ③ 复发）** —— few-shot 的 `img_id` 改用
`900000 + 主题序号*1000 + i`；每个 latent npz 额外写 `names`(源图名)，
`latent_dataset.py` / `inference.py` 加载时逐行比对 CSV，对不上直接 `ValueError`
（原来只有"找不到→g=ZERO"的比例告警，而号段撞车时**根本不会"找不到"**）。
shard 无 names 且覆盖 id 数 ≫ 数据集行数时打 `[skel-guard]` 警告。

**⑧′ 极性逐图判、用贴边底色** —— `border8 = median(图框 8px)`；`border8 < 128` 才反相；
落在 128±12 的判不出 → **丢掉不猜**（宋高宗-楷 488 张里 327 张死在这条 + ⑨′，主题弃用）。

**⑨′ 50k 目标分布是严格二值的** —— 实测 50k 训练图像素直方图：
**80.7% 恰为 255、19.1% 落在 0-10、中间几乎为空**。wild 扫描件是灰底连续调
（背景 170-246，各主题还不一样）。不二值化 = 让模型拟合它从没见过的目标分布，
Diff 下界被底色钉死且跨主题不可比。修法：`build_fs_topic.py` 里 Otsu 二值化
（之后 沈周-行 latent std=1.059 / 50k=1.119，同口径）。

**⑩′ 两条老坑仍然有效**：`--eval-only` 基线走 ckpt 的 ema、`use_ema=false` 的训练跑走 raw
→ 对比前必须对齐（few-shot 全程 `use_ema=false`）；CSV 的 `old_50k_id` 是
`extract_img_id` 的**回退键**，填了 50k 行号等于埋雷 → 一律留空。

**⑫′ 换数据重跑要换 results_dir** —— `in_mem_eval` 按 `(step,set)` 在
`results_dir/eval_stdskel_summary.csv` 里去重。同名目录重跑时**每一步的评测都被跳过**，
日志只留一行 `[in-mem-eval] step 152000 done in 0s:`，跑完一个 eval 都没有（实测踩过一次，
傅山-行 白跑 2000 步）。已在 `run_fs6.sh` 里给结果目录加时间戳，并让跳过时打显式警告。
**⑪′ v15a 的"1536 维"要打折** —— 4 个 style token 在进 adaLN 前被 **mean pooling**
（`src/model/dit.py:1202` `return style_tokens.mean(dim=1)`），所以每行**有效容量 384 维**。
v15a 相对 v13 的真实差别是 *384 维 vs 128 维* + *可训 vs 冻结*，不是 12 倍容量。
K=4 的作用是**初始化时把风格模态分开**（防塌缩），不是推理时的额外通道。

## 8. 本轮实测结果（2026-09-21 02:35，管线修好之后）

口径统一：v15a@150k **raw** 权重、cfg=0.7、50 步 heun、n=100 留出字（与训练 50 字按字互斥）。

### 8.1 不训练 baseline —— 新行"怎么写"就有差别

| 主题 | A `mean_scaled` | B `row_pt`(零梯度直写) | Δssim | 配对 t | B 更好的字 |
|---|---|---|---|---|---|
| 沈周-行 | 0.5042 | 0.5190 | +0.0147 | +5.70 | 79/100 |
| 伊秉绶-行 | 0.4989 | 0.5089 | +0.0100 | +5.40 | 76/100 |
| 伊秉绶-隶 | 0.4364 | 0.4531 | +0.0167 | +7.00 | 80/100 |
| 傅山-行 | 0.4723 | 0.4785 | +0.0063 | +5.47 | 76/100 |
| 徐渭-行 | 0.4860 | 0.4906 | +0.0046 | +3.36 | 65/100 |

**5/5 主题一致**。两臂是配对观测（同批字、同噪声 seed=0），所以 +0.01 量级也显著；
只看两个均值相减会误判成噪声。

### 8.2 可直写性的**上界对照** —— 拿已训过的 米芾-行 当尺子

| 臂 | 新行是什么 | ssim |
|---|---|---|
| S2 | 模型自己训出来的那一行（pair 35，见过 2118 张） | **0.6342** |
| S1 | 用该字 50 张图的 DINO 质心**手写**进新行（零梯度） | 0.5229 |
| S1b | 87 行均值（下界） | 0.5107 |

→ 一个真正训好的行比"均值行"高 **+0.123**，而零梯度直写只追回 **+0.012（约 10%）**。
也就是说：**表示空间不是"随便写进去就能用"的** —— 行的数值语义是主干在 150k 步里
和它一起协同适应出来的，外部按特征构造的向量只能提供很粗的起点。
（S2 见过对照字所属书家的全部样本，偏乐观，所以 +0.123 是上界、10% 是下估。）

### 8.3 梯度还有多少增量

**lr 扫描（沈周-行，1000 步，起点 row_pt=0.5190 / mean=0.5042）**

| lr | 起点 | 峰值 ssim | Diff 首→末 |
|---|---|---|---|
| 1e-4 | row_pt / mean | 0.5398 / 0.5383 | 0.456→0.360 |
| 3e-4 | row_pt / mean | 0.5505 / 0.5505 | 0.441→0.353 |
| **1e-3** | row_pt / mean | **0.5532 / 0.5533** | 0.408→0.352 |
| 3e-3 | row_pt | 0.5555 | 0.380→0.352 |
| 1e-3 @3000 步 | row_pt | 0.5539（1000 步后回落到 0.5526） | — |

- 两个起点在 lr 1e-3 下**并轨**（0.5532 vs 0.5533）：lr 够用时 init 就不重要了。
- **有明确甜点区**：lr 1e-3~3e-3、约 1000 步；再往上或再往长只是平/微降，
  没有出现 09-20 报的"越训越差"。

**铺到全部主题（lr 1e-3，2000 步，起点 row_pt；数据为去麻点后的最终版）**

| 主题 | baseline(直写) | 训练后峰值 | Δ | Diff 首→末 | lpips |
|---|---|---|---|---|---|
| 沈周-行 | 0.5190 | **0.5571**（lr 3e-3@1000 步可到 0.5555） | **+0.0381** | 0.398→0.343 | 0.4031→0.3803 |
| 徐渭-行 | 0.4906 | 0.5133 | +0.0227 | 0.454→0.397 | 0.4313→0.4246 |
| 伊秉绶-行 | 0.5089 | 0.5264 | +0.0175 | 0.351→0.292 | 0.4159→0.4073 |
| 傅山-行 | 0.4785 | 0.4886 | +0.0101 | 0.493→0.424 | 0.4164→0.4171 |
| 伊秉绶-隶 | 0.4531 | 0.4547 | +0.0016 | 0.412→0.339 | 0.4480→0.4374 |

- **5 个主题里 4 个训练有增量**（+0.010 ~ +0.034），全部同时把 Diff 压下去 0.06~0.09。
- 唯一没涨的是 **伊秉绶-隶**：它是**拓片**（反相后成片底噪，墨占比 p90 高到 0.393，
  去麻点也救不了，因为噪点连成了大片）。→ 介质噪声是这一格失败的原因，
  不是"风格容量"的问题：Diff 从 0.412 降到 0.341（模型确实拟合了训练图），
  但留出字的 ssim 不动 = 那 50 张学到的东西不迁移。
- 傅山-行 肉眼核对（`vs_傅山-行.png`）：直写版已经很"傅山"（浓墨粗笔），
  训练后部分字更贴、但 亂/勝/協 几字结构反而崩了 —— 与"只有 +0.010"一致，
  是 50 张过拟合的形态。

### 8.7 数据口径的第二次修正（本轮自己踩的坑，记下来）
`_binarize` 的连通域去噪最初标在**亮域**上（`a > thr`），删的是"小块背景"而不是
"小块墨点"，结果傅山-行 ink 0.226→0.228 不降反升。已改成标在墨域上 + `min_area=30`：
傅山-行 ink 0.226→**0.212**、latent std 0.961→**0.998**（50k=1.119），重跑结果见 8.3 末行。
其余 4 个主题的数据几乎不变（ink/latent std 三位小数内一致），它们的数字沿用。


### 8.4 肉眼核对（`_review/posters/fs6runs/vs_沈周-行.png`）
四联：骨架 g | GT 真迹 | 零梯度直写 | 训练 1000 步。
训练后笔画明显变粗变湿、结构与墨色更接近 沈周；直写版偏干偏细。→ ssim 的增益与肉眼一致。

### 8.5 判读（对 §6 的判据表逐条）
1. **B > A 成立**（5/5 主题，配对 t=+3.4~+7.0）→ 行的"写法"有讲究；但见 8.2：
   零梯度直写只值"训好的行"增益的约 10%。
2. **C/D > max(A,B) 成立**（沈周 0.5571 vs 0.5190，+0.038；4/5 主题为正）→ 梯度有真增量。
3. **"Diff 降但 eval 反而降" 未出现** → 09-20 的"没有甜点区 / 越训越差"是 ③′⑤′ 的产物。
   唯一的例外 伊秉绶-隶 是"Diff 降、eval 不涨"（拓片噪声），不是"eval 反而降"。
4. **Diff 从旧管线卡死的 ~1.4 降到 0.29–0.42**，与全量书家的 0.24–0.31 已在同一量级。
5. 最好成绩 沈周-行 **0.5571** —— 距 v15a 全量书家的 strict 平均 **0.568** 只差 **0.011**；
   距"同一书家被真训出来的行"（米芾对照 0.634）还差 0.077。
   而 8.8 说明这 0.077 **不是数据量能解决的**（50→200 张零增益甚至微降）。

> **一句话结论**：在修好管线的 v15a 上，"冻结主干 + 只训 1536 个风格参数"用 50 张图
> **能**把全新书家学到 ssim 0.553 / Diff 0.35，已经很接近全量训出来的书家平均；
> 旧文档 §1 的"结论预设"（学不会）作废。

### 8.8 样本量 scaling（沈周-行，eval 恒为同一批 100 字，train 集嵌套）

`build_fs_topic.py` 支持 `主题@N`（只往 train 侧加字，eval 一字不换，种子只跟基础主题绑定）：

| train 张数 | baseline(零梯度直写) | 训练 2000 步峰值 | Δ vs 自己的 baseline | lpips |
|---|---|---|---|---|
| 50 | 0.5190 | **0.5571** | +0.0381 | 0.3803 |
| 100 | 0.5207 | 0.5545 | +0.0338 | 0.3808 |
| 200 | 0.5190 | 0.5560 | +0.0370 | 0.3798 |

配对检验 50 vs 200：**Δssim = −0.0034（t=−4.30，200 只在 38/100 字上更好）** ——
加数据不但没买到的东西，还略微倒退（batch 固定 50 时，同样 2000 步下每张图被看到的
次数变少）。

→ **50 张已经饱和**。剩下与全量书家（strict 平均 0.568 / 米芾被训出来的行 0.634）的差距
**不是数据量问题**，而是"冻结主干 + 只有一行可训"这个设定本身的容量上限。
下一步该动的是设定（解冻 adaLN/末几层、或给新行更多可训参数），不是去多收图。
