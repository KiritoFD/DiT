# 75. 风格 encoding + 注入：瓶颈定位与改进方案

> 日期：2026-09-22
> 范围：**只谈"书家风格"这条线**——风格怎么编码（style encoding）、怎么进网络（injection）。
> 依据：`docs/HISTORY_REVIEW_2026-09-22.md`、`docs/system/{54,67,68,72,73,74}`、
> v13/v14/v15a/v15b/v15c/v16 的 `eval_stdskel_summary.csv`、`assets/multistyle_k4_*.pt`
> 的行间余弦体检、`logs/_div*.log`（ratio_style）。
> 口径提醒：**strict = 未见 (书家,字) 组合**（泛化）；**seen = 训练内图**（记忆）；
> 全图 SSIM 被 ~90% 白底抬高，**风格/内容质量要看 `ink_ssim` / `ink_iou`**。

---

## 0. 结论速览（TL;DR）

1. **风格条件是全局最弱环，但至今没有一次"干净"的有效性检验。** v14（87 pair 表）、
   v15a（K=4 子风格 token）都"零增益"，可 **v15a 的表是坏的**（DINO K-Means 初始化，
   行间余弦 0.86），所以它的零增益**不能**当作"风格容量无用"的证据。
2. **唯一表质量合格的 v15b_supcon**（SupCon 重训，行间余弦 0.002）才到 70k、
   strict 0.5525 仍在缓升，且**还没在好表上测过 `ratio_style`** → 风格这条线的结论**未定**。
3. **注入侧**：xattn / CrossAttn / 每层 ctx 三条"更强注入"路径，历史上要么 strict≈0、
   要么有 bug 从未跑通。但这**大概率是假阴性**——被"坏表 + CFG 抵消 g-通路 + 冻主干"
   三重混淆掩盖。
4. **真正的大杠杆是数据质量（+0.087）和实例级骨架条件 g（+0.30）**，不是风格 encoding。
   风格线要先把**测量口径**和**混淆因素**清掉，才谈得上判断容量/注入是否有用。

## 1. 风格 encoding 的演进 + 表质量体检（关键）

| 版本 | 风格表示 | 表构建 | **行间余弦**（体检） | strict | ratio_style | 判定 |
|---|---|---|---|---|---|---|
| v13_base | 45 书家 × 128，**冻结** | SupCon(pair→书家) | **0.020**（近正交，好） | 0.5547@155k（seen 0.758） | 1.42–1.48 | 基线 |
| v14 | 87 (书家×书体) × 128，冻结 | 层级 SupCon | 好 | 0.5703 | — | **≈v13 零增益** ✗ |
| v15a | 87 × K4 × 384 = 1536/行 | **DINO + K-Means** | **0.8596（max 0.988）共线，坏表** | 0.5699 | **1.21（反低于 v13）** | 零增益，**但表坏→证据无效** ✗ |
| v15b_supcon | 87 × K4 × 384 | **SupCon（无 DINO 锚定）** | **0.0019（max 0.078）好表** | 0.5525@70k（seen 0.587，升） | **未测** | 进行中，**唯一合格的检验** |
| v13/v16 few-shot | 新行 K=10 / K4 | row_pt / mean | — | 失败（loss 趟平、grad-norm 0.008） | — | 受坏表拖累 ✗ |

### 1.1 决定性发现：DINO 不能用来建风格表
- **DINO CLS 的 pair 质心间余弦 = 0.956** → DINO 编码的是"这是一张书法图"，
  **几乎不区分"谁的风格"**。
- 因此任何**用 DINO 直接初始化或锚定**的风格表都会共线：v15a 的 K-Means 表行间余弦
  **0.8596**（87 个 pair 几乎同一个方向）→ 模型拿到的"风格向量"彼此无法区分 →
  再多 token 容量也是白搭 → strict 零增益、`ratio_style` 反而更差（1.21 < 1.48）。
- **修法（已落地 `tools/pretrain_multistyle_supcon.py`）**：SupCon InfoNCE **只用 pair 标签**
  （同 pair 近 / 异 pair 远），**`--w-anchor 0` 丢掉 DINO 锚定** → 行间余弦压到 **0.0019**。
  这与 v13 单向量 SupCon 表（0.020）同源，是唯一被验证"能区分书家"的构建方式。

### 1.2 v14 的教训：表"结构"不是瓶颈
把 45 书家拆成 87 (书家×书体) pair、仍用单向量/冻结 → strict 与 v13 无显著差异。
说明**"按书体细分"这个结构改动本身不解决问题**；要么加 token 容量（v15）、
要么改注入、要么风格根本不是当前的约束瓶颈。

## 2. 注入机制：现状 + 为什么"看起来都没用"

### 2.1 三条注入路径
| 路径 | 机制 | 代码 | 现状 |
|---|---|---|---|
| **(a) adaLN 全局调制** | K token **mean-pool** 进条件向量 `c=t_emb+Linear(cat[e_callig,glyph_vec])` | `DiT_2Cond.forward` | **唯一稳定 work**；v15a 用它 |
| **(b) CalligStyleCrossAttn** | Q=骨架 token(+2D sincos)，K/V=K 个风格 token，zero-init → "书家化骨架" | `dit.py:388` | v15b 用；**在坏表上测过→证据无效**，好表上待测 |
| **(c) style_ctx_every_layer** | K 风格 token 拼进**每层** xattn context（风格在每个空间位置可寻址） | `dit.py:816+` | v15c；**`ctx_pos_g` 重复注册 bug → 历史从未跑通**；修后 ink_iou 0.1727（最差） |

### 2.2 为什么注入≈0 很可能是**假阴性**（三重混淆）
1. **CFG 结构性抵消**（doc67/68）：`forward_with_cfg` 里 `g2 = cat([g, g])`，两半给同一个 g
   → 任何"只由 g / 风格-token 经骨架"驱动的通路，在 `eps_cond − eps_uncond` 里**精确抵消**。
   用 `cfg=0.7` 评测 → **注入通路被天然绕过** → 测出来 ≈0 是口径问题，不是机制问题。
2. **坏表**（§1.1）：在行间余弦 0.86 的表上，再强的注入也拿不到可区分的风格信号（garbage in）。
3. **冻主干**：styletok / v15 用 `--train-only-style` 冻主干只训风格链 → 渲染器（adaLN/final）
   **没机会学会使用**新风格信号；且 styletok 还把 `glyph_inject_mode` adaln→xattn，
   随机重置了 52 个注入张量 → step0≠ckpt，strict 先崩到 0.094 再爬回，峰值仅 ≈base 后掉头。

> adaLN 之所以"work"，恰恰因为它**直接进 c（全局调制）**，不经过会被 CFG 抵消的 g-通路。

## 3. 瓶颈到底在哪（证据分层）

- **层 1｜指标**：像素 SSIM 已饱和（doc72：12ch 后训练 22.5k 步 strict 只 +0.0009）；
  全图 SSIM 被白底抬高（"升"vs"陞" 全图 0.61 但墨迹框仅 0.36）。**必须用 ink_ssim/ink_iou**。
  换 ink 指标后 **v13 仍 > v15**（ink_iou 0.266 vs 0.17–0.20）→ v13 的优势在**"字写得对不对"（内容/g）**，不在风格。
- **层 2｜风格信噪比**：`ratio_style = inter_callig/intra ≈ 1.18–1.48`（理想 5–10）；
  `inter_callig ≈ inter_char`（换书家 ≈ 换字）→ 风格条件**远未主导**输出。
- **层 3｜内容条件 g 本身带病（用户新洞见）**：**std 骨架 g 用简体、GT 是繁体/异体** →
  g 与 GT **拓扑不同胚** → 模型学会"遇到冲突就忽略 g、靠记忆" → 这**同时**压低 strict 和 ratio_style，
  且让所有"风格注入"实验带病（**g 不可信时，风格注入无从谈起**）。已有 OCR/VLM 工具线
  （`tools/ocr_simp_trad_scan.py`、`vlm_compare_std_gt.py`、`cross_validate_mismatch.py` 等）在量化。
- **层 4｜数据**：one-shot（75% 的 (书家,字) 只有 1 张）+ 仅 45 书家 → 风格×内容解耦信号本就稀薄；
  书家间 strict 与样本数 **r=−0.62**（样本多→风格跨度大→单向量/少 token 装不下）。

> **总判**：风格 encoding 确是短板，但它被 **坏表 + 错配 g + 饱和指标 + CFG 抵消** 四重混淆掩盖。
> **在清掉这些之前，无法判断"风格容量/注入"是否真的有用**——现有全部"零增益"结论都不成立。

## 4. 合理的改进方案（按优先级）

### P0 — 先把"测量与混淆"清掉（否则一切结论无效）
1. **好表 + 补测 ratio_style**：用 `multistyle_k4_supcon.pt`（row-cos 0.002）把 v15b 训到平台，
   并**测 `ratio_style`**（固定书体+字+噪声、只换书家、**cfg=1.0**）。这是风格是否 work 的**唯一干净判据**。
2. **组件结论统一 cfg=1.0 口径**：绕开 §2.2-① 的 CFG 抵消；要评内容/风格注入用**双轴 CFG + `glyph_drop_prob>0`**。
3. **修 g 的简繁错配**（用户 OCR/VLM 线）：先量化错配比例；对错配样本**换成繁体 std 骨架**或剔除。
   g 可信之前，风格注入实验都不可信。
4. **指标切 ink_ssim/ink_iou**（全图 ssim 仅参考）。

### P1 — 风格 encoding 本身（在好表基础上）
5. **K-token 表继续用 SupCon 初始化**，并上**层级 SupCon**（同书家异书体弱正对，保留"这个人"的身份）；
   K 做 2/4/8 扫描，看容量-收益曲线。
6. **表可训 + mean-anchor（λ≈0.01）**（v15 已这么做）防 K 簇重新塌缩；
   **别整表冻结**（v14 零增益）**也别全解冻**（gap 恶化到 0.15）。
7. **风格×内容交互**：`CalligStyleCrossAttn`（书家化骨架）方向对，但必须
   (a) 好表、(b) 不冻主干（或至少解冻 adaLN/final）、(c) cfg=1.0 评测——三者缺一即假阴性。

### P2 — 注入（在 g 可信、表合格之后再比）
8. **adaLN 作基线**；CA / 每层 ctx 作为**增量**，用 cfg=1.0 + 双轴公平比。
9. 若要 ctx-every-layer：先修 `ctx_pos_g` 重复注册 bug，并降 batch（xattn @360 OOM，v12 实测 260@22.6G）。

### P3 — 数据（根本杠杆）
10. 提高每 (书家,字) 样本数 / 书体平衡 / 长尾重采样；few-shot 新书家线（v16）**用 SupCon 好表重跑**
    （此前 few-shot 数字还踩了 `img_id=0..149` 命中错骨架、`--train-only-new-callig` mask bug 训 0 参数两个坑）。

---

## 5. 明确的"不要再做"
- ❌ **不要用 DINO 直接初始化/锚定风格表**（pair 质心 cos 0.956、K-Means 表 0.86，已证伪）。
- ❌ **不要在坏表或 cfg=0.7 口径下判断注入有效性**（假阴性）。
- ❌ **不要再指望缩/扩容量救 strict**（各容量 strict 都卡 0.51–0.57）。
- ❌ **xattn 作为内容注入**在现口径下 ≈0 且 +33% 成本——除非先解决 CFG 抵消，否则别投入。
- ⚠ **g 的简繁错配未清前**，任何"风格注入"实验的结论都要打问号。

---

## 6. 一句话
> 风格 encoding 是短板，但**当前所有"风格无用"的结论都建立在坏表 / 错配 g / 饱和指标 / CFG 抵消之上，不成立**。
> 正确顺序是：**先修 g（简繁）+ 换 ink 指标 + cfg=1.0 口径 + SupCon 好表补测 ratio_style**，
> 再谈 K-token 容量与 CrossAttn 注入。在这之前，风格线的实验都不该下"有效/无效"的定论。
