# 诊断报告 2026-08-28：s19 预训练"效果差"归因 + eval CFG bug 修复

> 范围：s19_midclean_s_flow 预训练 early-stop 的归因、3-top30 → mid-clean
> 历代实验（s12–s19）横向对比、eval 链路 bug。
> 所有结论均有远程 4090 实测数据支撑（见各节"证据"）。

## TL;DR

1. **s19 预训练没有退化，是 eval 口径变了。** s18 基线 ssim 0.5476 的 eval 集
   （eval_strict_top6）里 263 个字**全部**在 s18 训练集出现过；s19 的 mid-clean
   训练集有意剔除了其中 **93 个字（35%）**，这批 zero-shot 字 ssim 只有 0.476，
   把均值从 0.547 拖到 0.522。**在训练见过的字上，s19 = 0.5475 ≈ s18 = 0.5476。**
2. **CFG 口径无问题**：同一 s19 ckpt 实测 cfg 1.7 (0.5229) 优于 cfg 4.0 (0.5174)，
   flow 模型用低 CFG 是对的；不是 s19 数字的解释。
3. **真正的质量瓶颈是 zero-shot 字符泛化 + 密集字崩坏**（结构性，见 §3），
   以及历代实验 **eval 集互不可比**（见 §2 表格）。
4. **eval 链路 bug 已修复**：`sample_latents` 把 `cfg_scale` 塞进 `model_kwargs`，
   sampler 只做 `model(x,t,**kwargs)` 转发 → ControlNet eval 的 base 通道
   TypeError 崩溃、ctrl 通道 CFG 静默失效。修复后 ControlNet 训练已重启恢复。

## 一、eval CFG bug（已修复，src/eval/inference.py）

旧代码：`mk = dict(y_callig=..., y_char=..., cfg_scale=cfg_scale)` 传入
`FlowMatching.ddim_sample_loop`，而后者只做 `model(x, t, **model_kwargs)`：

- **ctrl 通道**（cond≠None）：`ControlNetDiT.forward` 用 `**kwargs` 吞掉
  `cfg_scale` → 所有 in-process eval 实际无 CFG；
- **base 通道**（cond=None）：kwargs 透传 `DiT_2Cond.forward` → TypeError，
  base 图不生成 → pending marker 不写 → CPU daemon 拿不到指标。

修复：`cfg_scale>0` 时包 `model_fn = lambda x,t,**kw:
model.forward_with_cfg(x, t, cfg_scale=cfg_scale, **kw)`；cfg=0 走 plain forward。
已同步 4090 并验证。注意：**修复后 eval 带 CFG，与修复前的指标不可直接对比**。

## 二、历代预训练横向对比（3-top30 → mid-clean）

| 实验 | 数据 | eval 集 | eval_cfg | 步数 | ssim | skelIoU |
|---|---|---|---|---|---|---|
| s15 (WS/2, flow) | 3top30_nobeike | eval500_3top30 (n=500) | 4.0 | 195k | 0.5390 | 0.0345 |
| s17 (S/2, flow) | 3top30_nobeike | eval500_3top30 (n=500) | 4.0 | 165k | 0.5325 | 0.0302 |
| s18 (S/2, flow) | **top6 (10,866 张)** | eval_strict_top6 (n=271) | 4.0 | 43k | **0.5476** | 0.0395 |
| s19 (S/2, flow) | **mid-clean (118,776 张)** | eval_strict_top6 (n=271) | 1.7 | 50k | 0.5222 | 0.0220 |

**问题：四个实验用了两套 eval 集 × 两种 cfg，数字互不可比。**
"3-top30 上 0.53" vs "top6 上 0.5476" vs "mid-clean 上 0.5222" 的落差，
主要是评测口径漂移，不是训练质量变化。

### s19 "退化"的定量拆解（同一 ckpt、同一噪声、同一 eval 集，GPU 实测）

```
cfg 1.7: ALL=0.5229 | seen(178字) ssim=0.5475 | unseen(93字) ssim=0.4759
cfg 4.0: ALL=0.5174 | seen(178字) ssim=0.5426 | unseen(93字) ssim=0.4692
```

- **seen 子集 0.5475 与 s18 全量 0.5476 完全持平**：s18 的 eval 263 字
  全部在它训练集内（0 个 held-out），s19 被剔除 93 字 → 两边 in-domain
  能力相同，s19 还多学了 2,523 字的覆盖。
- unseen 0.476 是 **zero-shot 字符泛化**的代价——这是 mid-clean 扩字符
  覆盖设计（为 ControlNet 通用性服务）的预期交换，不是训练失败。
- cfg 4.0 更差 → s19 的低数字不能用 eval_cfg 解释，现有 cfg=1.7 已最优。

### mid-clean 数据构成（重要背景）

```
train_mid_clean.csv = 23,597 张干净原样本 + 95,179 张增广变体 (aug6.py 仿射/弹性)
字符 2,523 个；原样本每字 min 1 / p25 2 / 中位 5 张
```
增广把每字行数抬到中位 30，但**真实多样性仍是每字中位 5 张**。
s19 共训了 ~119 epoch（对原样本相当于 ~600 遍）。

## 三、绝对指标为什么上不去（SSIM 0.7 / MSE 0.3 的可行性分析）

### 3.1 测量：条件信息量决定了指标上限

模型的条件只有两个标量：`calligrapher_id` + `char_id`（DINO 字形 embedding）。
对该条件不可预测的"这一个 GT 实例"的差异，全部变成指标损失。实测（[0,1] RGB，
mse 为 ×4 口径）：

```
同一 (char, calligrapher) 的两张真实样本:      ssim 0.563  mse 0.762   ← 天然风格内方差
同 char 检索训练集最像的一张 (1-NN oracle):    ssim 0.583  mse 0.605   ← 只用 char_id 的信息上限
s19 seen 子集 (同口径):                        ssim 0.5475 mse ~0.75
构图抖动 (同写本 bbox IoU / 中心偏移 / 缩放差): 0.856 / 1.4px / 5.5%        ← 数据归一化良好, 非因素
VAE 往返底噪 (docs/VAE_NOISE_FLOOR.md):        ssim 0.962  mse*4 0.003   ← 非因素
```

三个结论：

1. **0.7 的 SSIM 超过了条件信息上限**。同一位书家写的同一个字，两张真迹之间
   也只有 0.563——不告诉模型"要像哪一张"，任何确定性生成器的逐实例 SSIM
   都被压在 ~0.56 附近。模型 seen 0.5475 已达到该上限的 96%。
2. **模型还没榨干 char_id 的信息**：1-NN 检索（只用"找出训练集里同字最像的
   一张"）能拿 0.583，高于模型。差距 ~0.035 是真实的模型侧提升空间
   （容量/训练量），但天花板仍是 ~0.58，不是 0.7。
3. **容量不是瓶颈的证据**：s15 用更大的 WS/2 模型，在自己口径上也只到
   0.539 平台。加大模型不改变条件信息量。

### 3.2 目标本身已在一个地方被达成

ControlNet step10000（GT skel 条件，n=100，带 CFG）：
**ctrl SSIM=0.720 / MSE=0.231** —— 恰好就是 0.7/0.3 的目标。
骨架 latent 把"这一个实例"钉死了，指标立刻从 0.55 跳到 0.72。
这证明生成机器（VAE/DiT/flow/ControlNet 注入）是够用的；
**base 冲不上去纯粹因为条件里没有实例信息**。

### 3.3 失败模式分布

密集楷书（20+ 笔，如"聽"）笔画粘连仍是最大的单样本损失来源
（seen/unseen 两个子集都受影响）；简单字已接近条件上限。

### 3.4 要冲 0.7/0.3，按性价比排序的路径

1. **保持 ControlNet 路线为主航道**：它是唯一已实测达标（0.72/0.231）的路径。
   推理时骨架来自用户输入，天然就是实例级条件。
2. **base 模型想单独接近目标 → 把标准字形 g 用起来**：当前 2cond eval 完全
   不喂 g，训练时 `cond_drop_which_glyph_prob=0.75` 又把 75% 的 g 丢掉。
   印刷体模板能钉死结构（残差只剩风格形变），是唯一不依赖 GT 的实例级
   条件源。建议做 3cond 版本（callig+char+g，eval 喂 g）并实测。
3. **榨干 char_id 的 0.035**：加容量/步数把 seen 从 0.547 推向检索上限
   0.583——值得做但量级小。
4. **修评测口径**：如果业务是"给定书家和字，生成一张合理的字"，
   逐实例 SSIM 本身是错配的 KPI；应改 best-of-N（多样性感知）或
   FID/LPIPS 类分布指标。逐实例 SSIM≥0.7 只对"有实例条件"的任务成立。
5. **数据**：每字真实样本中位 5 张。1-NN 上限与 zero-shot 泛化都随
   真实多样性增长；增广（95k 张）对指标上限无贡献。

## 五、建议

1. **评测协议统一**（最重要）：任何跨实验对比必须锁定 (eval 集, cfg, n)。
   建议：预训练指标固定按 **seen / unseen 两个子集分别报告**；
   eval 集与训练数据版本绑定（mid_clean 数据配 mid_clean 专用 eval 集，
   增补 93 个 zero-shot 字的对照子集）。
2. **ControlNet eval 同口径**：daemon 指标恢复后，base/ctrl 对比同样按
   seen/unseen 拆分，避免 zero-shot 字污染 Δ 指标。
3. **提升方向**：① 密集字子集单独监控（前导指标）；② 零样本泛化想再提，
   需真实数据多样性（每字 ≥10 张原样本）或更大模型，增广已到收益上限；
   ③ early-stop 判据改 patience≥5 + 最小提升阈值 0.002。
4. skel_iou 对笔画粗细极敏感（base 仅 0.039），只作趋势参考，不进早停判据。
