## 1. 任务定义

| 项 | 定义 |
|---|---|
| 输入 | ① 标准字形骨架 latent `g` (4,32,32) ② 书家 ID ③ 噪声 `ε` |
| 输出 | 书法字图像 256×256（VAE latent 4×32×32） |
| 条件 | `g`（字身份+结构，**开集**）+ `y_callig`（风格，闭集） |
| **无** char ID | `no_char_cond=true` —— 字身份**只**来自 `g` |
| 评测 | **strict** = (script,callig,char) 三元组在训练集**从没出现过**（250 张，真泛化）<br>**seen** = 训练集内的图（20 张，记忆指标） |
| 主指标 | `strict ssim` / `strict LPIPS` / **`ratio_style`** |

**为什么不用 char ID**：离散字 ID 是闭集 —— 没训练过的字写不出来。用标准字形
latent 作条件，只要字体库能渲染这个字，模型就能写（doc 60 §4 记录了这个取舍）。

## 3. 当前最核心的问题：风格可控性

### 3.1 实测数字（doc 68，已修 3 个静默 bug 后重测）

| 指标 | v12 (S/2)@100k | v12_d8@100k | v13_base@155k | 理想 |
|---|---|---|---|---|
| cfg / k | 0.7 / 4 | 0.7 / 3 | **1.0** / 4 | — |
| `intra`（固定条件，变噪声） | 0.1878 | 0.3735 | 0.2086 | 低 |
| `inter_callig`（固定噪声，换书家） | 0.3447 | 0.9267 | 0.2956 | 高 |
| `inter_char`（固定噪声，换字） | 0.3258 | 0.9221 | 0.3446 | **≫** inter_callig |
| **`ratio_style`** = inter/intra | 1.83 | 2.48 | **1.42** | **5–10** |
| `ratio_char` | 1.73 | 2.47 | 1.65 | — |

⚠ **逐书家版本测到 `ratio_style ≈ 1.18`**（`logs/_div2.log`，被
`src/utils/callig_script_map.py` 文档串引用）—— 即**换书家 ≈ 换噪声 = "假风格控制"**。

⚠ **跨 run 比较必须同 cfg/k**：上表三个值口径不同，只能看**区间**（≈1.2–2.5），
不能直接相减。

**两个共性问题**：
1. `ratio_style` 只有 1.2–2.5 —— 条件驱动的输出差异只比噪声驱动大 1.4–2.5 倍，
   **大部分方差是随机噪声，不是条件控制的**
2. `inter_callig ≈ inter_char`（0.345 vs 0.326）—— **换书家和换字造成的差异一样大**，
   而书法任务要求内容 ≫ 风格（字必须认得出来）

### 3.2 根因（doc 72/73 核实结论）

1. **书家条件 = 45 行 × 1 个 128 维冻结向量**（SupCon 预训练，`freeze_callig_table=true`）
   - 苏轼 3131 张图（早期/晚期风格差异极大）压成 1 个固定向量 → strict **0.3485**（最低）
   - 李邕 1168 张、风格统一 → strict **0.6300**（最高）
   - **r(该书家训练样本数, strict) = −0.62** ← 样本越多、风格越杂、单个向量越不够用
2. **75% 的 (书家,字) 对只有 1 张样本** → 条件与目标近一一对应 =
   Gu et al.《On Memorization in Diffusion Models》里"记忆最强开关"
   （唯一标签使记忆率从 0% 跳到 >65%）—— 这也解释了**为什么缩模型没用**：
   问题不在参数量，在条件的信息量。
3. **32/45 书家跨多书体** → 风格与书体纠缠

### 3.3 v14 的结论与 v15 矩阵（当前）

```
v14 三阶段 + fullft 的裁决（2026-09-19）:
  Stage2(冻结 87 表训主干) 160k: strict 0.5703 / gap 0.196  ← 与 v13 base 持平
  Stage3(冻主干只微调表)  162.5k: strict 0.5764 峰值后平台   ← +0.006, 不显著
  fullft(从 60k 全解冻)   160k:  strict 0.5691 / gap 0.195  ← 未超 base, gap 最差
  → 87 表 vs 45 表 strict/seen 无显著差异; 全解冻只会恶化 gap。表"结构"不是瓶颈。

v15 假设: 每 pair K=4 个 token 的**容量**才是瓶颈 → MultiStyleEmbedder
  (DINO K-Means 质心初始化) + 三种注入方式从头训练单变量对照。
  ⚠ 为什么从头: 注入方式变了 resume 不公平 —— adaLN 条件几何断层
  (旧 128 维 callig 几何是纯标签的, 见 10_data §3.4)、冻结主干不会"读"
  新注入通路 (styletok 前车之鉴)、判据不可归因。resume 版 v15 跑了 ~20 分钟
  即停 (日志 logs/v15_series/v15_train_20260919-221005.log 留档)。
```

**判据**（重要）：不是 strict ssim（已饱和），而是 **`ratio_style` 从 1.18 显著上升**；
strict/seen 轨迹与 v13_base（0.5703@155k）/ v14_s2（0.5703@160k）同口径对比为辅。

## 5. 回答三个常见问题

**Q: 为什么 strict 卡在 0.57？**
A: 像素级 ssim 天花板。12ch 后训练的 20k 步里 strict 从 0.5699 到 0.5708
（**+0.0009 / 20k 步**），poster 逐帧几乎不变 —— 模型早就饱和了。
不是过拟合（strict 从未下降），是**任务本身在这个指标上到顶**。

**Q: 为什么 seen 涨到 0.77 而 strict 只有 0.57？**
A: **两个指标定义不同，直接比是苹果比橘子**。seen 是训练集内的 20 张图（记忆指标），
strict 是未见的 (书家,字) 组合（泛化指标）。差距本身含"记忆 vs 泛化"的定义差异。

**Q: 瓶颈到底在哪？**
A: **风格可控性**（`ratio_style ≈ 1.2–2.5`，应为 5–10）+ **书家条件容量**
（45×128 装不下多模态风格）。v14 正在验证 (书家×书体) 87 类方案。
