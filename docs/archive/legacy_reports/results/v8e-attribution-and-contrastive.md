# v8e 成功归因 + 对比微调方案（09-05）

## 1. v8e 成功归因（why 0.7761 > v8c 0.7674）

### 配置差异（唯一两个变量）
| | v8c（对照）| v8e（SOTA）|
|---|---|---|
| w_repa | 0.3 | **0.5** |
| max_steps | 20k | 80k |
| 其余（lr/layers/batch/eval）| 相同 | 相同 |

### 曲线对比
- v8c best：0.7675 @ **12.5k**（lpips 0.1854, base 0.464）
- v8e best：0.7761 @ **22.5k**（lpips 0.1778, base 0.463, skel_iou 0.432）
- v8e 峰值后回退：27.5k→0.7746, 35k→0.7725, 50k→0.766（无早停跑过峰）
- base 崩溃：22.5k 后 0.474→0.42（27.5k）→0.15（72k）

### 归因结论
1. **w_repa 0.5（更强对齐）→ ctrl +0.009、lpips 更优**：REPA 数据增强强度提升直接换 ctrl 质量
2. **峰值时序后移 ~80%**（12.5k→22.5k）：**强 REPA 需要更长训练才达峰**——v8c 的 20k max 可能截断了上升曲线（0.7675 非饱和值）
3. **无早停是唯一缺陷**：best 22.5k 已保存（31 ckpt 全留），但跑了 80k 浪费算力且 base 伤到底。**修好早停后，v8e 配方 = w0.5 + 峰值早停，是最优 REPA 配方**

### 部署建议（未来 REPA 标准）
`w_repa=0.5 + repa_layers 8,11 + max_steps 80000 但 early_stop(patience 5, delta 0.002)`——
预计在 ~25k 早停取出 0.7761，省 55k 步算力。

## 1.5 ⭐ v9 两阶段链（09-05 重构后落地，v8e 配置对齐）

**教训落实**：v8e 峰值 22.5k（监控曲线确认 0.7761@22.5k → 77.5k 回退 0.762）——
**继续跑反而更差**。v9 两阶段链已带正确早停：

| 阶段 | 脚本 | REPA | 早停 |
|---|---|---|---|
| **A base 预训练** | train.py (v9a config) | w_repa=0.1, layers=(8,) 全程挂 | ✅ ssim_lpips, patience 5, min 20000 |
| **B ctrl 后训练** | train_controlnet.py (v9b config) | w_repa_early=0.5, **layers 8,11** (=v8e) | ✅ ctrl.ssim, patience 5, min 10000 |

**A→B 自动衔接**（run_v9_2stage.sh）：A 早停 → 取 best ckpt (eval_auto 最高 ssim) → B 从该 base 起。

**B 段配置 = 完全对齐 v8e 成功配方**（修正：最初误用 v8b 参数）：
- w_repa_early 0.5 (=v8e w_repa) + repa_early_layers "8,11" (多层, 新支持)
- lr 1e-4 (=v8e, 非 3e-4) + batch 128 (非 192) + warmup 200 (非 500)
- max 80000 + early_stop (v8e 本无, 改进)

预期：B 段早停 ~25k 取出 0.7761+ 水平 ctrl SOTA（基于更优 v9a base）。

## 2. 对比微调方案（正确用 DINO 的落地设计）

### 背景
DINO 内容信号 +0.23 被风格 +0.21 淹没（SNR≈1）：
- 同字同书家 cos 0.435 / 同字跨书家 0.226 / 异字 -0.003
- 任何离线预处理（l2/center/pca）都无法同时放大内容 + 压风格
- patch 位置对齐不优于 CLS（同为外观驱动）

### 方案 A（推荐）：离线对比微调 → 冻结词表（低成本、兼容现有架构）

1. **训练数据**：train_fame_clean_v8 的图级对
   - 正对：**同字 + 同书家 不同图**（干净，cos 0.82）
   - 负对：异字（cos 0.60）
2. **模型**：DINO CLS 特征冻结 → 小投影头（384→256, 2-3 层 MLP）→ L2 归一化
3. **损失**：InfoNCE（batch 内正/负对），batch 256-512，数据增强可用 crop/mask
4. **训练**：~20k 步，lr 3e-4，GPU 几小时
5. **产出**：判别字表（35131×256）或 (7026×256) 按字原型后处理
6. **接入**：新表替换 `--char-dino-embeddings`，freeze_char_table=true（架构零改动）

**为什么保留冻结**：s22 证明 51k 数据在线学 35130 表必然过拟合（0.4622）；
离线在 51k 上对比训练产出**判别表**（表在"图级对"上学习，数据利用率高），
再冻结接入 = 扬长避短。

### 方案 B（远期，在线对比损失）
- 字表不冻结，主训练联合 diffusion loss + char 对比损失
- 风险：51k 学 35130 表过拟合（s22 教训）；需大 batch 才有效对比
- 暂不推荐，除非 A 的检索增益不足

### 预期与验证
- 验证指标：新表字级原型检索（从 1.2% → 目标 >20%）、同字跨书家 cos 分离度
- 若检索达 20%+：替换 v8a 表做 v9 预训练，预期 base ssim 提升（char 条件判别性强 → 模型学"字"而非"类形状"）
