# v83-A / v84 系列：std-soft 条件路线实验记录与审计报告

> 记录时间：2026-10-13 · 代码基线：`28f3396`（内容条件模式重构）+ 本文档所在提交
> 结论一句话：**std-soft 字形条件是一条稳定、可用的路线（90k 达 inkIoU 0.2990，全程无白化）；
> 但"开集字符"尚未证明，且此前的 v83-A 是"字表+std"混合模式，条件归因不可分离。**

---

## 一、这一版到底是什么

| 项 | 值 |
|---|---|
| 主干 | `DiT-2Cond-Sp/2`（depth 12, hidden 512, heads 8, patch 2）· 59.9M |
| **内容条件** | **v83-A = 字表 + std 字形（混合，legacy ✗）**；**v84-A = 仅 std 字形 ✓**；**v84-T = 仅字表 ✓** |
| 风格条件 | 书家表(32) + 书体表(16)，**两种模式都保留** ✓（实验 B 证明其有效） |
| std 条件 | 标准字形渲染的 64×64 软掩码（8451 字/3 书体，σ 网格 0.40–1.00，5 个标准 TTF） |
| 关键修复 | `g_tok = enc(g) − enc(0)`（**消除编码器对全零输入的非零响应**，不 detach） |
| VAE | SD-VAE `sf=0.18215, shift=0` · latent 分片 26k 语料 |
| 训练 | batch 288、200k 步（cosine）、C2OT on、REPA w=0.03、ODE γ=0 |
| 初始化 | **从零训练**（0→55k 被中断→`--resume-full` 续至 100k；非 v80/v81 续训 ✓） |

## 四、审计结论（逐项，全部实测）

| 优先级 | 检查项 | 判定 | 证据 |
|---|---|---|---|
| **P0** | **GT 是否进入推理** | ✅ **通过** | 固定 ckpt/g/noise，只换 GT（真迹/纯白/无关书法）⇒ **三次生成逐位一致**（`max|diff|=0`）|
| **P0** | **std-soft 是否真来自 TTF** | ✅ **通过** | 同字(戶)同书体(楷) × **4 书家** × **4 张不同真迹** ⇒ **g 逐位相同**；store 用 5 个标准 TTF |
| **P0** | 训练/评测重叠 | ⚠️ **已披露** | **同源作品 69/187 = 36.9%** ✗；完全同图 **0** ✓ |
| **P0** | 字表是否仍在提供信息 | ⚠️ **是**（v83-A）| `use_char_cond=True` + 字表 `(4691,256)` 可训练 + 结构耦合（关掉会形状失配）|
| **P1** | 模型是否真用 std-soft | ✅ 实验 A | 固定其余，只换字(g) ⇒ 三张生成**两两 `max|diff|=255`** |
| **P1** | ckpt 来源 | ✅ **从零训练** | 首启无 `--resume-full`；55k 后续训 |
| **P1** | 评测缓存/条件映射 | ✅ | `glyph_embedder` 前向钩子 `mean=0.1225>0` + manifest 显式记录 + 逐行对应 ckpt |
| **P1** | 书家风格是否被 TTF 覆盖 | ✅ 实验 B | **同 g** 换书家 ⇒ 墨量差最多 **+0.135（65%）** |

### 推理期字表单变量干预（`tools/audit_char_table_intervention.py`）

|---|---|---|---|---|

⇒ 三点：① 字表确实在贡献笔画细节（inkIoU −17~43%）✓ ② **把字表全零，模型仍写出结构正确的字**（ssim 几乎不变）⇒ **std 条件已能承载字符身份** ✓✓ ③ **"恒定错字"反而 ssim 最高但欠墨** ⇒ 又一次证明 **ssim 会奖励退化输出** ✗（⚠️ 仅 3 样本）

## 六、两种内容条件模式（2026-10-13 重构）

**原则：一个模型只能处在一种内容条件模式，不得共存** ✗（`dit.py` / `train.py` / `model_io.py` 三处硬校验）

| 模式 | 定义 | 参数量 | 用途 |
|---|---|---|---|
| **`table`** | 字条件 = 字表 embedding（`use_char_cond=True, std_soft_cond=False`）| 59.9M | 字表路线基线（与 v68 同族可比）|
| **`std`** | 字条件 = 标准字形软掩码（`use_char_cond=False, std_soft_cond=True`）| **58.6M** | **唯一可宣称开集**的路线（未见字不吃随机表行）|

- 配置：`src/train/configs/v84A_std_cond.json`（std）/ `v84T_table_cond.json`（table）—— 除模式键外**与 v83A 逐位相同** ✓
- 旧 ckpt（混合模式）仍可加载，但会打 **RuntimeWarning** ✓（用于复现旧结果）
- `content_cond=None` = legacy 行为（仅告警，不报错）✓

## 七、诚实的限制（未解决）

1. **开集字符证据薄弱** ✗：unseen-char 仅 **13 张**、inkIoU 0.1586 ⇒ 需要**更大的开集评测集**（含足够多表外字）
2. **v83-A 是混合模式** ✗：字表与 std 并存 ⇒ 本轮所有"std 的贡献"结论都无法与字表分离；**v84-A（std 单模式）才是干净对照**
3. **OCR 判别器尚未训完** ✗（跨作品留出：ep13 Top-1 0.8166 / Macro 0.7824 ✓ 已达验收门槛）⇒ 现在只能说"像不像"，**还不能说"字对不对"**
4. **同源作品披露** ✗：36.9% 的评测 GT 与 DiT 训练集同源；seen 类已按"非同源"定义 ✓，但跨模型比较时必须一并披露
5. **溯源待补** ✗：`std_soft_glyphs_v1/index.csv` 的 `font_path` 指向本地 Windows 路径；`NotoSerifSC-VF.ttf` / `simsunb.ttf` 在 4090 上不存在（store 为本机渲染后拷贝）⇒ 按评审要求需冻结 TTF 哈希（已有 3/5）
6. **实验 C（关掉 y_char）无法事后做** ✗：会改变 `cond_fusion` 输入维度 ⇒ 只能**重训**（v84-T vs v84-A 即此对照）
