## 本轮落地（本地代码，未热更正在跑的任务）

`--train-path latent-std` 启动时选择独立 FM+REPA 目标，要求缓存 4ch latent、软 STD 条件和 Flow Matching。不执行旧骨架、形变、Critic 等目标分支；不支持的混用直接报错。默认 `legacy`，不改变历史配置的目标选择。

公共训练生命周期继续负责条件、一次优化、EMA、checkpoint 和统一评测；本轮不复制整套循环，也不宣称已经拆净所有历史初始化代码。下一轮使用新路径需显式添加该配置项。

每次启动在 run 的 `records/` 写一个独立 UUID 的 `*.identity.json`（独占创建，不覆盖），包含：最终配置、源码 manifest 哈希、训练/评测 CSV、STD bank 文件哈希、VAE 权重与配置哈希、实际加载的模型及 EMA 张量哈希、latent scale/shift、FM 模型时间尺度、样本数量、指标实现哈希。启动哈希有一次性 CPU/磁盘成本，不进入逐步热路径。

原有 checkpoint SHA256 完成清单保持不变；checkpoint 的 args 保存 `run_launch_id` 和 `run_identity_sha256`，连接到对应启动记录。续训创建新身份，不冒充同一次执行。

`*.events.jsonl` 在首步和日志边界记录实际 FM/REPA 值、有效 REPA 权重、梯度连接状态、缓存命中、batch IDs、时间范围和 optimizer/EMA 是否更新。零 loss 本身不等于失效；新路径会对缺失学生特征、缺失监督输入、warmup 后 REPA 脱离梯度图直接报错。

边界：这是抽样执行证据，不是每步完整审计；legacy 其他 loss 尚未逐项认证。源码清单中的缓存目录哈希只覆盖元数据，不证明所有 tensor 文件内容。记录是追加文件，不是防篡改存储；旧 run 不补造身份。

## 验证与待办

已用真实 FlowMatching、小型可微模型和替身 REPA，固定噪声验证新路径与参考目标的 loss/参数梯度逐位一致；验证身份不覆盖、事件可读、旧目标混用拒绝。仅 CPU 小规模边界验证，不代表完整 DiT GPU 长训已验收。

仍待实测：STD 重新 pin 的占比；编译长训稳定性；CPU 指标/PNG/poster 的有界异步队列、异常传播、drain 完成与 DONE 顺序。STD 在启用现有 `--profile-steps` 时增加 `std_bank.select`、`std_bank.pin`、`std_bank.h2d` 三个区间，尚未据此声明收益。未降低评测频率、未少保存任何图。没有证据承诺剩余 2×，也不沿用“只剩 1%”结论。
