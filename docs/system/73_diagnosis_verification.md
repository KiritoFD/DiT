## 1. ⚠ 唯一实质错误：字符数「~5,943」与口径混乱

**实测三种口径**（`assets/train_50k_v2.csv`，50,786 行）：

| 口径 | 唯一值数 | 说明 |
|---|---|---|
| `character`（字符串）| **5,821** | 字面意义上的"不同字" |
| `character_id` | **7,122** | **有 1,307 个字符对应多个 id**（如 `'䟽'` → ids `126, 21204`）✗ |
| `glyph_id` | **9,232** | **有 2,536 个字符对应多个 glyph_id** |

**「5,943」三者都不是** ✗ —— 报告未声明口径

**⚠ 但 `glyph_id` 的"重复"经查是无害的**：
```
'㝡':  glyph_id=27     data/50k/std/000002.png  md5=76e1b7e4bc80
       glyph_id=27     data/50k/std/000003.png  md5=76e1b7e4bc80
       glyph_id=21105  data/50k/std/000004.png  md5=76e1b7e4bc80   ← 不同 id，同一张图
```
**同一个字形被存成了多个文件、配了不同 id** ✓ —— 模型看到的 `g` 是同一张 ✓
**但它把 (书家,字) 对数虚高了** ✗（39,267 vs 35,879）

**⚠ 另有一处更该关注的**：`character_id` 有 **10 例一个 id 对应多个字符**（如 id `3` → `['扃','毳']`）✗ —— 若被当作字符身份使用会串字

### 各口径下的 (书家,字) 对

| 口径 | 对数 | 只 1 张 | 覆盖率 | 未监督 |
|---|---|---|---|---|
| `character_id` | 37,630 | 28,235 (**75.0%**) | 11.74% | **88.3%** |
| `character` 串 | 35,879 | 25,654 (71.5%) | 13.70% | 86.3% |
| `glyph_id` | 39,267 | 30,609 (78.0%) | 9.45% | 90.5% |

**报告用的 `character_id` 口径** ✓ —— 所以它的 75.0% / 88% 是**自洽且正确**的 ✓
**只是"字数"那一项没跟着用同一口径** ✗

## 2. 主结论：核实后**成立**

### 2.1 不是过拟合，是「记忆↔泛化鸿沟」 ✓
- 经典过拟合 = 验证指标**下降**；strict 全程单调微升 ✓ → 严格说没有过拟合 ✓
- 但 seen（训练内图）/ strict（未见组合）**是两个不同定义的指标**，直接比是苹果比橘子 ✓

### 2.2 根因是数据结构（**核实成立**）
- **75% 的 (书家,字) 对只有 1 张** ✓（`character_id` 口径精确匹配）
- **唯一标签 = 记忆最强开关** ✓（Gu et al. 实测：无条件 0% → 唯一标签 >65%）
- **88% 组合无监督** ✓
- **32/45 书家跨多书体**（报告写 33/48，数字错，但"跨书体导致风格与书体纠缠"的论点成立）✓

### 2.3 条件信噪比过低（**核实成立**）
- `ratio_style = 1.83` ✓（理想 5–10）
- `inter_callig 0.345` ≈ `inter_char 0.326` ✓ → 风格过度表达/内容约束偏弱
- 样本两两 SSIM 0.683 > 样本 vs GT 0.586 ✓ → 输出聚在一起、整体偏离 GT

### 2.4 像素指标天花板（**核实成立**）
- 12ch 后训练 22.5k 步，strict 0.5699→0.5708（**+0.0009**）✗
- poster 逐帧几乎不变 ✓

## 3. 12ch 的判断：**核实成立**

| 论断 | 判定 |
|---|---|
| 梯度稀释（等权吃 51% final-layer 梯度，patch_embed aux 2.6×）| ✓ doc54 逐字 |
| 12ch 从头训 80k：strict −0.056 / seen −0.144 | ✓ doc71 逐字 |
| 冗余监督（canny/skel 可由图像算出）| ✓ 论点成立 |
| px60 只有 skel 没有 canny → 只能做 8ch | ✓ doc67 §1.5 |
| **历史 12ch 数字被 CFG bug 污染** | ✓ **doc67 §3.0 —— 这条最重磅** |

**⚠ 第 5 条值得展开**：`factorized_cat` 漏进 drop guard →
**所有 cat 系 run（含 v12_12ch）训练全程零条件 dropout** →
`null_embed` 停在随机初始化 → CFG 的 uncond 半用未训练向量 ✗
**该 bug 2026-09-17 才修** → **此前的 12ch 评测口径不可信** ✓

**⭐ 本次核实新增**：我们自己在 09-17 独立发现并修的 `null_embed` 被静默丢弃问题，
与 doc67 §3.0 是**同一个根因的两个面** ——
- doc67 说的是「训练时 drop 没生效」→ null_embed 没被训练
- 我们说的是「加载时 null_embed 被丢」→ 恢复成随机

**两者叠加**：既没训好、又没存对 ✓ —— 这解释了为什么历史上 12ch/CFG 的结论一直不稳

## 4. xattn 的判断：**核实成立，且优先级判断正确**

**「xattn ≈ 0」不可信，三个污染源** ✓ 全部核实：
1. **CFG 结构性抵消** ✓ —— `g2 = cat([g,g])` 两半同一个 g → 只由 g 驱动的通路对 `eps_cond − eps_uncond` 贡献**精确为 0**
2. **Q 无位置嵌入** ✓ doc67 §2.2
3. **cat drop-guard bug** ✓ doc67 §3.0

**「当前瓶颈是风格/泛化，不是内容注入」** ✓ —— 与 doc72 §4.2 一致
（poster 证明 g 条件有效、字写得对；问题在风格×内容解耦）

## 6. 核实后的最终结论（三条）

1. **「过拟合」需重新定义** ✓ —— 是 one-shot 记忆鸿沟 + 像素指标天花板 + 条件信噪比低，
   **不是容量过拟合**；缩模型已实测不救 strict ✓

2. **12ch 的正确用法是 per-group 加权 + 当辅助监督** ✓，别指望它抬图像 strict；
   且其历史数字被 CFG bug 污染过 ✓

3. **注入机制改动不是当务之急** ✓ —— 该做的第一件是 **callig A/B 决定性实验**
   （固定 `g` + 噪声，只换 `y_callig`），它会区分瓶颈在"数据"还是"条件机制" ✓
