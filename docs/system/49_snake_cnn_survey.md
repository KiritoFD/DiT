# 49. 蛇形 CNN（DSConv / DSCNet）调研：能否用到我们的模型上

日期: 2026-09-12
结论: **不建议引入主路径**；唯一值得试的是 `skel_head` 辅助头 + clDice 损失（低风险）
前置: 47（阶段总结）、48（消融实测）

---

## 1. 蛇形 CNN 是什么

**DSCNet: Dynamic Snake Convolution based on Topological Geometric Constraints for
Tubular Structure Segmentation** — Qi et al., **ICCV 2023**（非 CVPR）。
[arXiv:2307.08388](https://arxiv.org/abs/2307.08388)

**任务**：管状/细长结构的**分割**（血管、道路、视网膜血管）。

论文在三阶段同时增强管状结构感知：

### 1.1 Dynamic Snake Convolution（特征提取）

标准可变形卷积为每个采样点学习**自由偏移**，在细长结构上容易"散开"（偏移点跑到结构外，
采样到背景）。DSConv 给偏移加**连续性约束**：

- 对 K×K 卷积核（典型 9 点），以中心点为起点，向两侧**逐点累积**偏移：
  `offset_i = offset_{i-1} + Δ_i`，其中 `Δ_i` 由一个小卷积预测、经 tanh 约束在 [−1, 1]
- 于是采样点连成一条**蛇形链**，沿着结构的走向贴着走
- 分 **x 轴蛇** 与 **y 轴蛇** 两个方向，组合以适应任意走向的曲线

效果：感受野从"方形窗口"变成"贴合曲线的一维链"，对**细、长、弯**的结构
（笔画中心线正是这类结构）感知更强。

### 1.2 多视角特征融合
在融合阶段从多个视角补充对特征的注意力，保留不同全局形态的信息。

### 1.3 TCLoss（损失约束）
基于**持久同调**（persistent homology）的连续性约束损失，直接惩罚分割结果的
拓扑错误（断裂、伪连接）。

## 2. 我们的架构现状（与判断相关的代码事实）

| 事实 | 值 | 位置 |
|---|---|---|
| 条件 g 输入 | VAE latent `4×32×32` | forward `g` |
| `glyph_embedder` | `Conv2d(4→hidden, k=2, s=2)` + 2×(SiLU + `Conv2d 3×3`) | `dit.py:682-694` |
| **卷积实际运行的分辨率** | **16×16**（降采样后） | `k=2,s=2` → 32→16 |
| g 的 token 化 | flatten → **256 tokens**（16×16 网格） | `dit.py:900` |
| 注入方式 | 输入层 token-add（`glyph_scale`，**实测 0.1896**）+ 12 层 xattn | `dit.py:914, 1008` |
| **`skel_head`** | `Sequential(norm, Linear(hidden → 4))` —— **纯 Linear，无空间卷积** | `dit.py:663-667` |
| `skel_head` 是否启用 | **否**（`skel_head_enabled = w_skel_head > 0`，c41x config 无此项） | `train.py:256` |

## 3. 匹配度分析：为什么收益有限

### 3.1 任务方向是反的

| DSCNet | 我们 |
|---|---|
| 从图像 → **分割/提取** 管状结构 | 从骨架 + 书家 → **生成** 墨迹 |
| 骨架是**预测目标** | 骨架是**已知输入条件** |

蛇形卷积的核心价值是"**更好地感知/提取**细长结构"，而我们的骨架是**现成给定的**，
不需要提取。我们要生成的是笔画的**墨色分布**（宽度、笔锋、浓淡），这不是管状结构分割问题。

### 3.2 分辨率不足 —— 这是硬约束

蛇形采样的优势依赖于**足够高的空间分辨率**（细长结构要占若干像素，采样链才有意义）。
论文的实验在 256×256（DRIVE 视网膜）、1024×1024（道路）等级别。

而我们：
- `glyph_embedder` 的卷积在 **16×16** 网格上（32×32 latent 经 `k=2,s=2` 降采样后）
- 笔画中心线在这个尺度上只有 **1~2 px** 宽

**在 1~2 px 宽的结构上做"蛇形链采样"，退化成普通的 1D 邻居采样，优势基本消失。**

### 3.3 主干是 Transformer，不是 CNN

主干是 DiT（全局自注意力 + RoPE），本来就不是靠局部卷积核提取特征；
DSConv 是 CNN 算子，塞进 Transformer 主干既不自然也会破坏已训练的结构。

### 3.4 一个更根本的问题（蛇形卷积解决不了）

细笔画半宽 **2~3 px**（30 号实测），经 VAE **8×** 下采样后在 latent 里
**不足 0.5 px**。也就是说：**细笔画的信息在 latent 空间本来就被下采样丢掉了**。

这大概率是 `skel_iou` 一直只有 0.35（即使 cfg 修正到 2.0）的结构性原因之一。
**这是分辨率/表示问题，不是特征算子问题** —— 换蛇形卷积无解，换更高分辨率
latent（512×512）或加像素级监督才是对症的。

## 4. 可行的结合点（按推荐度排序）

### A. `skel_head` 改造成蛇形卷积头 —— 唯一真正对口的点 ⭐

`skel_head` 的任务是**预测骨架**（管状结构），与 DSCNet 完全对口。
但当前实现是 `Linear(hidden → 4)` 的 per-token MLP，**完全没有空间卷积**，
所以现在连"能不能利用空间结构"都没试过。

改造思路：
```python
# 现状: norm -> Linear(hidden, 4) -> unpatchify -> (N,1,32,32)
# 改为: norm -> Linear(hidden, hidden) -> reshape (N,16,16,hidden)
#       -> DSConv 块(蛇形卷积, 沿 x/y 两个方向) -> 上采样 2x -> (N,1,32,32)
```

- 分辨率 32×32（比 16×16 好，但仍不高 —— 见 §3.2）
- **低风险**：辅助头，不进入主生成路径；可 zero-init 保证初始无影响
- 前置条件：先验证"骨架辅助头本身是否有益"（`w_skel_head > 0` 跑一次对照），
  **否则就是在一个从未验证过的模块上再叠一个未验证的算子**

### B. 拓扑连续性约束：用 **clDice**，不要用 TCLoss ⭐

如果关心的是"生成笔画**断裂/粘连**"，那么：

| 方案 | 评价 |
|---|---|
| 论文的 **TCLoss**（持久同调） | 实现复杂、计算慢、可微性处理麻烦 —— **不推荐** |
| **clDice**（centerline Dice） | ✅ **强烈推荐作为替代**：基于软骨架化的拓扑敏感损失，**可微、几十行、开销小**，是管状结构分割的事实标准损失 |

clDice 可作为辅助损失加在 `skel_head` 预测上（甚至直接加在生成的骨架/笔画上），
直接惩罚"该连的没连上"。**比引入 DSConv 算子性价比高得多。**

### C. `glyph_embedder` 换 DSConv —— 收益有限，不推荐优先

在 16×16 上做蛇形采样（§3.2），且后续 256 个 token 会进全局 cross-attention
（注意力本身就能建模长程结构关系）。成本（grid_sample 及其 backward）大于收益。

### D. 条件改为高分辨率骨架图 + 蛇形 CNN 编码器 —— 收益更大但改动大

若把条件从"VAE latent 32×32"换成"**原始骨架图 256×256**"，蛇形卷积的价值会显著上升
（高分辨率 + 细长结构 + 需要提取）。但这需要：
- 重新生成/encode 条件数据
- 改 `glyph_embedder` 为下采样编码器
- 重训

**属于大改动，不作为近期项**；若未来要走"高分辨率条件"路线，DSConv 值得列入候选。

## 5. 成本与风险

| 项 | 说明 |
|---|---|
| 实现 DSConv | ~60 行（预测 offset 的小 conv + 沿轴累积 + `grid_sample`/`deform_conv2d`）；仓库无现成算子 |
| 计算 | 可变形卷积的 `grid_sample` backward 较慢；在 16×16×512 上绝对值不大，但会是新的热点 |
| 显存 | 当前训练已 19.6G/24G，新增算子需留余量 |
| 风险 | 改主路径（`glyph_embedder`）会**破坏与现有 ckpt 的兼容**（新增参数 → 48 号已证明这类改动有 resume 陷阱）；改辅助头（`skel_head`）则无此风险 |

---

## 6. 结论与建议

1. **蛇形 CNN 不是我们当前瓶颈的解药。** 任务方向（生成 vs 提取）、分辨率（16×16）、
   主干形态（Transformer）三方面都不匹配。
2. **当前瓶颈更可能是**：评测口径（48 号已修正 cfg=2.0，skel_iou +58%）、
   风格表达、以及 **latent 分辨率不足以表达细笔画**（§3.4）。
3. **若要试蛇形 CNN**：只在 `skel_head` 辅助头上试（A），且**先验证骨架辅助头本身有效**。
4. **更值得先做的**：引入 **clDice** 作为拓扑连续性辅助损失（B）——
   更便宜、更直接地针对"笔画断裂"，且不需要引入新算子。
5. **不要**把它加进 `glyph_embedder` 或主干：收益不确定，且会重蹈 48 号
   "结构改动 → resume 语义不安全"的覆辙。
