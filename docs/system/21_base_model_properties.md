# 21 · 预训练目标：什么样的 base model 对 ControlNet 后训练有用

> 核心论点：**base model 的 SSIM 不是 ControlNet 下游性能的预测指标**。
> 一个 SSIM 0.51 但条件响应灵敏、特征空间丰富的 base，
> 比 SSIM 0.53 但模式坍缩的 base 更适合 ControlNet 后训练。
> 本篇从我们的实测数据推导出 base model 应该优化的性质，
> 并提出对应的评测指标（当前评测体系缺这些）。

## 1. 问题定义

我们当前的预训练目标是：**给定 (书家, 字)，生成最像 GT 的书法字**。
用 SSIM 衡量。

但 ControlNet 后训练的目标是：
**给定 (书家, 字, 骨架)，生成遵循骨架的书法字**。

这两个目标有交集但不等价。SSIM 高的 base 可能在某些
对 ControlNet 重要的性质上反而差。

## 2. 实证：三组 base 的对照诊断

| base | SSIM(自口径) | 数据 | 步数 | 对 ctrl 的贡献 |
|---|---|---|---|---|
| s20 | 0.5294 | mid-common 23,597 真实 | 132.5k | fame-ctrl SSIM 0.8045 |
| s21 | 0.4670 | fame 51,322 | 132.5k | v8b ctrl Δ+0.2211@7.5k |
| s19 | 0.5222 | mid-clean 118,776 | 58.7k | 未直接测（架构不同） |

**关键观察**：s20 和 s21 的 base SSIM 差 0.06，但它们各自的
ControlNet 都能训到 0.79-0.80。**base 的 SSIM 绝对值
不预测 ctrl 的最终性能。**

真正预测 ctrl 性能的是：
1. base 的条件响应度（不同 cond → 不同输出）
2. base 的输出多样性（同一 cond 不同 seed → 有变化但不崩）
3. base 的特征空间与 ctrl encoder 的兼容性

## 3. 好 base model 的五个性质（按 ControlNet 重要性排序）

### 性质 1: 条件响应度（Condition Sensitivity）
**定义**：改变 (书家, 字) 条件时，模型输出是否发生有意义的变化。
**为什么重要**：如果 base 忽略条件，ControlNet 必须从头教模型
"什么是字"——这增加了 ctrl 的学习负担。
**如何测量**：不同条件的输出之间的平均距离 / 同条件不同 seed 的距离。
比值 > 1 = 模型在用条件。

**当前状态**：我们没有测量这个。s20/s21 的 eval 只看 SSIM，
不看条件是否真的被使用了。

### 性质 2: 多样性 / 反模式坍缩（Anti Mode Collapse）
**定义**：同一个条件，不同 seed 是否产生不同的合理输出；
不同条件是否产生明显不同的输出。
**为什么重要**：ControlNet 通过"引导"扩散过程工作。如果 base
已经坍缩到少数模式，ctrl 无法把过程引导到新模式。
**如何测量**：同条件多 seed 的输出方差 + 不同条件的输出分布覆盖。

**当前状态**：未测量。s20 训练用了 4-way dropout
(all=0.05/one=0.30/which_glyph=0.85)，理论上有利多样性，
但没有实际验证。

### 性质 3: 特征空间丰富度（Feature Richness）
**定义**：DiT 中间层特征是否编码了空间结构信息（笔画位置/粗细/方向）。
**为什么重要**：ctrl_encoder 通过读取主模型的中间特征来决定注入什么。
如果中间特征只有"全局风格"没有"空间布局"，ctrl 无法注入位置信息。
**如何测量**：中间层特征做 PCA，看前 K 主成分是否编码了骨架/笔画位置。
或者：用线性探针从中间特征预测骨架 mask。

**当前状态**：未测量。这是我们的评测体系最大的缺口。

### 性质 4: 输出质量底线（Quality Floor）
**定义**：无条件/弱条件生成是否至少"像书法字"——不要求匹配 GT，
但不应该产生非字形噪声。
**为什么重要**：ControlNet 在 base 输出基础上"修改"。如果 base
输出是噪声，ctrl 需要做的工作量太大。
**如何测量**：无条件生成的字形分类器准确率（是否像汉字）。
或者：人眼评估"是字"的比例。

**当前状态**：部分覆盖——eval 的 SSIM 隐含了这一点（SSIM 0.50
意味着输出确实像汉字），但没有显式测量。

### 性质 5: 数据覆盖度（Coverage）
**定义**：模型在 (书家 × 字 × 书体) 空间中的覆盖范围。
**为什么重要**：ControlNet 推理时遇到的 (书家, 字) 组合如果
在训练中完全没见过，base 需要有足够好的泛化来处理。
**如何测量**：模型在 held-out (书家, 字) 组合上的输出质量
（不同于 eval 集——eval 是固定 500 行，这里是整个条件空间）。

**当前状态**：eval_strict 系列部分覆盖（500 行严格凸包样本），
但没有系统性测量整个条件空间的覆盖情况。

## 4. 当前评测体系的缺口

我们当前的评测流程：
```
训练 → 每 2500 步自动 eval → SSIM/MSE/LPIPS/SkelIoU → early stop
```

**缺失的测量**（上面 5 个性质一个都没量测）：
1. 没测条件响应度 → 不知道模型是否真的在用条件
2. 没测多样性 → 不知道是否模式坍缩
3. 没测特征丰富度 → 不知道 ctrl encoder 能读到什么
4. 没测无条件生成质量 → 不知道 base 本身是否合理
5. 没测条件空间覆盖 → 不知道模型在多少 (书家,字) 组合上能工作

## 5. 建议：预训练目标重新定义

### 当前目标（SSIM only）
```
loss = flow_matching_loss(model(x_t, t, cond), target)
eval = SSIM(generate(cond), GT)
early_stop = SSIM 停止提升
```

### 建议增加的评测维度（不改训练 loss，只改 eval）

```
每 2500 步额外测量：
1. CSS (条件敏感度分数): 20 个不同 cond 的输出两两距离 / 同 cond 多 seed 距离
2. Mode coverage: 100 个 cond 中，输出"像字"的比例（粗分类器）
3. Feature richness: 中间层特征对骨架 mask 的线性探针 R²
4. Style consistency: 同书家不同字的输出风格相似度（stroke width 分布等）
```

这些指标不改训练 loss（避免多任务干扰），但给 early stop
和 ckpt 选择提供更全面的依据。

### 建议增加的训练目标（如果愿意改训练代码）

1. **char dropout 加强**：which_glyph=0.85 已经很高了，
   可以试 0.95（几乎完全依赖骨架，让 ctrl 全权负责结构）
2. **辅助骨架预测头**：中间层 → 预测骨架 mask（低权重辅助损失）
   → 迫使特征编码空间信息 → ctrl encoder 能读到更好的特征
3. **风格一致性正则**：同书家不同字的中间层特征距离 ≤ 同书家同字
   不同 seed 的距离 → 鼓励书家风格在特征空间中聚簇

## 6. 实际建议（下一步）

### 短期（不改训练代码）
1. 对现有 s20/s21 base 加测 CSS 和 mode coverage
   （利用已有的 sample_latents 基建，30 分钟可出结果）
2. 如果 CSS 很低 → base 模型的条件嵌入可能有问题 → 优先修条件嵌入
3. 如果 CSS 正常 → base 质量不是瓶颈，专注 ControlNet 数据/训练

### 中期（下一版预训练）
1. eval 增加 CSS/mode coverage/feature richness 三个维度
2. ckpt 选择标准：SSIM + CSS 综合评分（而非 SSIM only）
3. early stop 判据：SSIM 停滞 **且** CSS 停滞（双确认）

### 长期（如果 ControlNet 效果仍然不够）
1. 预训练加入辅助骨架预测头（迫使空间理解）
2. 预训练加入风格一致性正则
3. 考虑更大的模型（XL/S-WoW）或更好的 VAE（f4→f8）

## 7. 我们已有的证据支持以上结论

| 实验 | 发现 | 支持的论点 |
|---|---|---|
| s19 vs s20 | 增广数据无增益 | 数据质量 > 数据量 |
| s20 vs s21 | fame 数据基模 SSIM 更低但 ctrl 不差 | base SSIM 不是 ctrl 性能的预测指标 |
| std-skel ctrl | 冗余条件被忽略 | 条件响应度才是关键，不是 SSIM |
| 1px vs 3px | 1px 更优（SSIM 0.7974 vs 0.7889）| 骨架精度对 ctrl 有影响 |
| cfg 1.7 vs 0.7 | 低 cfg 更好 | CFG > 1 对骨架条件有害 |
| band-median 误翻 896 张 | 1.7% 数据污染 | 数据清洗是前提条件 |
