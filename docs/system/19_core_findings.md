## 0. 三个最重要的发现

### 发现 1：base 与 ControlNet 的差距是**条件信息量**的差距，不是训练质量

| | base（预训练） | ControlNet |
|---|---|---|
| 全局条件 | 书家 128 + 字 384（**有效秩仅 34**） | 同左 |
| 空间条件 | **无** | 骨架 latent **4,096 维** |
| 有效条件维度 | ~162 | ~4,258 |
| 实测 SSIM | 0.467–0.50 | 0.73–0.80 |

**比值约 120 倍。** 骨架提供的不是「提示」而是**答案的空间骨架**。

含义：
- 「预训练差得出奇」这个说法需要修正——**不是训崩了，是条件信息量根本不够**。
- 后训练（ControlNet）之所以好，是因为补上了结构信息的缺失。
- 因此，**在全局条件上继续做文章（解冻 embedding、换投影）天花板很低**。
  s22 已实测证实：只训字 embedding 反而从 0.4664 降到 0.4622。

### 发现 2：SSIM 跨数据集不可比（报告指标必须带书家数）

| 书家数 | SSIM_max | SSIM_mean |
|---:|---:|---:|
| 11 | 0.7322 | 0.5452 |
| 44 (fame) | 0.4670 | 0.4646 |
| 67 | 0.5409 | 0.5231 |
| 108 | 0.5319 | 0.4022 |
| 1,004 | 0.4578 | 0.2612 |

历史上「0.73 → 0.47」看起来像退步，**实为评测集从 11 书家变到 44 书家**。
此前的跨实验对比（以及基于它的部分结论）都需要重新审视。

### 发现 3：1px 骨架优于 3px（两个评测点一致）

同期对照（base 恒为 0.4977）：

| step | 骨架 | SSIM | SkelIoU | MSE |
|---:|---|---:|---:|---:|
| 2,500 | 1px | **0.7355** | **0.2060** | **0.2276** |
| 2,500 | 3px | 0.7288 | 0.1969 | 0.2500 |
| 5,000 | 1px | **0.7376** | **0.2141** | **0.2240** |
| 5,000 | 3px | 0.7337 | 0.2055 | 0.2431 |

**否定了「3px 高分靠条件泄露」的假设**（详见 17 文档 §3）。

原假设：3px 骨架在 256px 图上面积可观，其 VAE latent 已接近真实书法图，
因此 0.80 的高分里有一部分是「给的条件已经很像目标图」。
若成立，换成信息更少的 1px 应明显变差——**实测反而略好，且两个点一致**。

含义：
- 模型学到的是**真正的结构跟随能力**，不是靠条件像素级近似作弊
- 1px 是更干净的条件（信息更少而效果不降），且省去膨胀后处理
- 对下游（零样本、用户可编辑骨架）更有价值

## 1. 已证伪 / 已收敛的方向

| 方向 | 结论 | 证据 |
|---|---|---|
| 训练字形分类器做评估 | **不可行** | 4,765 字 / 51k 样本，每字 10.8 个样本，欠拟合 |
| DINO CLS 检索式字形评估 | **不可行** | 库内 84% / 库外 **4%**（top-5 低于随机） |
| 解冻字 embedding（s22） | **无益，略有害** | 0.4664 → 0.4622，loss 持平 |
| 标准字库骨架（std-skel） | **彻底失败** | SSIM 0.494≈base，IoU 0.015，**12 个评测点全平** |
| 「字→骨架」预测网络 | **上界很低** | 他人书法骨架实测只值 +0.007 |

### 1.1 关于 std-skel 失败的机制（文档 13 的归因需要修正）

文档 13 §4 说「ControlNet 学会门控掉冗余条件」，解法是「提高 char dropout」。

**门控是结果不是原因，且该解法不会生效。**

要区分两个指标：
- **跟随度**（输出是否忠实于给定骨架）：3px 已达 0.32，**不需要救**
- **保真度**（输出是否接近目标图）：受限于骨架携带多少目标信息，
  **提高 dropout 救不了**

提高 char dropout 只会让模型在「骨架 vs char」之间重新分配权重，
跟随度↑，但保真度仍被「预测骨架 ≠ 目标图真实结构」钉死在 ~0.52。

std-skel 的失败曲线（12 点全平）是最好的证据：**冗余条件被完全门控，
且训练过程毫无挣扎**——说明模型从一开始就判定这个条件无用。

## 2. 已修复的代码问题

| 问题 | 影响 | 状态 |
|---|---|---|
| `_default_dino_ckpt()` 路径少一级 | 本地 DINO 永远找不到，静默回退 `torch.hub`（需联网） | **已修**（9844b8f） |
| `w_glyph_cond` 接线到失效的 v1 字典 | 启用后条件全零、实验静默无效 | 诊断完成，**修复方案已定**（见 §3.1） |
| eval daemon 需按实验手动启动 | 换新实验名时漏配 → 跑了半天没指标 | 已为 s22/1pix 补配；建议进启动脚本 |
| fame 骨架 train/eval 覆盖不一致 | eval 侧 stale | 新脚本已改为一次性覆盖 |

### 2.1 一个反复出现的失效模式

仓库里出现了**两次同构的静默失效**：

```
w_glyph_cond:    字典缺失 → 返回零张量 → 条件无效但不报错
ControlNet ckpt: injections 未加载 → zero-init → cond 短路但不报错
```

共同模式：**zero-init / 零填充 + 宽松加载 = 静默失效**。
排查「某个条件看起来没用」时，应**优先检查这个模式**，而不是先怀疑模型设计。

## 3. 下一步方向（按优先级）

### 3.1 修 `w_glyph_cond` 接线 → 做 A/B（**最高优先**）

**为什么值得做**：这是唯一直接针对「字形正确」的路径。
标准字形 latent 编码的是**字的形状本身**，而不是全局图像描述子——
正好补上 DINO CLS 丢掉的空间结构。代码完整、数据齐备（v2 覆盖 53.1%）。

**关键洞察**：`w_glyph_cond` 与骨架是**同源的空间条件**，都是 4×32×32。
既然骨架能带来 +0.29 SSIM（0.4977→0.7889），
而标准字形 latent 同样是空间图、且编码的是**标准字形**（比骨架更接近目标），
它的效果值得期待——**而且它是可推理获取的，不需要 GT 图**。

换句话说：
- 骨架 = 必须从目标图抽取（推理时拿不到）→ 只能验证上限
- 标准字形 = 只需知道「写哪个字」（推理时**天然可得**）→ **真正可用**

**这可能是把 ControlNet 的 0.80 从「复刻」变成「零样本生成」的关键**。

**成本**：改 1 行（v1 → v2）+ 重训。

**必须同步修的两处**（否则实验无效）：
1. `latent_dataset.py` 改用 `get_glyph_lookup_v2()`
2. **eval 侧也要喂 g**：`train.py` 调 `prepare_eval_cache` 时未传
   `use_glyph_cond`，且 `in_process_eval.py` 的 cache **不含 g**。
   训练喂 g、eval 不喂 → 条件域不匹配 → 结论失效。

**风险**：草 10,910 样本、篆 2,977 样本零覆盖，需明确缺失策略
（给零 / 用同字他体 / 排除）。

### 3.2 等 1px 实验跑完，确认趋势

当前只有 step 2,500 一个点。需确认 5,000 / 10,000 / 20,000 步后
1px 是否仍优于或持平 3px。

- **若持续持平/更优** → 1px 成为默认骨架条件（更干净、无需膨胀后处理）
- **若后期被 3px 反超** → 说明 3px 确实提供了额外的面积信息，需权衡

### 3.3 建立未见字评测

当前 fame 评测：字 100% 见过、书家 100% 见过，**只测组合泛化**。

**未见字能力完全未评估**——而这是真实使用的核心场景，
也是「字→骨架网络」唯一尚未证伪的价值场景。

建议：留 300 个字完全不训，量化 base 跌多少、骨架能救回多少。
现成的 `eval_unseen_top6.csv`（255 条）可直接改造。

### 3.4 评测口径改进

SSIM 对书法有盲区：**「写对但细节不同」和「写错」可能都是 0.5**。

建议：
- 字形正确率做主指标（但自动化测量目前无解，见 §1）
- 退而求其次：**固定 50 样本的人工目检**，每次实验看同一批
- SSIM / LPIPS 做副指标
- SkelIoU 做跟随度指标（已有，很好用）

### 3.5 数据规模化

fame 51k / 44 书家 vs 全量 329k / 1,853 书家。

200 斩杀线砍掉了徐渭、张芝、怀仁、杨凝式、康熙等代表性书家。
可考虑：全量预训练 + fame 微调，或放宽斩杀线。

**注意**：书家数增加会让 SSIM 下降（§发现 2），
所以「数据更多」与「指标更高」在此任务上是**冲突的**，需要明确取舍。

## 4. 一张图总结

```
                    条件信息量                    实测 SSIM
                    ----------                    ---------
base (全局条件)      ~162 维有效                    0.47-0.50
  ├─ 书家 ID          128 维  ─┐
  └─ 字 ID (DINO)     384 维   ├─ 有效秩仅 34
                      (有效 34)┘

ControlNet           +4,096 维                    0.73-0.80
  └─ 骨架 latent       4×32×32 空间图  ← +0.29

w_glyph_cond (待接线) +4,096 维                    ???
  └─ 标准字形 latent   4×32×32 空间图  ← 推理时天然可得 ← 关键机会
```

**核心判断**：这个项目的问题从来不是「模型训不好」，
而是**「条件里没有足够的信息让模型知道该画什么」**。
所有能提升条件信息量（尤其是**空间结构信息**）的方向，都值得优先做；
所有在全局标量条件上打转的方向，天花板都很低。
