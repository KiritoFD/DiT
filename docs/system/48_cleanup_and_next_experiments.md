# 48. GPU 消融实测：哪些模块真的可删 / CFG 口径修正（2026-09-10）

状态: 容量扫描已停。本文含 **GPU 推理时消融实测结果**（工具 `src/eval/gpu_ablate_eval.py`）。
前置: 46（风格 token）、47（阶段总结）

---

## 0. 方法：为什么用"推理时消融"

对已训练 ckpt，在**推理时**把某模块的输出置零，看指标掉多少：

- 指标基本不变 → 该模块在推理路径上未被使用 → **可删**
- 指标大幅下降 → 该模块是必需的 → **不可删**

成本 = 一次评测（**每个配置 4 秒**）而非一次训练（数小时）。
局限：这是"是否被使用"的强证据，**不完全等价于"训练时删掉它"的对照**（训练时模型会重新适应）。
但足以**发现纯冗余/死重模块**，也能给出各模块的**相对贡献量级**。

## 1. 实测结果（c41x @212.5k，n=10，cfg=0.7，50 步 heun）

| 配置 | ssim | skel_iou | vs baseline |
|---|---:|---:|---:|
| **baseline** | **0.7838** | **0.2227** | — |
| `no_glyph_add`（屏蔽输入层 token-add） | 0.5021 | 0.0108 | **−0.2817 / −0.2119** |
| `no_xattn`（12 层 out_proj 置零） | 0.5412 | 0.0217 | −0.2426 / −0.2010 |
| `no_callig`（书家→null） | 0.5641 | 0.0316 | −0.2197 / −0.1911 |
| `no_g`（骨架条件→None） | 0.4331 | 0.0116 | **−0.3507 / −0.2111** |
| `no_callig_no_g` | 0.4423 | 0.0115 | −0.3415 / −0.2112 |

### ⚠ 结论 1：**没有一个是冗余模块，此前"可删"的判断被推翻**

我此前（§旧版）主张删除的两项，实测**全部是最关键的通道**：

| 我此前的判断 | 实测 | 修正 |
|---|---|---|
| D1 "输入层 token-add 与 xattn 重复，且其存在理由（提供梯度）已失效，应删" | 置零 → **ssim −0.28，skel_iou 0.223→0.011（几乎归零）** | ❌ **撤回。它是骨架条件的主力通道** |
| D2 "`CalligStyleCrossAttn` 与 `GlyphStyleCrossAttn` 重复" | c41x **根本没启用它**（`callig_style_attn=None`） | 仅 `c41x_scratch` 线的问题，与主线无关 |

**为什么 D1 判断错了**：`learned glyph_scale = 0.1896`（init 0.6）——模型确实主动把它调小了 3 倍，
所以我推断它"无关紧要"。但 xattn 的 `out_proj` 是 **zero-init**，学到的贡献有限；
**骨架信号主要靠这条"看起来很小"的 token-add 直通**。两者是**互补**关系
（token-add = 全局粗注入；xattn = 空间精细寻址），不是重复。

**教训**：不要用"参数幅度小 / 初始化设计"推断模块重要性，**必须实测**。

### 结论 2：四个条件通路全部必需
骨架 g（−0.35）、输入层注入（−0.28）、xattn 逐层注入（−0.24）、书家条件（−0.22）——
去掉任何一个都导致 skel_iou 崩到 0.01~0.03（baseline 0.223）。**当前架构没有可删的大件。**

## 2. ⭐ 意外发现：CFG 一直用错了（免费提升）

同一 ckpt，只改评测 cfg：

| cfg | ssim | skel_iou |
|---:|---:|---:|
| 0.5 | 0.7136 | 0.1200 |
| **0.7（一直用的默认值）** | 0.7838 | 0.2227 |
| 1.0 | 0.8054 | 0.2921 |
| 1.3 | 0.8139 | 0.3245 |
| 1.5 | 0.8188 | 0.3419 |
| **2.0** | **0.8261** | **0.3517** ← 峰值 |
| 2.5 | 0.8256 | 0.3470 |
| 3.0 | 0.8244 | 0.3448 |
| 4.0 | 0.8227 | 0.3328 |

**最优 cfg ≈ 2.0**：

| 指标 | cfg=0.7（历史全部） | cfg=2.0 | 变化 |
|---|---:|---:|---:|
| ssim | 0.7838 | **0.8261** | +0.042 |
| **skel_iou** | 0.2227 | **0.3517** | **+58%** |

**这意味着**：
1. 45 号"CFG 理论值 s=1.0"的裁定**偏保守**，实测最优 ≈ 2.0（条件信号需要 >1 的放大）。
2. **所有历史评测（cfg=0.7）都系统性低估了模型**，尤其低估"骨架遵循度"（skel_iou 被压掉 58%）。
3. 这是一个**零训练成本的提升**——只需改评测参数。

**置信度说明**：n=10，`ssim_std ≈ 0.13` → ssim 曲线在 1.5~4.0 之间的差异（0.819~0.826）
**在噪声内**；但 **skel_iou 的 0.223→0.352 远超噪声**，结论成立。需用 strict 集（n=237）复核。

## 4. 优先级最高的实验（更新版）

### P0 —— 零训练成本，立刻做

| # | 实验 | 内容 | 预期 |
|---|---|---|---|
| **E4a** | **CFG 复核** | 用 strict 集（n=237）跑 cfg ∈ {0.7, 1.3, 1.5, 2.0, 2.5}，确认峰值 | 若成立，**所有实验报告口径改为 cfg≈2.0** |
| **E4b** | **历史 ckpt 重测** | 把 c41x 各点（105k~212.5k）用 cfg=2.0 重测 | 得到真实收敛曲线 |
| **E4c** | **sty 重测** | sty16@15000 用 cfg=2.0 重测（原 0.4762@cfg0.7） | 容量对比必须同口径 |

### P1 —— 30k 训练级消融（成本 ~2h/个）

| # | 实验 | 唯一变量 | 目的 |
|---|---|---|---|
| E1' | xattn 层数 | `glyph_inject_layers` ∈ {0, 4, 12} | 既然输入层 token-add 已撑起主要通路，**12 层 xattn 的成本/收益**需重新审视（+9G 显存换 −0.24 的贡献，是否 4 层就够？） |
| E2 | 关 REPA | `w_repa=0` | 0.03 **从未被验证**；41 号只说 0.1 会劫持 |
| E3 | 关条件 drop | `cond_drop_*=0` | 闭集部署 + CFG=2.0（**要用 uncond 分支了！**）→ drop 从"浪费"变成"必需"，需重新评估 |

> 注：E3 的结论会因 §2 而改变。既然 cfg=2.0（>1）确实最优，说明 uncond 分支**是必需的**，
> 训练时的 cond_drop **不再是浪费**——它正是为这个 CFG 服务的。**这是 CFG 发现带来的连锁修正。**

### P2 —— 新模块验证（前提是口径统一后）

| # | 实验 | 要求 |
|---|---|---|
| E5 | 风格 token 收益 | n=0 vs n=32，30k，**同 warmup**，**同 cfg（2.0）** |
| E7 | n ∈ {16,32,64} 容量扫描 | 仅在 E5 通过后 |

### P3 —— 评测基础设施

| # | 问题 | 修法 |
|---|---|---|
| F1 | ~8 处模型构建点需手工同步新参数（本次 `style_token_n` 漏传导致 eval 全崩） | 抽 `build_model_from_ckpt_args(a, arch)` 单一入口 |
