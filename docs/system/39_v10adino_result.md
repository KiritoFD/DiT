## 4. 结论（用户困惑的最終答案）

1. **冻结 DINO char 表对 base SSIM 是净负贡献**（-0.002~-0.014，全程系统性低于 v10a）：
   - 中段差异最大（50-62.5k -0.012~-0.014），尾段收敛（-0.002~-0.004）
   - 参数量还少了 13.8M —— 不是欠拟合问题，是**条件语义本身更差**
2. 机制解释（与 dit.py 25 号文档证据链一致）：
   - 冻结 DINO 表有效秩只有 **34.1/384**，PC1 占 26.3% 能量，表征"书体"多于"字符身份"
   - ln_only 直通无容量重组微弱信号；可训练随机表在 80k 内已学会足够好的字符判别
   - "特征够好就不该投影"的旧法则（s28 遗训）在**从头预训练 + 大量数据**场景下不成立：
     可训练投影能把随机表也学到 384 维有用方向
3. **用户困惑的完整答案**：
   - "drop char 没什么损失" —— 对：v10b 无 char 仍 0.8404，char 因子非必需
   - "良好 DINO embedding 理应有用" —— **错**（至少 base 上）：冻结 DINO 表只能当
     **推理时开集 char 查表**价值（部署态给新字一个语义向量），不能当训练条件质量杠杆
4. **v10b（无 char）仍是 v10 系列最优形态**：base 0.8404（未完）+ 开放词汇 + 参数最少
5. 遵循度维度未测（训练只到 80k 即停，且用户已判定遵循度平台不值得继续）：DINO 表
   的潜在优势只可能在"开集 char 查表推理"场景，与 skel-as-cond 的 g 通路职责重叠，
   预期无增益（§3.5 已证两模型遵循同源）
