# 77 · 条件注入的分层路由（TableCondRouter）与其实测有效性

- 日期：2026-10-06
- 代码：`src/model/injections.py`（`TableCondRouter`）、`src/model/dit.py`、`src/train/cli.py`、`src/eval/cli.py`、`src/eval/model_io.py`
- 配置：`src/train/configs/v66_tables_condroute2456.json`
- 相关：`docs/system/76_experiments_20261005.md`

## 1. 一句话结论

把三表条件**只注入 4 个中前层（block 2,4,5,6）**，其余 8 层**完全切断**（`c = t_emb`，条件不参与任何计算）：

- 在 187 张 held-out（`eval200fix`）上**不输** v54 的全局注入，且 **LPIPS 在 24/24 个评测点上全部更优**、SSIM 在 23/24 个点上更优；
- 在 20 张训练分布样本（`seen`）上领先 v54 **+3.4 pt**，且 v66@120k（0.6555）**已超过 v54 的 150k 终点**（0.6410，历史最佳 0.6478）；
- 结构类指标（墨迹 IoU/SSIM、骨架 IoU、缺笔率）一致更好 → 条件在中前层**更集中、更有效**。

## 2. 动机：三次改版（其中一次是被否证的负面对照）

| 版本 | 做法 | 结果 |
|---|---|---|
| **v54**（基线） | `c = t_emb + y_emb` 喂给**全部 12 层**（全局 adaLN，无处不注入） | best 0.5960 / seen 0.6410（150k） |
| **v65**（**已废弃**） | 在全局 adaLN 之外**额外叠加** 4 个 zero-init adaLN 注入模块（层 2,4,6,8） | 同 step 比 v54 **低 1.2–3.0 pt** → 负面对照：深层照样有结构/条件输入是有害的 |
| **v66**（本方案） | **白名单路由**：只有列出的层拿到条件，其余层 `c = t_emb` | 见 §4 |

理论依据：UNIC-Adapter / RelaCtrl / Ctrl-X / ControlDiT 的逐层功能分化结论 ——
浅层（0–20%）在做噪声解相关与吸收全局信息；中前层（20–60%）在定轮廓/拓扑；
深层（60–100%）在渲染高频纹理，注入"锐利线稿式"条件会得到塑料描边感。
0-indexed、depth=12 时中前带 ≈ 3–7；本配置取更靠前的 **2,4,5,6**（17%–50%）。

## 3. 实现（干净重写，旧机制已连根删除）

`src/model/injections.py`：

```python
class TableCondRouter(nn.Module):
    def cond(self, block_idx, t_emb, y_emb):
        k = self._map.get(block_idx)
        if k is None:
            return t_emb                       # 非白名单层: 条件不参与任何计算
        return t_emb + y_emb * self.scales[k]  # 白名单层: 才注入
```

- `scales` 是**每层一个可学习标量**（init 1.0）。训完它本身就是"这一层多想要条件"的读数（§4.4）。
- `src/model/dit.py`：`cond_inject_at` 非空时构造 router，forward 逐层选择条件；
  **已删除**上一版的 `cond_inject_layers` / `cond_inject_mode` / `cond_injections` / `_cond_inj_map`（那套是"叠加"语义，被 §2 的 v65 否证）。
- CLI：`--cond-inject-at "2,4,5,6"`、`--cond-inject-scale`（train 与 eval 两侧都注册）。
- eval 侧 `model_io.build_model_from_args` 同步接上；`scales` 是**真参数**，漏传会 `strict=True` 报 missing（不会像纯行为开关那样静默）。
- 空 `cond_inject_at` = 旧行为（条件给全部层 = v54 语义），向后兼容。

**CPU 单元测试**（`_sync_work/test_cond_route.py`，不占 GPU，用 forward hook 抓每个 block 的 `c` 入参）：
非白名单层 `[0,1,6,7,8,9,10,11]` 的 `c` **逐元素完全相同**（= `t_emb`）；白名单层 `Δ = c − t_emb` 各层范数一致（= 同一个 `y_emb`）；非白名单层 `Δ = 0`。

### 4.4 模型自己学出来的层强度（router scales，init 1.0 → @122k）

| 层 | L2 | **L4** | **L5** | L6 |
|---|---|---|---|---|
| scale | 1.5002 | **1.5474** | **1.5398** | 1.4606 |

- 4 个全部涨到 1.46–1.55 → 把条件从另 8 层切断后，留下的 4 层被模型**主动加强**（与"切断不亏"一致）；
- 带内 **L4 ≈ L5 > L2 > L6**（中段最贪、两端最淡）→ 注入带内部呈弱倒 U；
- ⚠ 这是**带内相对值**（被切断的 8 层是硬 0，不可比），**不能**当绝对层级重要性曲线用。

## 5. 必读的反面与未决（不写进结论会被误导）

1. **`seen` 不是 held-out**：`seen20 ∩ train = 21/21`（全部是训练样本）；`eval200fix ∩ train = 1/188`（真 held-out）。
   故 `seen` 上的 +3.4 pt 是**记忆**而非泛化；泛化判据只能看 `eval200fix`。
2. **held-out 上的早期领先会收敛**：10k 时 +1.37 pt → 120k 时 −0.06 pt（与历史 v53/v54"起点差、终点同分"同型）。
   对 v54 的 **150k 终点**，v66 在 eval200fix 上仍差 SSIM −0.004、LPIPS +0.0026（但 v66 还有 30k 步未跑）。
3. **碎片率两集方向相反**（held-out 略差 +0.027、seen 大幅更好 −1.32）→ 需看 poster 判断是否视觉可辨。
4. **梯度类"层选择"探针无效**（今日两次实测）：
   - 原始 `‖∂L/∂W_out‖` 随深度**单调递增**（0.25@L0 → 0.40@L10），是"反向路径越短梯度越大"的深度偏置；
   - 除以 block 输出梯度归一化后，top4 仍恒为最深的 `[11,10,9,8]`；
   - 条件路由的 scale 轨迹层间差异只有 ~1.5%，无分辨力。
   → **层号目前是"按文献带人工定 + 单点验证"，尚无数据驱动的定层方法。**
   实现与结论留档于 `src/utils/inject_probe.py` 的 docstring 与 `src/train/configs/_probe_inject12.json` / `_probe_route12.json`。
   真要做因果定层，正确做法是**免训练的门控评测**（把 `scales` 设 one-hot / leave-one-out，跑小子集评测），而非梯度统计。
5. **组合稀疏是最根本的瓶颈**：训练集 26,003 张 / 因子空间 10×3×4,690 = 140,700 组合 → **覆盖仅 18.5%**；
   150k×384 = 57.6M 样本 = **2,215 个 epoch**。最近 25k 步 held-out 仅 +0.004（收益衰减）→ 下次可把 `max_steps` 砍到 ~100k。
   **Rectified-Flow 的 reflow 不能治这个**：我们已经在用 flow matching（`diffusion_type: flow`），
   而 reflow 只是用模型自采配对把 ODE 轨迹拉直（改善少步采样/离散化误差），**不注入任何新信息**，对未见组合无效。
