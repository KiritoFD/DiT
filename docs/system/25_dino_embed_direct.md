# DINO cls/patch 直接作为 char/glyph embedding —— 零参数信号质量研究（2026-08-31）

> 核心问题：能不能用 DINO 的 CLS / Patch 特征**零可训练参数**地直接作为 char/glyph
> embedding 注入模型（冻结查表）？前提是「初始信号足够好」——即**外形像的字在
> 特征空间里应该接近**（用户原话：「不只是区分度，外形像的应该接近」）。
> 参数量约束：可训练参数 ≤ 2M。

## 0. 结论（一句话）

**DINO 特征本身具备极好的外形一致性（标准字形下 AUC 0.92–0.96），可以直接零参数
注入；但「书法真迹跨书体平均」的 DINO 特征不行——它被书体主导，把形近/随机对的
余弦全部压到 ~0.83，区分度坍缩到随机（AUC 0.50）。**

只要把 char/glyph embedding 的特征来源从「真迹跨书体平均」换成「标准字形（kai/li）」，
就能在 **0 可训练参数**（≤2M 自然满足）下满足外形一致性。

---

## 1. 评测方法（为什么不用像素 IoU）

最初试图用**标准字形骨架的像素 IoU/余弦**当"外形相似度"真值，结论是 CLS 不行。
用户指出错误：**土/士 结构相似，但像素 IoU 只有 0.07**——因为像素级度量对笔画位置
敏感，非刚性的"结构相似"（横画位置、比例微变）无法用像素重叠捕捉。

改用**判别性评测**（不依赖像素真值）：
- **正例**：人工标注的形近字对（土/士、大/太、人/入、王/玉…，共 46 对）。
- **负例**：随机不同字对（10 倍量）。
- **指标**：
  - 分离度 = 形近对余弦均值 − 随机对余弦均值
  - AUC = 用余弦对「形近 vs 随机」二分类的 Mann-Whitney U AUC（0.5=随机，1=完美）

若 CLS 给形近对显著更高余弦 → 它正确捕捉了"外形像的字接近" → 可零参数直接注入。

## 3. 核心发现

1. **DINO 特征本身外形一致性极好**（标准字形下 AUC 0.92–0.96，分离度 +0.09~+0.16）。
   用户直觉「CLS 蛮好的」在干净字形上是**成立**的。

2. **问题不在 DINO 特征，在「真迹跨书体平均」。** 真迹 CLS768 把所有字对余弦压到
   ~0.83（书体主成分主导，PC1 占 26.3% 能量），形近/随机无法区分（AUC=0.50）。
   这与 `docs/system/23_dino_signal_diagnosis.md` 的结论一致：**CLS 被书体主导，
   跨书体平均丢失字形结构**。

3. **CLS vs Patch：都可用。** 标准字形下 CLS 分离度更大（+0.139~+0.163），
   patch-mean AUC 更稳定（0.94，形近对普遍 0.93+，方差小）。patch 对"外形像"
   更鲁棒，但平均池化后区分度略弱于 CLS。

4. **零参数直接注入可行，前提是换特征来源。** 用标准字形 DINO 特征查表冻结注入，
   可训练参数 = 0（≤2M 自然满足），外形一致性 AUC>0.92。

## 4. 可落地的 embedding 设计建议

**推荐方案：char/glyph embedding 改用「标准字形」的 DINO 特征，冻结查表，零参数。**

- **特征**：`std_kai_cls.npy`（或 `std_kai_patch_mean.npy`）按 codepoint 建表。
  - CLS：分离度最好，AUC 0.92–0.96。
  - PatchMean：AUC 更稳，对外形像更鲁棒（形近对全 0.93+）。
- **参数量**：查表冻结 → **0 可训练参数**（远小于 2M）。
- **注入**：直接 `Embedding.from_pretrained(冻结)` 查表，经 `char_proj`（可省或仅 LN）
  进入 adaLN，与 `callig_scale` 平衡。若连投影都省，就是纯零参数。
- **覆盖**：kai 4521 字 + li 3402 字，合并约覆盖训练字符集的常用部分；未覆盖字
  可用 `fallback_embed`（如 IDS 均值或全局可学习向量，参数量极小）。

**与当前实现的衔接**：
- 当前 `IDSCharEmbedder`（60 万参数）用 IDS 部件池化，天然零样本但部件粒度粗。
- 若 DINO 标准字形信号足够（AUC>0.92），可**替换**为 DINO 冻结查表，参数量更低
  （0 vs 60 万），且外形一致性更直接。
- **注意域差异**：标准字形是印刷体，模型输入是真迹书法。需验证风格对齐
  （标准字形 embedding 的语义能否驱动书法生成）。若域差异导致注入弱，可退化为
  用真迹特征但先做"去书体"（CLS384 居中，AUC 0.68）或小投影放大（<2M）。
