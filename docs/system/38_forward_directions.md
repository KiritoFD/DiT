# 38 — Drop-char 之谜与模型提升方向分析

> 2026-09-06 深夜。回应困惑："drop char 对 skel 遵循没提升？良好的 DINO
> embedding 对学习没起作用？" —— 结论：**这不是诡异，是测量与混淆**。
> 上承 36（遵循度矩阵与协议修正）、37（数据布局）。

## 1. 三个关键事实（解开困惑）

### 1.1 v10a 的 char 因子不是 DINO embedding

v10a 配置（`src/train/configs/v10a_skel_cond_pretrain.json`）明确：

```
"freeze_char_table": false,
"_comment": "...无 DINO index 文件, char 表随机初始化需可训练..."
```

即 v10a 的 y_char 走 `dit.py` 的 **LabelEmbedder（可训练随机表，35130×384）**，
**不是** `StdDinoCharEmbedder`（冻结 DINO 表，仅 s28/s29 两阶段主模型用过）。

所以"v10b drop char 之后遵循度没掉"**完全正常**：drop 掉的是一个从头随机
初始化、对训练集外新字查表即垃圾的 35k 查表，而不是任何"良好 embedding"。
用户的直觉「良好的 dino embedding 理应起作用」在 v10 系列里**从未被测试**——
v10 系列从头到尾没用过 DINO 条件。

### 1.2 对比不公平：85k vs 135k

| 模型 | base SSIM best | 封顶点 | 曲线状态 |
|---|---|---|---|
| v10a (有 char 随机表) | 0.8476 @127.5k | 127.5k→135k 持平 | 已封顶 |
| v10b (无 char) | 0.8404 @85k（早停） | **85k 时仍在上行** | 未到平台 |

v10b 被早停在 85k（0.8298→0.8404 持续升），v10a 跑到 135k。
"drop char 净亏 0.007"是 **85k vs 135k 的不公平比较**——v10b 若续跑到
135k，base 能否追平 v10a 未知。**净代价未被回答。**

### 1.3 遵循度两地持平且平台化（协议修正后）

char-null 协议 n=30：v10a 0.578 ≈ v10b 0.570（差 0.008 << std 0.036-0.045）。
两模型遵循度同源（都来自 g 骨架主干通路），char 因子不影响 follow；
且遵循度 12.5k 即 0.554，67.5k→85k 平台期——早停 85k 正确。

## 2. 真正的提升方向（按信息量/成本排序）

### A. v10b resume → 135k（补完 drop-char 净代价，成本最低）✅ 推荐先做

v10b 85000.pt 续训到 135k（配方原封不动，早停 patience 放宽/停用）。
- 若追上 v10a（≥0.847）→ **drop char 完全免费**：v10b 定案（开放词汇
  无字表边界 + 少 13.8M 参数 + base 持平），v10 路线以无 char 形态收尾
- 若封顶 ~0.843 → drop char 净亏 ~0.004，代价微小，仍可接受
- 同时补 v10b 遵循度 12.5k 单点（CPU 版同协议），画完整曲线

### B. 骨架遵循度平台突破（0.57 → 目标 0.65+）✅ 产品关键指标

遵循度是手绘端到端的体验核心。当前平台候选杠杆：
1. **glyph_scale 从 0.4 调大 / 变可学习**（v10b 现固定 0.4）：骨架注入强度
2. **glyph_embedder 多 token**（现 4→384 conv + patch2 → 256 token）：
   骨架信息容量
3. **1px → 3px 骨架 latent**：1px 中心线对细线天然苛刻，3px 容差才是部署
   协议；用 3px latent 训练可能直接提 IoU3
4. **glyph_drop 0.1 → 0.05**：g 条件给得更足

低成本先探 1/4（改 config 即可），2/3 需小改模型。

### C. REPA 强化到 v8e 成功配方（w 0.1 → 0.5）✅ base 质量杠杆

v9b 两阶段 REPA w0.5（layers 8,11）是用户认可的最成功配方；
v10a/v10b 预训练 REPA 只有 w0.1。v10 路线 REPA w0.5 未测。
注意 v8e 教训：长训伤 base，**必须配早停**（patience 5 / min 10000 已有）。

### D.（中长期）模型规模 / 数据

- DiT-S 只有 33-46M，书家 1013 类 + 字 35130 类，容量偏紧；
  可试 S/1 或 M（显存预算 20-22G 内 S/1 可行）
- 数据：fame 4765 字 × 1013 书家固定；字库标准骨架 37k 字可作
  预训练自监督扩展（先 A/B 小步验证）

## 3. 禁忌（历史教训）

- ❌ 不重启 DINO 作为条件源（系统性证伪：检索 1.2%、ln_only -8.2%、秩分析不值；
  且用户明确"不用 DINO，skel latent 直接当输入"）
- ❌ 长训伤 base（v8e 22.5k 峰值后回退）；一切长跑必须早停
- ❌ v10b 的 char 表方向混淆：它不是 DINO，是随机表；"良好 embedding"
  假说在 v10 路线上的验证 = 冻结 DINO 表实验（被 §3 否决），不是本文件的主题

## 4. 建议执行顺序

1. **A：v10b resume → 135k**（GPU 空闲，顺手补遵循度 12.5k 点）
2. **B：遵循度杠杆 1/4 一次双跑 A/B**（glyph_scale 0.6 + glyph_drop 0.05）
3. **C：REPA w0.5 新一轮**（等 A/B 结论后）
4. 全部入册后写 v10 系列终结页，定稿 v10a/v10b 数字
