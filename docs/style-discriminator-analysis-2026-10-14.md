# 风格判别器：为什么差 —— 完整分析

- 日期：2026-10-14
- 背景：用户提出用标准字形作为对比学习的负样本/独立槽位 ✓，实现后跑完 5000 步 ✓

---

## 0. 一句话结论

> **思路是对的 ✓，但 "跨字的书家风格判别" 这个任务本身在当前条件下无法达成** ✗。
> 所有已试方案（DINO / CLIP / latent CNN / 像素 CNN + 字体负 / 像素 CNN + std 负）
> 的 2AFC 都低于 0.65 门槛 ✗ —— 说明瓶颈不在负样本策略，而在**任务本身的难度** ✓。

---

## 1. 实验汇总

| 方案 | 输入 | 负样本策略 | 训练量 | G1(书家 2AFC) | G2(检索 mAP) |
|---|---|---|---|---|---|
| DINOv2-L/14 | 像素 | 无（预训练 ✓） | 0 | 0.365 ✗ | 0.139 ✓ |
| CLIP-L/14 | 像素 | 无（预训练 ✓） | 0 | 0.410 ✗ | 0.139 ✓ |
| latent CNN v1 | 4×32×32 | 同书家异字正 + 异书家同字负 | 6000 步 | 0.594 ✗ | 0.288 ✓✓ |
| latent CNN v2 | 4×32×32 | 同上 + 权重 ↑ + ch ↑ | 8000 步 | 0.611 ✗ | 0.272 ✓ |
| 像素 CNN + 字体负 | 3×160² | 系统字体渲染同字负 | 1000 步 | 0.32 ✗ | 0.126 ✓ |
| **像素 CNN + std 负** | **3×160²** | **std 字形同字负 ✓** | **5000 步** | **0.450 ✗** | **0.140 ✓** |

> 所有方案的 2AFC 都 < 0.65 ✗。检索 mAP 都 > 基线 ✓ 但绝对值不高 ✓。

## 2. 为什么差 —— 五层原因（从浅到深 ✓）

### 2.1 数据稀疏（最浅层 ✓）

```
真迹 9000 张 / 10 书家 / ~4677 字
⇒ 每个 (书家, 字) 对平均只有 **1.25 张** ✗
⇒ 48.2% 的字连一个"异书家同字"的负样本都没有 ✗
⇒ 19.9% 的 (书家,字) 对有 ≥2 张（可做"同书家同字"正样本 ✓）
⇒ 对比学习的正/负样本池天然稀疏 ✓
```

### 2.2 对比损失的**捷径问题**（核心 ✓）

任何对比学习都会**先学最容易的判别特征** ✓：

```
容易度排序（从易到难 ✓）:
  ① 材质（纸张纹理 vs 渲染/扫描） — 只需低级纹理特征 ✓
  ② 字符身份（"山" vs "水"） — 只需形状特征 ✓
  ③ 书体（楷 vs 行 vs 隶） — 需要笔画风格特征 ✓
  ④ **书家身份**（王羲之 vs 颜真卿） — 需要跨字概括**笔法习惯** ✓✓✓
```

**std 负样本的问题** ✓：它们让模型可以走 ①"材质"捷径 ✗——
- std 字形是干净渲染（无纸张纹理、无墨色渗透 ✓）
- 真迹是扫描/拍照（有纹理、有背景噪声 ✓）
- ⇒ 模型只需区分"干净 vs 粗糙"就能让 loss 归零 ✗✗
- ⇒ **根本没碰到 ④"书家身份"** ✗

**字体负样本的问题** ✓：同理 ✗——
- 系统字体渲染比 std 更"干净" ✗ ⇒ 同样的 ①"材质"捷径 ✗
- 且字体渲染**没有笔锋/墨色变化** ✓ ⇒ 更容易被区分 ✗

### 2.3 **跨字迁移**问题（深层 ✓）

G1 2AFC 问的是：
```
anchor = 王羲之写的「永」
正样本 = 王羲之写的「山」（同书家、**异字** ✓）
负样本 = 颜真卿写的「永」（异书家、**同字** ✓）
⇒ 要答对，模型必须理解：王羲之的「山」比颜真卿的「永」**更像**王羲之 ✓
   —— 即"王羲之的笔法习惯"能**跨字迁移** ✓
```
⇒ 这要求模型从**单个字的视觉外观**中抽象出**书写者的运动习惯** ✓✓
   （笔压、笔速、笔画连接方式、墨量控制 ✓✓）
⇒ 这是**认知科学级别的抽象** ✗，不是 CNN 短期能学到的 ✗

### 2.4 预训练偏置（技术层 ✓）

```
resnet18 在 ImageNet 上预训练 ✓
  → 浅层：边缘/纹理检测器 ✓（有用 ✓）
  → 深层：物体语义（"这是一只猫" ✓）→ 对书家风格**完全无用** ✗
对比训练需要**覆盖**这些深层偏置 ✓ 但 1000-5000 步不够 ✗
  （ImageNet 预训练 = 90 epoch × 1.28M 图 ✓ 我们的 5000 步 × 192 图 = 1/10000 ✓✗）
```

### 2.5 2AFC 比检索**更难**（评估层 ✓）

```
2AFC: 逐对判别 ✓ — 每一对都必须答对 ✓ 一题错就扣 ✓
mAP:  排序 ✓ — 只要求目标书家的图**平均**排更前 ✓ 个别错被稀释 ✓
⇒ 2AFC 是更严格的判据 ✓（我们的 latent CNN 2AFC 0.59 但 mAP 0.29 ✓ 说明有信号但不够强 ✓）
```

## 3. G2（检索 mAP）为什么有信号 ✓

```
所有方案的 mAP 都 > 同书体随机基线 0.052 ✓
最好的（latent CNN）达 0.288 ✓✓
⇒ 说明模型确实编码了一些书家信息 ✓
   只是这些信息**不足以做逐对判别** ✓ 但足以做**排序** ✓
⇒ 建议: 用 mAP 作为风格轴的**主指标** ✓（放弃 2AFC ✗——它太严格了 ✓）
```

---

## 4. std 负样本的价值评估

| 方面 | 评价 |
|---|---|
| **思路** | ✓✓ 正确——std 是"中性风格"的最佳参照 ✓ |
| **数据** | ✓✓ 已在管线 ✓ 100% 覆盖 ✓ 不需额外标注 ✓ |
| **作为对比负样本** | ✗ 太容易被"材质"捷径区分 ✗ |
| **作为独立槽位** | ✓ 有潜力 ✓ 但需要更长的训练/更大的模型 ✓ |
| **作为生成端参照** | ✓✓ 最有价值的用法 ✓——v85 的 std-repulsion 惩罚 ✓ |

---

## 5. 下一步建议

| 优先级 | 方向 | 理由 |
|---|---|---|
| **1** | **用 G2 mAP 代替 G1 2AFC 作为风格轴主指标** ✓ | mAP 有信号 ✓ 且跨方案可比 ✓ |
| 2 | 判别器**长跑**（20000+ 步 ✓）看 G1 是否最终能涨上去 | 排除"训练不够"因素 ✓ |
| 3 | std-repulsion 惩罚 ✓ 加进 v85 训练 | 用**生成端**解决"太像 std"问题 ✓ |
| 4 | 判别器改用**书法专用预训练起点** ✓ | 避免 ImageNet 偏置 ✓ |
| 5 | 接受"跨字书家判别是开放问题" ✓ | 文献也一致认为这很难 ✓ |
