## 0. 先明确两个「大杠杆」和一堆「非瓶颈」

| 类别 | 改动 | 效果 |
|---|---|---|
| **★ 大杠杆** | **数据质量**（top6 → fame）| **SSIM +0.087** |
| **★ 大杠杆** | **实例级骨架条件**（ControlNet / skel latent）| **+0.30**（IoU 0.194 → 0.554，2.9×）|
| **非瓶颈** | 模型容量、数据增广、结构 loss、xattn、多风格表 | 均无显著增益 ✗ |

**→ 结论：这个任务里，「数据干不干净」和「骨架条件给不给力」决定成败；其余都是微调。**

## 5. 书法家 style encoding

### ⚠ 全部「无显著增益」

| 配置 | 方案 | strict |
|---|---|---|
| **v13_base** | 45 书家 × 128 维冻结向量（SupCon 预训练）| **0.5547**@155k（seen 0.7580）|
| **v14** | 87（书家×书体）pair 表 + 层级 SupCon，冻结 | **0.5703** ≈ v13 0.5703 **零增益** ✗ |
| **v15a** | K=4 子风格 token × 384 = 1536 维/行（DINO K-Means 初始化）| **0.5699** ≈ v13 **零增益** ✗ |
| **v15b_supcon** | SupCon 重训表（余弦 0.86 → 0.0019）| 0.5525@70k（口径待齐）|
| **v13 few-shot** | K=10（128 参数）| **失败**（loss 趟平 1.05）✗ |

### 根因分析

1. **DINO CLS pair 质心余弦 0.956** ✗ —— **几乎不区分书家** ✗
2. **K-Means 表行间余弦 0.860** ✗ —— **共线** ✗
3. **书家间 strict 与样本数负相关 r = −0.62** ✗ —— **样本多 → 风格跨度大 → 128 维装不下** ✗
4. **`ratio_style`** v15a 1.21 反低于 v13 的 1.48 ✗ —— **风格分离更差** ✗

**→ 结论：书家风格编码目前是明显短板，尚无严格同口径的有效性证据。**

## 7. 踩坑记录（12 条，同样重要）

1. 结构损失混入扩散损失**有害**（pixel + latent 双重否定）
2. 数据增广**无信息增益**
3. std-skel 冗余条件被门控忽略
4. 12ch 从头训**劣于** 4ch
5. xattn strict ≈ 0 且 **+33% 成本**
6. 多风格表扩容（K=4 / 87pair）对 strict **零增益**
7. **v13/v15 few-shot 的 g 错位**（`img_id=0..149` 命中无关骨架，**静默不报错**）→ 此前所有 few-shot 数字带病 ✗
8. `--train-only-new-callig` mask bug（MultiStyleEmbedder 无 null 行）→ 训练空转 0 参数
9. `--resume-full` 对通道扩展**静默跳过**（须 `--expand-from-4ch`）
10. `repa_layers` 未注册 argparse 被**静默忽略**；`w_repa` 默认 1.0 会悄悄占大头
11. eval CFG bug（`cfg_scale` 塞进 `model_kwargs`）→ 指标假象
12. `injections.*` ckpt 存盘丢失（致命）；无条件噪声增强证伪

---

## 8. 一句话总结

> **数据质量（+0.087）和实例级骨架条件（+0.30）是仅有的两个大杠杆。**
> 容量、增广、结构 loss、xattn、多风格表均**不是**瓶颈。
> **风格条件（书家）是当前最明显的短板** —— SupCon 表 + K token 是待验证方向，
> 但尚无严格同口径的有效性证据。
