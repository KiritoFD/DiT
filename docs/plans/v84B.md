## 1. 三处读码纠正（先于任何改动）

那份分析对机制的推断方向正确，但有三处细节需要按代码事实修正：

### ① 门控**同时**管两路 —— 不是"只管 c"

`_gate` 在 `src/model/dit_conditioning.py` 里被用到两处：

```python
# :776-778  空间残差（主通路）
if not cfg.glyph_concat_input:
    x = x + cfg.glyph_scale * (_gate * g_tok if _gate is not None else g_tok)
# :786-789  池化进 adaLN 的全局内容向量
if _gate is not None and g_tok is not None:
    g_tok = _gate * g_tok          # 池化源用**已乘门**的 g_tok
```

⇒ 打开 `glyph_gate_t` 就能**同时**收住"空间注入"与"条件向量"两路 ✓（不必新写门控）。

### ② 但 **v84A 根本没打开它** —— 这才是问题所在

`glyph_gate_t` 默认 `0.0`（`src/model/dit.py:158`），v84A 配置**没有**这一项 ⇒ `_gate = None`
⇒ **空间骨架注入在整个去噪过程恒为全强度**（t 从 1 到 0 都不衰减）。

额外发现：`cond_gate_t` 默认 `0.0` ⇒ **条件向量 `c` 也没有时间门**。这是**第二个可独立开关**的变量
（本批实验不动它，留作后续单变量）。

### ③ 时间约定与分析一致 —— **不需要反转门控方向**

`src/loss/flow_matching.py`：`x_t = (1 - t) * x0 + t * noise`，`t ∈ [0,1]` ⇒ **t=1 是噪声端** ✓。
代码 `_tf = (t/1000).clamp(0,1)`，`t ≥ glyph_gate_t → 1.0`，否则 → `glyph_gate_floor`
⇒ 语义 = "高噪声给足条件、低噪声收到 floor" ✓，与分析的 `w(t)=w_min+(1-w_min)·t^p` **同向** ✓。

## 2. 挂上的三个配置

| 配置 | `glyph_gate_t` | `glyph_gate_floor` | 语义 | 检验什么 |
|---|---|---|---|---|
| `v84B_std_gate05_floor0.json` | 0.50 | **0.00** | t<500 **完全关**骨架 | "低噪声仍被标准字形模板拖累"（最强版） |
| `v84C_std_gate05_floor35.json` | 0.50 | 0.35 | t<500 保留 35% | 分离"有没有门"与"关到底" |
| `v84D_std_gate90_floor0.json` | 0.90 | 0.00 | 只在前 10% 噪声用骨架 | 近似"缩短有效注入时长"的幅度对照 |

**门控取值实测**（直接套代码公式）：

```
gate_t=0.0 floor=0.35 : t=0→1.00  100→1.00  300→1.00  500→1.00  700→1.00  900→1.00  1000→1.00   ← v84A 现状(无门)
gate_t=0.5 floor=0.00 : t=0→0.00  100→0.00  300→0.00  500→1.00  700→1.00  900→1.00  1000→1.00   ← A1
gate_t=0.5 floor=0.35 : t=0→0.35  100→0.35  300→0.35  500→1.00  700→1.00  900→1.00  1000→1.00   ← A1b
gate_t=0.9 floor=0.00 : t=0→0.00  100→0.00  300→0.00  500→0.00  700→0.00  900→1.00  1000→1.00   ← A2
```

**前向实测**（同一个 ckpt、同一批输入、**同一 t** 对比 ✓）：

```
t=100（低噪声）: 门开(floor=0) vs 无门 ⇒ |Δ|/均值 = 4.49%   ← 有实质影响 ✓
                门开(floor=0.35)       ⇒ 2.86%              ← 更小，与 floor 一致 ✓
t=900（高噪声）: 门开 vs 门关          ⇒ |Δ| = 0.00000000   ← 门=1 ⇒ 完全一致 ✓
```

⇒ 这就是"**只在低噪声段关掉骨架条件**"✓ —— 正是那份分析要检验的因果。

**训练/推理一致性**：门作用于 `t`，训练与采样走同一条代码路径 ⇒ 天然一致 ✓
（分析强调的"不能只在推理时临时打开"在实现上自动满足 ✓）。

## 3. 怎么跑

```bash
# 只打印将要执行的命令（安全 ✓）
bash run_v84B_std_gate.sh --dry-run

# 真跑：等当前 v84A 结束后，自动按 v84B → v84C → v84D 顺序 fine-tune
tmux new -s v84b "bash run_v84B_std_gate.sh"

# 可调：每个变体的 fine-tune 步数（默认 30000，分析建议 20–40k）
FT_STEPS=40000 tmux new -s v84b "bash run_v84B_std_gate.sh"
```

脚本要点（`run_v84B_std_gate.sh`）：

* **不 `pkill`** ✓ —— 只 `pgrep` 等待现有训练自然结束，绝不打断正在跑的 v84A；
* 起点 = v84A run 目录里**最新** checkpoint，`--resume-full` + `--max-steps = 起点步数 + FT_STEPS`；
* 每个变体独立日志 `logs/std_v84B-*.log`；结果落 `assets/results/v84B_std_gate/`；
* `--dry-run` 可先验证命令与起点。

> ⚠️ 这三个是 **fine-tune**，只能用来**筛选**，不能替代"从头训练"的架构结论（分析里也这么讲 ✓）。
> 真正的架构结论等 B1（用胜出门控从头训）✓。

## 6. VAE 事实核实（分析 section 六）—— **v84A 用的不是物理 Calli-VAE**

实测该 run 的 `resolved_config.json`：

```
vae_path            = data/pretrained/sd-vae-ft-ema      ← 标准 SD VAE (f8) ✗ 不是 Calli-VAE
vae_scaling_factor  = 0.18215
vae_shift_factor    = 0.0
shift (FM)          = 1.0
latent_shards_dir   = exp-std/data/shards_img_aug        (613 MB)
```

⇒ 分析里"若 v84A 已用这组就冻结；不是就单独开实验"——**答案是：不是** ✓
⇒ 物理 Calli-VAE（PSNR 34.04 dB / 顶带高频 0.901 / LPIPS 0.0135）**从未进入 v84A** ✓
⇒ 它是一条**完全未探索的独立变量**，且**不能**与本次门控实验混在一起 ✓（否则收益归因不清）
